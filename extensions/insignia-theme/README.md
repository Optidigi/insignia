# Storefront integration

The existing `cart-repair` body embed now owns automatic Customise placement and cart repair. Its handle is retained so existing activation survives an app version update. Enable **Insignia storefront** once under Theme Editor → App embeds, then save the theme. App Bridge reports published-theme activation without extra scopes. A section `customize` block remains an optional placement override.

App snippets render **complete HTML elements** through `customise-control.liquid`. Shopify inserts comment wrappers around app-snippet output. A `render` inside an opening tag corrupts its attributes, and capturing rendered output is not a safe boolean/value protocol. Compute publication flags inside Liquid and render whole controls. `theme-liquid-browser.test.mts` parses the actual templates with pinned test-only LiquidJS and replays the observed Shopify wrappers in a browser; this qualifies that boundary, while native rendering still needs its own observation.

Automatic placement uses the effective published required policy, never a new draft. The product-page Liquid hint reads only the app-owned policy and current authorization generation. A known required product keeps its Customise entry during backend failure; the Designer can show unavailable/retry. Other identified product forms use `GET /apps/{prefix}/v1/eligibility?productId={id}`. This signed-proxy, active-installation read returns only `{ productId, configured: true }` for an effective required publication; it performs no contextual catalog lookup, quote calculation, preview, session or issuance work. A404 is absence of an eligible publication. Other failures are retryable on section load or connectivity recovery and never clear a known required hint.

The integration matches exact product identity from the theme component, form product ID or current product's variant IDs. It replaces the matching form's native submit/accelerated controls and Horizon quick-add/sticky controls. Ordinary products and the cart checkout button retain their behavior. It copies theme button classes without native handlers, refs, IDs or submission names. A visible manual block takes precedence within its own section/surface. Hidden modals cannot suppress another surface's button. Variant, section, dialog and teardown lifecycles retain this ownership; teardown restores only presentation changes still owned by Insignia. Quote acceptance and Shopify validation remain the purchase authority.

Theme Editor controls offer a localized label with default fallback, theme/primary/secondary style, width, optional background/text/border colors, optional border width/radius and spacing. Defaults retain native presentation. The selected Designer remains isolated with its existing CSS and reducers.

Compatibility cases are based on the official [Horizon product form](https://github.com/Shopify/horizon/blob/main/blocks/buy-buttons.liquid), [quick-add](https://github.com/Shopify/horizon/blob/main/snippets/quick-add.liquid), [sticky purchase surface](https://github.com/Shopify/horizon/blob/main/sections/product-information.liquid) and [Dawn purchase form](https://github.com/Shopify/dawn/blob/main/snippets/buy-buttons.liquid), inspected7November2026. Local browser fixtures qualify those structures; custom themes require their own product/form check and may need a manual placement. Published-theme activation is not E2E acceptance. See [current delivery state](../../docs/delivery/state.md) for native qualification and deployment.

Shopify documents [app-owned Liquid access](https://shopify.dev/docs/apps/build/security/storefront/store-settings-in-app-owned-metafields) and [extension activation/deep links](https://shopify.dev/docs/apps/build/online-store/theme-app-extensions/configuration). No theme-source write or new scope is needed. The app cannot activate an embed on a merchant's behalf.

After the selected Designer receives its matching verified Shopify cart receipt and closes normally, the host opens the locale-native cart page. Confirmed group/all removals use the same handoff. This shows fresh server-rendered cart contents without relying on a theme drawer's private event protocol. Manual close and failed, cancelled or ambiguous applications stay in the current page/review; no checkout or purchase is started by this handoff.

Native release staging preserves the existing qualified theme extension UID/name. This directory's `shopify.extension.toml` is for local preview; copying it over a native manifest creates another registration. Copy only the reviewed theme files/CI assets into fresh native staging and compare all module identities before activation. See the runtime runbook for the immutable candidate/binding procedure.
