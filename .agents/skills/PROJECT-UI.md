# UI integration reference

Read only the notes relevant to the affected subsystem. These retained project lessons supplement current source/tests; the [operating model](../../docs/delivery/operating-model.md) owns workflow and permissions.

For performance work, keep quote preparation cancellable and distinct from cart submission. Prepared presentation and acknowledged draft versions are hints, never purchase authority; retain fresh signing-fence checks and original ambiguous-write identities. A clean Done action must not wait for a new quote. Verify background frame preparation does not take focus, show a modal, lock scrolling or start private/cart operations. Retire expired/context-mismatched preparation and preserve real cold/failure recovery.

For UI packaging, integration planning or UI review, read `frontend/README.md` first. It identifies the selected placement/Methods components beside example adapters. Preserve those presentations when replacing adapters. Production `apps/*` and isolated `frontend/*` have different runtime roles; example request shapes do not prove backend compatibility.

Production merchant routes compose `SelectedProductEditor`/`SelectedMethods` with authenticated containers; examples keep explicit demo adapters. Preserve the shared reducers, visual markup and immutable publication/quote authority. Verify lost-response custody, current installation/authentication, explicit price provenance, dirty-edit preservation and publication correlation through the real built UI. Native Save Bar, secure upload, final-head CI and owner visual acceptance require their own evidence. Do not replace a failing retained behavior test with a selector/source assertion.

For native editor header actions, provide translated text labels on exported production icon controls as well as accessibility labels: the observed Bridge export reads textContent without forwarding accessibilityLabel. Separately, `useAdminPageReady` re-exports unchanged heading metadata after both actual route reveal and Bridge readiness, and cancels retired-route work. Verify fresh-load native Preview/Publish visibility and accessible names; DOM tags and simulated host dispatch alone do not prove composition. Keep diagnostic probes reversible and distinct from deployed qualification.

The selected PR223 UI includes native editor/table/chart controls under the owner preservation instruction. Boundary checks retain strict defaults and a finite exact-node/count manifest at `scripts/boundaries/selected-native-presentation.json`; they reject new/changed/stale native nodes and raw HTML. Do not expand this manifest to silence a failure. Trace any change to the selected source/authorized UI requirement and independently review it; defaults for new ordinary controls remain Polaris.

All customer flows use the new selected UI under the latest owner decision in specification §15, including retained production choices. Preserve option definitions/labels/accepted values during merchant projection, copying and owned-cart recovery; no legacy UI fallback. Legacy unsupported pricing stays explicit; it is never made free by omission.

When changing theme placement, read [the extension integration contract](../../extensions/insignia-theme/README.md). Preserve the existing embed/block identities and distinguish published-theme activation, effective publication and native E2E proof. Eligibility is a presentation hint, never quote or purchase authority. A hidden manual block must not suppress another surface, and transient eligibility failure must remain retryable without background polling. Keep new browser cases in `*browser*` files and qualify the actual built entry before changing native release bindings.

Theme Liquid `render` is an HTML boundary: native Shopify adds app-snippet comments, including inside captures. Never render attribute fragments inside opening tags or compare captured snippet output as a scalar. Render complete elements and calculate boolean facts within Liquid. Retain the rendered-template browser cases as well as authored DOM fixtures; CLI theme-check success alone did not catch the native wrapper defect.

A confirmed Ajax cart and an Insignia-only event do not prove a theme drawer refreshed. Use the selected existing closed-state completion hook, and hand off to the locale-native cart only after its receipt matches the verified Shopify request (or after confirmed removal); keep failed/unknown applications and manual close on the existing page. Test actual navigation separately from retained-state cases that intentionally stub the external destination. Exercise projection facade methods with real runtime LOGINs: label-table access alone missed the identifier-only privacy-fence reads needed by naming/ingestion. Grant those exact columns through the reviewed owner delta, preserving raw receipt and mutation denials and existing attempt budgets.

After native replacement qualification, source retirement removes the old configurator/editor/Method screens and duplicate merchant views. The isolated frontend renderer uses the selected containers before explicit demo adapters replace them. Preserve `publication-state.ts` classifications, selected reducers/journals and actual artwork upload services. Retire tests of removed UI contracts with their consumers; keep real selected upload, quote/cart, publication and history regression coverage. A changed shipped theme graph requires a new qualified candidate and binding; deleting an unused source file alone does not require widening a historical release profile. See `docs/architecture/selected-ui-retirement.md` for the inventory and current native limits.

For selected-UI behavior/performance work, PR223 d490e4d owns the layouts, reducer transitions and host decisions. Replace simulated effects through existing real ports. Keep resume/new/saved-edit/discard behavior when replacing the developer host; do not ship its fake Shopify page or replace the selected reducer with another state framework. See the baseline behavior map in `docs/architecture/selected-live-designer.md`.

Opening the Designer reads selection facts, not purchase-release authority. Retain current-scope recheck before disclosure and fresh proposal/acceptance/cart guards. Test the immediate loader, asset/handshake failure, Escape/focus/scroll, cancellation/reconnection and media expiry through actual browser behavior. Code hashing can be reused only after an actual immutable-image mount proof; writable code, host binds, credentials, release evidence and operation settlement must not inherit that cache.

Storefront startup qualification includes Firefox as well as Chromium. Install both through the pinned designer/storefront Playwright package before the storefront suite. Firefox srcdoc may expose an empty document.referrer; peer identity comes from the deliberately same-origin parent, while source/origin/channel checks remain mandatory. A Chromium-only native check does not establish Firefox compatibility. A browser click completing does not acknowledge cross-frame message delivery: await the modal’s actual closed state before asserting closure, focus or scrolling. Keep the final assertions; do not substitute a sleep.

PR223 StorefrontHostPreview is explicitly developer-only. Preserve its callback semantics without promoting its controls/page to the Shopify customer flow: production reopening resumes the Designer; owned cart review selects designs. Ordinary close retains the draft; only an actual different-design switch with edited intent needs discard confirmation. Required quote review is not dirty content, and must still gate purchase independently.

The selected startup shadow uses shared `primitives.css` and theme tokens, not copied native controls. Keep `.css?inline` declarations in storefront/test compiler coverage and text-load these CSS inputs in esbuild browser fixtures. Real upload progress crosses only the bounded uploading/processing enum in the existing request channel; preserve abort/identity guards, inspected success and translated failure categories. Never replace provider processing with fake percentage or sample content.

For native browser qualification, scope the Insignia frame to the active dialog’s direct srcdoc child; Shopify also creates recognition iframes inside other dialogs. A broad iframe locator can fail before any app operation. Do not assume one theme’s cleanup endpoint/extension: reconcile an already-dispatched Remove with exact cart readback before considering another action. Preserve raw helper failures beside their bounded reconciliation; no duplicate mutation or false all-green report.

Designer failure and repair UI is modelled as one discriminated union per surface, never as flags: the commit failure's `cause` (`frontend/designer/src/commit-failure.ts`, view derived only by `commitFailureView()`) and the repair screen's `RepairState` cause (`apps/storefront/src/designer/repair-state.ts`, view derived only by `repairView()`). Add a new case as one union member plus its view, so illegal combinations stay unrepresentable. Errors cross the Designer iframe only through `portFailure()` (`frontend/designer/src/port-failure.ts`), which whitelists codes and bounded fields on both sides; do not add per-case bridge flags. Draft autosave (#405) and cart-line reopen (#397) keep the per-tab quantity base and latest-draft pointer rules in `design-custody.ts`; a no-op save writes nothing, not even the pointer.
