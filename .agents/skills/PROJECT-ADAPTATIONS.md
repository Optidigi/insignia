# Project skill scope and provenance

Project skills live under `.agents/skills` in the current checkout. Select that project path explicitly when the host also advertises a generic skill with the same name. A fresh session verifies its intended checkout and discovered skill paths; repository settings contain no machine-specific paths.

The [operating model](../../docs/delivery/operating-model.md) owns seam selection, review depth, model choice and actual resource permissions. Skill techniques adapt to that ownership; confirmation/refactoring/order recipes add no approval gate.

Matt Pocock's MIT-licensed source was inspected at commit c55ee46073ed923f86ce59a5eb3b6d895095d1b7; retained support files and [license](LICENSE.mattpocock) preserve provenance. Earlier project adaptations remain in Git history. No skill expands native permissions.

## Frontend handoff and verification

For UI packaging, integration planning or UI review, read `frontend/README.md` first. It identifies the selected placement/Methods components beside example adapters. Preserve those presentations when replacing adapters. Production `apps/*` and isolated `frontend/*` have different runtime roles; example request shapes do not prove backend compatibility.

For local execution, select `.node-version` and confirm it matches `package.json` before installing/building. CI, Docker digests and runtime qualification also pin Node; upgrades must reconcile all consumers. Build the workspace before tests that import compiled shared/localization packages. Install Chromium through both web and designer packages, which currently pin different Playwright versions.

For CI changes, retain the three protected jobs, their full-route checks and the narrow status-document classifier. The foundation job runs the root `check`, including `check:ui`; frontend-only changes must select full qualification. Use `scripts/ci/status-docs.test.mts` for route/guard regression. The frontend gate runs all four packages' tests and the embeddable library build. Review actual package scripts when changing coverage, including designer browser/localization checks.

When editing `docs/delivery/state.md`, run `node --test scripts/ci/status-docs.test.mts` before pushing. Its bounded link policy admits local targets and the classifier's exact approved GitHub forms. Keep external development-store review links in the frontend guide and link that local guide from current state; source/link checks alone do not run this CI regression.

The runtime job also runs the complete non-browser web/server test cohort against its migrated PostgreSQL18 service. This covers real Method propagation, configuration/reconciliation locks and purchase/customer-link composition; foundation's database-free web run alone cannot prove those branches. Browser-launching web tests must include `browser` in their filename; the runtime cohort intentionally excludes them and does not install Chromium. Foundation still runs the complete browser-enabled web suite.

CI does not guarantee ripgrep is installed; workflow discovery uses the available standard system tools and must retain the same test set. The owned local database runner defaults to trust authentication on a private Unix socket. Restricted LOGIN fixtures must set their own generated password in both PostgreSQL and the connection URL; trust-only success does not verify SCRAM authentication. Qualify changed LOGIN fixtures against SCRAM as well as retaining their permission-denial assertions.

The publication stress command targets `selected-publication-stress-browser.test.mts`: four real selected-state cases repeated25times (100cases). The renderer control blocks the actual built createVisualizer module and requires an observed failure with no painted canvas baseline. Browser/server fixtures start lazily so an empty test-name selection cannot leave a process running. Do not restore retired editor name filters or treat a zero-case run as stress qualification.

A passing local recovery test does not close a failing CI run or prove a timing cause. Record exact head, failed interaction, local reproduction result and remaining uncertainty. Demo/native deployment, backend integration and owner visual acceptance remain distinct outcomes.

For closed-action tamper tests, await the owning execution through its completion API before replacing result files. A terminal status can become readable before final fsync/cleanup finishes. Preserve in-flight pending/uncertain rules and security assertions; use completion synchronization rather than sleeps.

Production merchant routes compose `SelectedProductEditor`/`SelectedMethods` with authenticated containers; examples keep explicit demo adapters. Preserve the shared reducers, visual markup and immutable publication/quote authority. Verify lost-response custody, current installation/authentication, explicit price provenance, dirty-edit preservation and publication correlation through the real built UI. Native Save Bar, secure upload, final-head CI and owner visual acceptance require their own evidence. Do not replace a failing retained behavior test with a selector/source assertion.

For native editor header actions, provide translated text labels on exported production icon controls as well as accessibility labels: the observed Bridge export reads textContent without forwarding accessibilityLabel. Separately, `useAdminPageReady` re-exports unchanged heading metadata after both actual route reveal and Bridge readiness, and cancels retired-route work. Verify fresh-load native Preview/Publish visibility and accessible names; DOM tags and simulated host dispatch alone do not prove composition. Keep diagnostic probes reversible and distinct from deployed qualification.

Do not expand this manifest to silence a failure. Trace any change to the selected source/authorized UI requirement and independently review it; defaults for new ordinary controls remain Polaris.

All customer flows use the new selected UI under the latest owner decision in specification §15, including retained production choices. Preserve option definitions/labels/accepted values during merchant projection, copying and owned-cart recovery; no legacy UI fallback. Legacy unsupported pricing stays explicit; it is never made free by omission.

When changing theme placement, read [the extension integration contract](../../extensions/insignia-theme/README.md). Preserve the existing embed/block identities and distinguish published-theme activation, effective publication and native E2E proof. Eligibility is a presentation hint, never quote or purchase authority. A hidden manual block must not suppress another surface, and transient eligibility failure must remain retryable without background polling. Keep new browser cases in `*browser*` files and qualify the actual built entry before changing native release bindings.

Theme Liquid `render` is an HTML boundary: native Shopify adds app-snippet comments, including inside captures. Never render attribute fragments inside opening tags or compare captured snippet output as a scalar. Render complete elements and calculate boolean facts within Liquid. Retain the rendered-template browser cases as well as authored DOM fixtures; CLI theme-check success alone did not catch the native wrapper defect.

Publication is a bounded multi-provider workflow. Its client scheduling policy must remain isolated from ordinary requests and from their shared token promises; a decoded JWT is only an expiry hint. For held-product recovery, distinguish an explicit durable pre-fetch NOT_DISPATCHED receipt from timeout/readback/ambiguous delivery. Consume its digest once under the publication lock, archive the original immutable claim/receipt through the schema-owner trigger (append migration51; no app direct audit DML), and retain all fresh dispatch guards; never reconstruct a lost claim from unchanged provider state.

A confirmed Ajax cart and an Insignia-only event do not prove a theme drawer refreshed. Use the selected existing closed-state completion hook, and hand off to the locale-native cart only after its receipt matches the verified Shopify request (or after confirmed removal); keep failed/unknown applications and manual close on the existing page. Test actual navigation separately from retained-state cases that intentionally stub the external destination. Grant those exact columns through the reviewed owner delta, preserving raw receipt and mutation denials and existing attempt budgets.

Freeze each new release-module baseline in canonical handle order and run the positive collector case: the canonical hash alone sorts its input, while the collector also compares the ordered baseline array. Preserve historical profiles and guards.
