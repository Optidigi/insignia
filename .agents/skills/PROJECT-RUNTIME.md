# Runtime and concurrency reference

Read only the notes relevant to the affected subsystem. These retained project lessons supplement current source/tests; the [operating model](../../docs/delivery/operating-model.md) owns workflow and permissions.

Signing-fence read-only restrictions belong to the entire asynchronous operation tree. A sibling rejection must not let a delayed read select active credential refresh or release collection after the parent unwinds. Use the existing server async-context convention and verify a gated late-read failure; do not relax expiry, refresh or collection assertions to hide the race.

A fixture that owns a short-lived database core must drain initiated parallel scope/credential reads before destroying that core, including reads left running after a sibling rejection. Include entitlement binding’s provider-scope lookup as well as authorization/credential reads. Release test gates in cleanup and drain dependent reads to quiescence; an immediate pool close can race a new Kysely connection and hang shutdown. Keep long-lived production rejection behavior and the test deadline unchanged; qualify the teardown through a gated late-read regression.

Concurrent demand verification must recheck durable evidence inside the shared conditional-collection operation. An earlier empty read may resume after a sibling has already collected evidence. Share only the record identity; every caller still checks its current authority and independently reads the correlated fresh record before admission. Keep merchant, buyer and purchase-worker typed map consumers aligned, and qualify delayed empty reads as well as simultaneously pending collection.

Parallel immutable artwork writes and verification reads must drain every started sibling before claim release or failure recovery. Retain both digest checks before usability. A readiness assertion is time-sensitive: do not run it early beside slower IO and treat the result as current after joining. Overlap only request-local release preparation, then keep the actual readiness assertion after availability and final fenced readers passive. Distinguish prepared/cold opening and immediate/expired Add measurements; reservation timestamps bracket actions and do not measure each provider span exactly.

The artwork scan belongs to the separate immutable inspector host package, not the ordinary worker container. Qualify that package when changing runner timing. The existing decoder accepts one active inspection; bounded photo IO must retain decoder exclusivity and drain started work before reporting failure. Browser test compiler libraries remain distinct from Node's runtime features; use the existing deferred-promise pattern when the test project does not expose a newer Promise helper.

Publication is a bounded multi-provider workflow. Its client scheduling policy must remain isolated from ordinary requests and from their shared token promises; a decoded JWT is only an expiry hint. For held-product recovery, distinguish an explicit durable pre-fetch NOT_DISPATCHED receipt from timeout/readback/ambiguous delivery. Consume its digest once under the publication lock, archive the original immutable claim/receipt through the schema-owner trigger (append migration51; no app direct audit DML), and retain all fresh dispatch guards; never reconstruct a lost claim from unchanged provider state.

Freeze each new release-module baseline in canonical handle order and run the positive collector case: the canonical hash alone sorts its input, while the collector also compares the ordered baseline array. Preserve historical profiles and guards. Purchased order presentation can receive numeric IDs from immutable quote history while Shopify returns GIDs; normalize valid expected identifiers at that reader boundary, retain exact order/line/resource matching, and never substitute current catalogue names or rewrite accepted history.

A Type=exec inspector service being active does not establish socket readiness. After a qualified handover, observe its existing socket/health before submitting image RPCs; a startup ENOENT proves no request dispatch, not a reason to restart the healthy process. Preserve the first probe and reconcile current state before any further action. Native UI checks distinguish a fully opened host dialog from its asynchronous opening transition and retain QA-009’s known rapid-dismissal limit.
