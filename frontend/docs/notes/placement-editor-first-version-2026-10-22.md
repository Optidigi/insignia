# First product placement workspace

Implemented a frontend-only workflow on the existing product configuration preview route. The owner requested one working garment setup first, with later quality-of-life work deferred. No production configuration, pricing, publication or Shopify records were changed.

## Shape and references

- A view/placement outline, central garment canvas and selected-object inspector share one selection. Shopify's [theme editor](https://help.shopify.com/en/manual/online-store/themes/customizing-themes/theme-editor/features-overview) and [preview inspector](https://help.shopify.com/en/manual/online-store/themes/customizing-themes/theme-editor/preview-inspector) inform that interaction. This is a custom layout around supported App Home Polaris controls, not a claim that Shopify exposes its theme-editor shell as a reusable component.
- [DecoNetwork's admin view/area setup](https://help.deconetwork.com/hc/en-us/articles/235607368-Configuring-Product-Views-Assigning-Decoration-Areas-for-Products) and [InkSoft's blank-product configuration](https://help.inksoft.com/hc/en-us/articles/46724037237787-Edit-Products-Decoration-Blank-Products) inform product → view → placement → method relationships.
- [Zakeke](https://zakeke.zendesk.com/hc/en-us/articles/360016879139-How-to-define-a-Print-Area) and [Customily](https://help.customily.com/articles/8796195814-how-to-create-a-my-product-base) inform the distinction between production dimensions and visual alignment. The preview's normalized image geometry is not calibrated physical measurement.
- Applied the frontend-design and Vercel composition/performance guidance within the existing Astro/Preact implementation. Polaris remains responsible for form controls, icons and dialogs. CSS owns the custom editor layout and selection list. No React migration or additional canvas library was introduced.
- Checklist Design and Memorisely were revisited. Their public pages did not expose enough specific instructional content to attribute this design to their checklists or paid lessons. No inaccessible material was treated as evidence.

## Working interactions

The T-shirt starts with real Legacy photographs, four views and six placements. Hoodie and polo fixtures use the same workspace. Selecting a placement in the outline or canvas updates the inspector. Konva provides area selection, drag and resize. Keyboard nudging and numeric fields offer alternatives. A small shared-renderer correction selects an unselected area on pointer down before dragging, keeping the inspector attached to the edited object. The existing renderer rejects transforms outside image bounds; numeric inputs clamp to those bounds.

The inspector includes a customer-facing name, artwork area, optional production reference dimensions, offered methods, decoration sizes and artwork-later permission. Printing demonstrates the Methods preview's fixed €5 price; embroidery demonstrates product-specific size prices derived from the legacy fixture. Fixed methods do not retain a second hidden per-size price. Empty product-specific amounts mean unavailable; explicit zero is free. Incomplete setup can be saved, while malformed nonempty prices or dimensions require correction.

Add/remove placement, add/remove view, rename a view and choose its image work locally. Product images are an independent library, so deleting a view does not delete its available image. The Add views dialog accepts one or several selected images and assigns unique generic View N names. Merchants can rename each view in its inspector. Image captions are not treated as authoritative angles; usage captions distinguish available media from configured views. JPEG, PNG and WebP uploads are validated and converted to bounded WebP data URLs locally. Cancelling the dialog discards its temporary uploads. Changing an image prompts visual alignment review. Variant image overrides, physical calibration, bulk setup, production publication and automatic Methods synchronization remain outside this version.

The footer's Setup example selector provides Configured product, Partially configured, 10 views · 40 placements, Unconfigured product and No product images. The partial example retains Front and its placements while the other images remain available to add. Each has a separate tab-local draft. A blank product starts with no inferred views or placements. Creating a view leads to its inspector; Add placement creates and selects an editable default rectangle. Draw area explicitly starts a drawing gesture. A small editable default rectangle and Standard 100% decoration size are UI defaults, not detected garment facts. New placements have no selected methods or invented prices. Incomplete setup can be saved as a draft.

Clicking a view opens its name and image settings; clicking an area opens that area's settings. Size configuration precedes method prices. The compact size row uses a supported native number field with a wider column and a visible Scale (%) heading, avoiding a squeezed percent suffix/stepper. Each size has its own preview action. The selected size and scale are named in the inspector, with a visible Size label on the canvas selector and an Exit preview action. The former Preview sizes action is removed because it did not explain which size would appear.

Save/Discard reuses the preview host's existing contextual bar. Local state is schema-checked and saved in session storage per product. Reload restores it; Reset demo clears it. Before-unload and app link navigation protect unsaved work. Confirmations use the existing Polaris modal wrapper, and host actions are inert while a modal is open.

On phones, the canvas stays full-width above a single active panel. Starting a drawing expands the canvas and scrolls it into view without focusing an off-screen text field. A nearby Cancel drawing action and Escape both exit drawing mode; numeric inputs provide a keyboard alternative. Switching panels preserves edits. At desktop widths from 801 through 1180px, one 324px sidebar switches between outline and settings, leaving more room for the garment. Wider screens retain three panes. This follows the theme editor's responsive sidebar concept with a breakpoint chosen for this workspace, rather than copying its exact 1600px threshold. All desktop panes share a fixed 40px header row. Panel contents scroll below it, preventing the inspector heading from leaving a sliver. Compact tabs provide panel navigation; the settings panel retains a selected-object header and action menu. The outline uses indented rows and separate native-icon disclosure buttons, without a disconnected tree rail. Mobile disclosure and placement rows have 44px minimum targets. Canvas projection updates on viewport changes and runs before paint when changing modes, preventing stale garment sizing after expansion. The page has a matching silent skeleton, finite data-load deadline, retry state, image-load feedback, inline validation and long-label handling.

## Data assumptions

Shopify supplies product identity and available media when returned by its API. It does not guarantee complete angles, consistent alignment across colors, usable image labels or physical calibration. Merchants name each view, select its image, draw areas and configure allowed methods, sizes and prices. The prepared Legacy examples demonstrate those settings; they are not an automated setup pipeline. One view image currently represents that view across variants. Real variant image assignment needs an explicit follow-up design and integration.

### Reuse and ordering

The selected view's action menu offers Duplicate view. It inserts an independent snapshot beside the source with fresh view, placement and size IDs, focuses the copied name, and prompts review of image/alignment. A placement's Copy to another view action chooses an existing destination, copies its geometry, methods, sizes and prices into independent records, and selects the destination area for alignment review. Normalized coordinates are starting values, not proof that a different garment angle has matching physical alignment.

Pointer users can drag the hover handle to reorder views or placements within their current view. Source and destination use stable IDs with an explicit before/after insertion line. Search disables drag handles; cross-view dragging does not silently move or copy settings. Arrow keys on a handle and the existing Move up/down menu remain alternatives. Touch users retain the menu instead of a drag gesture that conflicts with list scrolling. The implementation uses native browser drag/drop, not an additional sorting dependency.

Unfinished geometry is committed to the actual tagged source before copying or changing selection. Invalid text keeps the original field visible and focused instead of being stranded behind another object. Duplicate view no longer snapshots stale geometry. Empty selected-object names have explicit fallbacks; filtered expansion labels match the forced expanded state; Collapse other views keeps the current view open.
