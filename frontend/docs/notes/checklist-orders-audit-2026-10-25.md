This is a read-only visual and behavior audit of the current Orders work. It covers all 15 Orders entries in the popup manifest, each at its supplied desktop and phone size, plus the populated Orders overview and one live detail route in the local preview. It does not cover new Settings V1, the untouched home page or other Settings pages, legacy templates, native checkout, or a live Shopify merchant session. No application, fixture, build, capture, upload, replacement, or production data was changed.

The screenshot manifest is [all-popups.json](/Users/pc/Development/Insignia/.artifacts/admin-popup-review-2026-10-24/all-popups.json); each supplied pair is 1440×1000 desktop and 390×844 phone. ## Basis and interpretation

Primary product guidance was read from Shopify's current App Home v2.0 docs: [page patterns](https://shopify.dev/docs/api/app-home/latest/patterns) identify Index as the resource collection template and the [Index table composition](https://shopify.dev/docs/api/app-home/latest/patterns) describes search, filtering, sorting and bulk actions; [Table](https://shopify.dev/docs/api/app-home/latest/web-components/layout-and-structure/table) describes a responsive list layout for small screens; [Modal](https://shopify.dev/docs/api/app-home/latest/web-components/overlays/modal) and [Popover](https://shopify.dev/docs/api/app-home/latest/web-components/overlays/popover) distinguish focused/space-intensive work from compact contextual controls; [Date picker](https://shopify.dev/docs/api/app-home/latest/web-components/forms/date-picker), [Drop zone](https://shopify.dev/docs/api/app-home/latest/web-components/forms/drop-zone), and Shopify's current [Empty state](https://shopify.dev/docs/api/app-home-ui-extension/latest/web-components/feedback-and-status-indicators/empty-state) informed their respective rows. Shopify's [layout](https://shopify.dev/docs/apps/design/layout) and [content](https://shopify.dev/docs/apps/design/content) guidance provides responsive and task-focused copy context. These are current Shopify sources and govern the platform/component expectations; the product intentionally uses a custom semantic HTML resource table rather than assuming the native `s-table` behavior.

The current [Vercel Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) were a secondary check for focus, keyboard access, labels and responsive behavior. Memorisely's [visual hierarchy discussion](https://www.linkedin.com/posts/memorisely_stop-ignoring-visual-hierarchy-in-ui-activity-7349029993810685953-wZK1) and Zander Whitehurst's [progressive disclosure discussion](https://www.linkedin.com/posts/zanderwhitehurst_ux-ui-uxdesign-activity-7163115739644698624-uqjX) were used only as context for grouping related information near the affected order and limiting default actions; neither establishes a Shopify requirement or a production hold rule.

Source review was used to verify actual behavior and limits behind the visible states: order search/artwork status and selection operate on the currently loaded page; the date filter/sort query is server-side and uses store-day boundaries; the replacement upload is an explicit staged action and does not replace the retained source until Replace artwork; production worksheet holds and artwork ZIP exclusions remain explicit; previews and downloads re-check current source/retention state. This audit does not make claims about backend security, automatic content generation, Shopify host styling, or a real production handoff.
