## Findings

### P2 · High confidence — the Methods list omits the fixed-price unit

`index-resource-list` labels the column “Default pricing” and shows `€5.00` for Printing, but does not say what that amount applies to. A merchant scanning the library can mistake a per-placement/per-garment default for a per-product or order amount. The editor does explain this once opened: its field is “Price per location per item” with “Per placement, per garment. Enter 0 for free decoration.” Add the unit to the list value or make it available beside the amount without opening the editor. The detail wording is already clear; the gap is the list summary. Evidence: [index desktop](/Users/pc/Development/Insignia/.artifacts/admin-popup-review-2026-10-24/methods/desktop/index-resource-list.png), [index phone](/Users/pc/Development/Insignia/.artifacts/admin-popup-review-2026-10-24/methods/mobile/index-resource-list.png), [create editor desktop](/Users/pc/Development/Insignia/.artifacts/admin-popup-review-2026-10-24/methods/desktop/create-method-editor.png), [create editor phone](/Users/pc/Development/Insignia/.artifacts/admin-popup-review-2026-10-24/methods/mobile/create-method-editor.png). Shopify content guidance asks for enough information to make a choice; the project’s pricing model defines this rate basis.

### P2 · High confidence — product identity scrolls off-screen in the mobile table

In both phone captures, the Products table is horizontally scrolled past its first Product column. `products-method-summary` and `products-location-summary` show the row’s method/location values and an open generic “Methods” or “Print locations” popover, while the product title that anchors those values is off-screen. The row remains visible, but the user must remember which product it belongs to. Keep the product name visible while scrolling (for example, a pinned first column) or present those mobile summaries in a product-labeled card/list row. Evidence: [methods summary phone](/Users/pc/Development/Insignia/.artifacts/admin-popup-review-2026-10-24/orders-settings/mobile/products-method-summary.png), [locations summary phone](/Users/pc/Development/Insignia/.artifacts/admin-popup-review-2026-10-24/orders-settings/mobile/products-location-summary.png). Shopify’s App Home table guidance describes transforming tables into lists on mobile; it supports preserving row identity, not requiring a specific implementation.

### P3 · Medium confidence — the empty picker does not say how to get products into the catalog

The `product-picker-empty-catalog` state says “No products available” and explains that nine existing assignments are unavailable and will be kept. `Select` is disabled and Cancel is the only next action in the dialog. A merchant who opened the picker to assign a product has no in-dialog recovery direction. Add a short next step such as “Add a product in Shopify, then return here.” The current Products page already uses that explanation in its zero-products state, so repeating it at the assignment point would help users recover without implying the picker can create products. Evidence: [empty picker desktop](/Users/pc/Development/Insignia/.artifacts/admin-popup-review-2026-10-24/methods/desktop/product-picker-empty-catalog.png), [empty picker phone](/Users/pc/Development/Insignia/.artifacts/admin-popup-review-2026-10-24/methods/mobile/product-picker-empty-catalog.png). The recovery sentence on the Products page is code-verified, not one of the 26 screenshot states.

## Destructive confirmation and pricing clarity

Destructive actions in this scope are deliberate and sufficiently confirmed. `delete-single-method-dialog` names the method and explains the effect: library availability is removed while existing product setup and orders remain. `delete-selected-methods-dialog` confirms the selected set/count and explains the impact before the critical action. Both show a safe cancel path and adapt on phones. Product-selection bulk actions shown here are copy/download/preview, not destructive, so no extra confirmation is needed. The unsaved-changes dialog names what will be lost and separates Keep editing from Discard. Duplicate offers a distinct name and optional assignment copy; its checkbox text changes to “Copy tag rule” for tag assignments in code, which avoids mislabeling that case.

Price setup is well explained in the editor: fixed vs. product-specific price consequences are described, and fixed amount is explicitly per location/per item.
