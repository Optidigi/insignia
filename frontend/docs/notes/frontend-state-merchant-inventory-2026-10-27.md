# Merchant frontend state inventory

27 October 2026. Read-only inventory of the Insignia merchant web frontend and its loopback design previews. No application code or tests were changed or run. Paths and line numbers refer to the checkout inspected on this date.

## Scope and reading guide

This note inventories the merchant side of the complete frontend plan. The production merchant interface is the Astro/Preact App Home under `apps/web/src`. Production routes mount the islands listed below with Shopify's pinned Polaris runtime. The owner-facing placement editor and full Methods/Home explorations currently shown in the loopback gallery are injected by the preview host; they are active design targets in the complete frontend plan, though they are not the production implementations. The separate `apps/storefront` buyer frontend is also in that complete plan and needs its own state-owner analysis; `designer-prototype` and `masking-editor-lab` are sibling experiments outside the current Insignia application fronts.

This is a coverage inventory, not a quota for reducers. State should be moved only where a single workflow's facts and transitions need to stay coherent. A local text input, disclosure, selection, request result, or timer is not a defect because it uses `useState`. “Candidate” below means a place to consider a narrow transition model in a future, approved pass. It does not assert a current bug or a measured improvement.

| Route / surface | Current production owner | State classification and future treatment |
| --- | --- | --- |
| `/admin/home` | `MerchantHomeContainer` + `MerchantHome` | Per-source read lifecycles and refresh ownership; setup-guide preference and action feedback are separate local state. Preserve source boundaries. |
| `/admin/products` | `ProductsOverview` | Catalog request result is already a discriminated union. Search, filter, cursor history, and page selection are related navigation facts; any model must preserve URL/history as the restoration authority and clear selection on view changes. |
| `/admin/products/:id/config` | `MerchantConfigEditor` | Product draft/save and publication are separate high-consequence workflows. Canvas objects and editing controls are separate from server state. Consider narrow models by workflow under the approved architecture plan. |
| `/admin/orders` | `OrdersOverview` | Server query, cursors, page result, local search/filter and page-scoped selection have coupled reset rules. Keep selection and display preferences scoped; URL/history remains restoration state. |
| `/admin/orders/:id` | `PurchaseArtwork` and download/preview components | Purchase read, artwork attachment, expiry, original download, archive, worksheet, and history have distinct owners and identities. Do not combine them into one `loading` state. |
| `/admin/methods` | `MethodLibrary` | Production method list/read/write/delete states are distinct from the richer local Methods exploration. CRUD transaction states could be made more explicit without absorbing search or modal DOM state. |
| `/admin/settings` | `MerchantSettings` | Static destination hub; no reducer candidate. |
| `/admin/settings/billing` | `MerchantBilling` | Subscription view is server-owned; read status could be represented as one load union. Plan changes hand off to Shopify, not a local write. |
| `/admin/settings/permissions` | `MerchantPermissions` + `ReadinessPermissions` | Parent session/product issue and child browser-scope inspection/request are different authority paths. Keep App Bridge permission request and server access readback distinct. |
| `/admin/settings/storefront` | `StorefrontSetup` + `StorefrontProductTest` | Theme readiness and product test have separate lifecycles; each already has a typed phase/test state. Preserve host recheck, picker, cancellation, and result correlation. |

`/admin/billing` redirects to Settings billing; `/admin/settings/methods` redirects to the canonical production Methods route. `/admin/unavailable` is a static recovery page. Route wiring and shared shell are in `apps/web/src/pages/admin/*.astro:1-34`, `apps/web/src/layouts/AdminLayout.astro:13-41`, and `apps/web/src/components/AdminNavigation.astro:1-8`.

## Production route state owners

### Home

`MerchantHomeContainer` owns independently loadable Products, Orders, setup, statistics, access/plan/session facts, and one `AbortController` per source at `apps/web/src/islands/MerchantHomeContainer.tsx:29-46`. `load(panel)` replaces and aborts that panel's prior read (`:44-73`); theme, billing, focus/visibility recheck, and reload synchronization are handled separately (`:75-159`). Keep the separately authenticated data sources separate: a combined reducer should not invent an aggregate endpoint or make one source's failure erase another's usable panel.

`MerchantHome` renders those facts and owns retry/create-product feedback (`apps/web/src/islands/MerchantHome.tsx:264-266,312-380`). The setup-guide collapse preference is stored per guide in `sessionStorage` (`:153-205`); it is a display preference, not network status. `HomeActivity` and `HomeGettingStarted` contain bounded chart/guidance UI (`apps/web/src/components/HomeActivity.tsx`, `HomeGettingStarted.tsx:55-78`). Guidance expansion, active step, focus restoration, and progress preference should remain local to that control unless a future interaction change couples them. The current production Home composition must not be conflated with `home-preview.tsx` (see preview section).

### Products catalog

`ProductsOverview` already represents the server result as `CatalogState = loading | ready | error` (`apps/web/src/islands/ProductsOverview.tsx:20-24`). It separately owns configuration filter, typed/applied search, cursor stack, selection, and feedback (`:48-56`). Search timer, active abort controller, request sequence, and catalog load are correlated in `:80-152`; URL/history restoration, pagehide/pageshow and cursor trails are coordinated in `:154-185`. Selection clears on new query/filter/page and CSV/ID actions have their own feedback (`:72-79,103-113,218-250`).

If future changes need a reducer, bound it to query intent and request lifecycle or to selection's invalidation rules. Keep the controlled text field's draft and timer, the URL/history navigation snapshot, export Blob/object URL, and live page result under their present owners. Do not duplicate server products inside a second reducer-owned catalog.

### Production product configuration editor

`MerchantConfigEditor` is the real persisted product editor. It has a server `view`, editable `draft`, geometry `editor`, derived/explicit save status, latest conflict read, and request/busy refs (`apps/web/src/islands/MerchantConfigEditor.tsx:485-529`). It also keeps text-entry values/errors, pagination and filters, modal targets, validation issues, image dimensions, and preview feedback separate (`:369-398,418-421,493-519`). Several are ordinary input/navigation state and should not be grouped solely by proximity.

The existing `SaveState` union (`:93`) names `clean | dirty | saving | saved | conflict | ambiguous`. Save itself is a transaction with validation, idempotency identity, version check, definite rejection versus uncertain outcome, and server reconciliation (`:909-1087`; pending request shape at `:94-99`). Publication is a separate lifecycle against the saved revision, has its own pending request and optional session-storage recovery (`:104-134,595-649,1089-1212`). Keep draft editability and publication progress able to coexist; a single flat enum would incorrectly collapse independent work. Do not turn persisted server facts, exact retry bodies/keys, or accepted publication history into a duplicate reducer store.

`apply(command)` delegates geometry changes to the existing pure `applyGeometryCommand` and synchronizes draft/save dirtiness at `:752-766`; the command's base-version validation lives in `packages/visualizer/src/geometry.ts:63-75,342`. Keep renderer, Konva/Visualizer, pointer/keyboard input, animation frames, focus, and element refs imperative. Setup-step navigation is already URL/hash-backed (`MerchantConfigEditor.tsx:361-465`); text, filters, price-page selection, and standalone dialogs remain local controls. Removal dialogs are separately targeted (`:369-396`), not one generic editor-modal workflow.

Potential reducer work here is a later, explicitly scoped save transaction or a bounded interaction mode. It is not a page-wide state rewrite. A `finally` setter or number of hooks alone is not evidence of a race or defect.

### Orders index and detail

`OrdersOverview` owns page data/status, artwork filter and local search, page selection, display columns, server date/sort query, current-time refresh, cursor stack and request refs (`apps/web/src/islands/OrdersOverview.tsx:35-36,124-159`). `load()` uses pending/generation guards, snapshots query and cursors, preserves the prior page while loading, updates URL/history on success and distinguishes denied/error (`:162-205`). The selection is intentionally page-scoped; query changes clear it (`:207-246`). URL parameters and `history.state` store search/filter/server sort/date and cursor restoration (`:69-122`). `OrdersDateFilter` keeps custom date text/view/error staged until Apply (`apps/web/src/components/OrdersDateFilter.tsx:55-124`); `OrdersDisplayOptions` is a controlled column/sort editor (`:10-22`).

Keep server page/query authority distinct from local display choices and the minute timer. A future query model must preserve popstate restoration, current filters and cursor state as one coherent query while avoiding selection from a different page. Do not put actual order data, clock ticks, or DOM focus refs in a reducer.

Order detail `PurchaseArtwork` owns the purchase read and request/access outcome (`apps/web/src/islands/PurchaseArtwork.tsx:369-441`) and renders independent item-level attachment controls. Each artwork assignment row owns selected asset, replace intent, busy/message, expiry, preview and generation identity (`:59-139`); private URL fetches verify the captured identity and expiry (`:140-164`), while attachment sends `expectedVersion` and applies only the current response (`:166-190`). Keep artwork version, asset identity, retention expiry, request identity and signed URLs correlated. `PurchaseItems` has a local time tick for retention display (`apps/web/src/components/PurchaseItems.tsx:16-28`); artwork history only reveals a larger local slice (`PurchaseArtworkHistory.tsx:7-14`).

### Production Methods and Settings

Production `MethodLibrary` is a compact API-backed index, not the injected full Methods management design. It owns list/name/query/editor state plus loading, busy, error/read-failed, notice, denied, uncertain, delete target, and pending idempotent write refs (`apps/web/src/islands/MethodLibrary.tsx:16-63`). Read and write paths are `:76-153`; modal/native events and keyboard entry are adapter concerns (`:22-54,154-172`). A future change could consolidate its read and mutation status transitions into explicit unions, preserving the uncertain-outcome state and exact command identity. Keep search text, edit form text and native modal refs local.

`MerchantSettings` only links to supported settings destinations (`apps/web/src/islands/MerchantSettings.tsx:3-49`). `MerchantBilling` loads a server `BillingView`, has status booleans and an in-flight guard (`apps/web/src/islands/MerchantBilling.tsx:14-48`); representing loading/ready/denied/failed as one read union is a small coherence option, but it must not treat browser state as subscription authority. Its action hands off to Shopify. `MerchantPermissions` reports session or product permission issue (`apps/web/src/islands/MerchantPermissions.tsx:6-53`); `ReadinessPermissions` separately queries browser scopes and requests optional grants, then reinspects server-backed read/edit/setup/order/product access (`apps/web/src/islands/ReadinessPermissions.tsx:3-56,90-190`). Permission request completion is not proof that app access is ready; preserve the explicit readback boundary.

`StorefrontSetup` already names theme check phases `loading | ready | unsupported | failed` (`apps/web/src/islands/StorefrontSetup.tsx:14-27`), plus retry and links. App Bridge theme request timeout and focus/visibility recheck are effects (`:27-110`). `StorefrontProductTest` separately models idle/checking/ready/error state (`apps/web/src/components/StorefrontProductTest.tsx:6-37`), cached product choice, picker in-flight state, request sequence and abort controller (`:30-64,90-123,153-181`). Retain the product picker call, cached selection and authenticated verification as distinct steps, and correlate the read with the selected product. Its component-level UI is still part of the real production route and should not be replaced by the settings preview's fake picker.

## Downloads and artwork uploads

## Other application boundaries and migration completion matrix

`apps/storefront/src/customizer.tsx:24-110,162` is an active production buyer frontend and already has a buyer reducer; `apps/storefront/src/buyer.ts:83-99` owns its abort/generation request lane. The complete frontend plan includes this lifecycle as a separate production buyer workstream. The sibling `designer-prototype` is also included as the active polished React buyer design, with its own simulated contract and [separate owner map](frontend-state-react-prototype-inventory-2026-10-27.md). Neither is part of this merchant-specific inventory. The separate `masking-editor-lab` experiment is outside this migration.

For any future approved whole-frontend state pass, use this matrix to account for each current UI family. “Complete” means reviewed against its proper owner and disposition, not “converted to reducer.”

No benchmark or claim of faster AI coding follows from this source inventory.
