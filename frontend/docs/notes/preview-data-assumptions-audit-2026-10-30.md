# Preview data and copy assumptions audit

30 October 2026. Read-only source audit of the selected customer prototype's admin preview bridge, its loopback merchant fixture, and the published buyer configuration. No application files changed.

## Finding

The customer preview cannot infer that a product is a phone case, nor its option axes, physical dimensions, or manufacturing constraints. The preview input carries a product title and already-selected view images, placement geometry, size labels/factors, methods, and prices. It has no Shopify product type. The `phone-case-options` scenario is a hand-authored presentation fixture, not an automatic mapping from the product editor or production DTO.

For copy that must work without more data, use product-neutral wording consistently. If the UI needs labels such as "Finish" and "Model", pass those labels and their option mapping explicitly. Do not detect them from a product title, image shape, or guessed option names.

## Phone-case fixture and option copy

The fixture explicitly sets `optionPresentation` to Finish and Model in JSON. The field is optional local `ProductConfig` metadata with a legacy Colour/Size default; the admin preview constructor does not populate it, and the merchant settings contract has no such field. ([fixture](../../../../designer-prototype/src/scenarios/phone-case-options.json#L1-L45), [schema](../../../../designer-prototype/src/config.ts#L28-L49), [default](../../../../designer-prototype/src/option-presentation.ts#L5-L22))

The scenario documentation says the model/finish labels are test labels, both choices reuse one schematic, and the fixture makes no SKU, compatibility, variant-price, or availability claim. It also says the phone-case image is schematic, its size names are relative labels, and the rectangular inset is not manufacturing calibration. ([scenario notes](../../../../designer-prototype/SCENARIOS.md#L78-L82)) Root's targeted config probe separately confirmed that renaming the product does not change the fallback copy, while omitting availability metadata leaves all four fixture cells available. This is fixture behavior, not evidence that real case models are interchangeable.

## Concrete bridge defect

There is one real local preview handshake mismatch. The sender's strict `PlacementProduct` schema accepts optional `variantPhotos`. The setup-copy overview path can create or load that field from a variant-photo example and passes the product to `launchCustomerPreview` unchanged. The selected editor path avoids it by removing `variantPhotos` and resolving the active photo into each view before launch. ([sender schema and post](../../../apps/web/test/admin/support/placement-customer-preview.mts#L89-L178), [overview path](../../../apps/web/test/admin/support/placement-setup-copy-entry.tsx#L40-L64), [example data](../../../apps/web/test/admin/support/placement-variant-photo-examples.mts#L18-L60), [editor path](../../../apps/web/test/admin/support/placement-workflow-preview.tsx#L2239-L2246))

The receiver uses a strict schema that omits `variantPhotos`. It silently ignores a message that fails parsing, so the child reports that the draft did not arrive after its timeout. ([receiver schema](../../../../designer-prototype/src/admin-preview.tsx#L72-L88), [message validation](../../../../designer-prototype/src/admin-preview.tsx#L326-L350)) The existing sender test checks that a regular fixture is posted; it does not check receiver-schema compatibility. ([test](../../../apps/web/test/admin/placement-customer-preview.test.mts#L130-L223)) This is limited to the local overview/setup-copy route when variant-photo metadata is present. No production DTO is involved.

## Recommendation

Keep the current artwork-preview label product-neutral. For eventual production UI, use saved labels only for fields they actually describe. If Model, Finish, or other Shopify variant axes must appear as named controls, the buyer contract needs an explicit axis/value mapping from `selectedOptions`, with any display mode supplied explicitly. Preserve stable IDs and raw backend contracts; do not parse a combined variant title or infer category from product copy.

For the local bridge, project a deliberately supported preview payload at the sender and cover both launch paths. Do not broaden its meaning by forwarding metadata the receiver does not render. This audit did not change or run application tests; the config probe noted above was performed by root.
