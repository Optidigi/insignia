# Frontend demo separation research

30 October 2026. Read-only audit for connecting the selected customer customizer later. No application code changed and no tests were run.

## Finding

There are two separate preview systems. The merchant demo/emulated Shopify host is already a loopback test harness under `apps/web/test/admin`; it is not imported into the production app. The selected customer design is the sibling Preact customizer. Its scenario prices, browser upload and simulated host/cart are useful local behavior, but `Designer` currently combines those preview effects with the editor reducer. The integration seam should separate those effects while keeping the existing editor workflow intact.

The local config is a view model, not a production quote payload: its IDs and dimensions are fixture-oriented and its price values are JavaScript numbers. The canonical spec requires `{ currency, minor: bigint }`, decimal-string JSON amounts, backend quote/acceptance and real Shopify line application. Keep current local totals covered, but have the real quote path preserve the server's exact currency and minor values rather than round-tripping through floating point. ([spec money and buy flow](../../architecture/implementation-plan.md#L79-L84), [money contract](../../architecture/implementation-plan.md#L192-L200))

## Minimal implementation and deletion checks

1. Keep the current scenario and localhost roots for local review. Inject `ArtworkPort` and `CartPort` at the composition root; do not add a generic fake HTTP backend.
2. Keep all editor decisions pure and local to the reducer. Add request IDs to quote/commit start and result events so stale responses are ignored. A fulfilled `commit` is the only event that may set completion and hand control to the host. Backend idempotency stays a separate key.
3. Move the preview-only saved-design list, `/product` route and “simulated host result” into the local host adapter. The production composition must not import those modules or local scenario fixtures. Preserve the current add/edit/update and resume journeys in local mode.
4. Give both ports deterministic local and failure implementations. Cover successful local upload/add/update, upload cancel and stale completion, quote failure, cart-commit failure, no success/host return before verified commit, and exact known totals. Keep browser tests on the visible journeys as well as pure reducer/port contract tests.
5. Deletion check: remove the local host adapter and scenario root from a production build and confirm no local cart, fake-success copy, fixture catalog or demo transport is reachable there; the local Vite entry must still exercise all scenarios and remain functional. For the merchant demo, delete only its own harness if explicitly retired, then retain production admin build/API coverage.

This follows the installed codebase-design deletion test and real-seam rule (one adapter is hypothetical; local and failure adapters make the interface testable now), and Pocock's warning against extracting helpers while leaving coordination in the UI. The project TDD guidance calls for testing public behavior; the existing customer browser suite already covers local handoff, update, upload retry/cancel and exact totals, although its reducer-specific assertions should not become the sole contract. ([Pocock recheck](pocock-video-implementation-recheck-2026-10-28.md#L19-L35), [customer test](../../../apps/web/test/admin/designer-state-browser.test.mts#L449-L575), [exact totals](../../../apps/web/test/admin/designer-state-browser.test.mts#L952-L988), [TDD skill](../../../.agents/skills/tdd/SKILL.md#L12-L24), codebase-design skill: `/Users/pc/.agents/skills/codebase-design/SKILL.md`)
