# Orders overview and detail refinement

20 October 2026. Local implementation on `codex/ui-redesign`. The real Shopify Orders overview and an order detail were inspected read-only in Chrome. The public Polaris 2.0 release-candidate components remain the implementation contract. The synthetic preview was inspected separately; this is not embedded-host qualification or owner acceptance.

## Deliberate composition

The overview keeps the order number alone in its primary cell. Test status appears on the detail page. `Items` shows the sum of purchased quantities as `1 item` or `2 items`, with localized digits and exact BigInt arithmetic. Missing line records display `Unavailable` rather than a fabricated zero.

All table headers are plain. Collection-wide date sorting remains available through Display options on desktop and narrow layouts. The earlier Date-only header arrow and custom column dragging were removed: they reproduced only part of the private Shopify table behavior and added interaction complexity. Column visibility and actual date filtering remain. Search and artwork filtering explicitly apply to the current page. Pagination appears only when needed. No custom SVGs, private shadow styles, theme override or replacement typography were added.

The detail follows Shopify's [details template](https://shopify.dev/docs/api/app-home/v2.0-rc/patterns/templates/details): resource identity and statuses, a primary work column, and supporting order information in the aside. Artwork controls come first, followed by purchased items, payment information and artwork history. Reference IDs are collapsed. Test, cancellation, payment and artwork states use actual retained facts. Customer, shipping and fulfillment sections are omitted because the current purchase DTO does not contain that information.

Attach, replace, private preview/download and version-checked lock retain their existing authorization and retention guards. Reconciliation says an update was requested rather than claiming that Shopify facts have already changed. Refund records do not claim that funds were returned. Amounts retain exact minor-unit arithmetic. Detail dates explicitly show UTC because the detail DTO does not carry authenticated store timezone context; the overview continues using its authenticated timezone metadata.

The detail island now reveals its own silent skeleton after hydration while its first authenticated read is pending. Transient refresh failure identifies retained details as stale. An authoritative 404 clears the loaded details and actions and directs the merchant back to Orders. Permission loss still clears private work. The preview's outer host now forwards the real detail refresh action and supports Back to Orders. Preview reads remain synthetic and API commands remain rejected.

It cycles in design/placement order, skips provided files and unavailable design payloads, and follows the existing unlocked/live-design replacement policy. ## Production worksheet and Settings implementation

The single-order Production sheet action prepares a native modal with an A4 page selector and Download PDF. Preparation and download each re-read the tenant-authorized purchase. The comparison excludes rotating image delivery URLs but retains order facts, artwork version/current asset IDs, quantities and retained geometry. Preparation aborts on close, stale parent data, permission denial or the earliest design/artwork/preview lease expiry. The shared authenticated request now honors caller cancellation without cancelling other callers' shared App Bridge token request. API/schema failures use safe recovery copy.

The worksheet uses each design group's variants as authoritative quantities. A total-by-product/variant comparison with purchased lines detects incomplete reconciliation without inventing a line-to-design join. Current authorized artwork derivatives are composed over retained garment photographs with the shared geometry projection. Purchased originals are never substituted for replacements. Identical image/placement geometry can share a view across sizes; variant geometry overrides keep different views separate. Physical millimetres appear only when configured, otherwise dimensions are explicitly unavailable. Missing artwork, cancellation, payment/refund uncertainty, unknown test status and test orders remain per-page notices. Held worksheets can be downloaded for review; they do not approve production. Unavailable garment imagery fails with retry guidance; unavailable geometry produces a held reference sheet.

Art references sit beside their placement/method/size details; garment views use two columns, or three for a three-view design. Merchant labels wrap and paginate, including long words and non-Latin scripts. Canvas rasterization preserves browser text shaping at 150 dpi; the PDF is a visual worksheet, not selectable text or original artwork. Images, decoded pixels, retained output and page count have limits; private artifacts stay in memory and object URLs are revoked. Downloaded copies outlive application access and must be checked against the current artwork version before use. Production task tracking, physical measurement inference and batch export are outside this change.

The detail aside now groups repeated product names and thumbnails while preserving distinct purchased line quantities and exact economics. Native icon-only badges qualify supporting section headings; Polaris supplies aside separators. Settings groups supported destinations under Customization and App and account. Its permissions subpage retains explicit optional-scope consent and denial recovery. Translation/preferences have no invented persistence or disabled placeholder controls.
