# Merchant editor workflow deepening

The merchant configuration screen now delegates save, publication, create, product-copy search, copy, load, resume, suspend, and authorization-clear coordination to `createMerchantConfigEditorWorkflow`. The island consumes its snapshot and dispatches semantic commands; the controller owns the write/read sequencing and the transaction reducer remains the single owner of save and publication intent.

The controller fences async completions by request epoch and observed installation generation. It keeps save and publication resources independent, retains the immutable save command (body and idempotency key) through ambiguous outcomes, and blocks retry after a suspended/failed read until current authority is observed again. It treats 408 and 429 as ambiguous because a gateway may return them after a write was accepted. A stale uncertain publication is retired only after its exact retry gets a definitive 409 and an authenticated read proves the server remains in DRAFT on a newer draft version. Authorization clearing, loading, suspension, and disposal close public command gates.

At the untrusted configuration boundary, an editable persisted draft must pass `MerchantDraftSchema` and geometry validation. Invalid stored values remain unsupported instead of reaching UI code that expects the full draft shape. The design canvas setup effect also follows editor availability and design-stage visibility so a late editor mount or stage remount still initializes Konva.
