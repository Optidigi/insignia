## Fresh Shopify guidance

Read [Content](https://shopify.dev/docs/apps/design/content), specifically `Product content`, immediately before `Use plain language`. Shopify warns against duplicating content and includes presenting the same content in different ways on one page among its examples. The journey repeats the guide's setup/customer-test/order context without creating a separate decision or task.

Read [Layout](https://shopify.dev/docs/apps/design/layout), `Single-column layout`. Shopify presents a single column as a way to focus merchants on one obvious task and identifies it as the normal homepage layout. This supports the simple setup composition. It does not require a larger hero, multiple panels or extra copy.

Read [Empty state](https://shopify.dev/docs/api/app-home/latest/web-components/feedback-and-status-indicators/empty-state). It explains missing content and a next action. A graphic is explicitly optional. The example does not make its sample product claim or asset suitable for every app.

Read [Media card](https://shopify.dev/docs/api/app-home/latest/patterns/compositions/media-card). Media is appropriate when its context helps a merchant understand a feature or make a decision. An available renderer capture is not automatically relevant. A sample T-shirt introduces an unsupported category assumption into a generic product setup task, even if it is honestly labeled an example.

Read [Callout card](https://shopify.dev/docs/api/app-home/latest/patterns/compositions/callout-card). Shopify says to use it sparingly for a feature, opportunity or first action. That does not justify another presentation of the action already supplied by the guide. This fetched page identifies itself as v1.1, so it is composition guidance only, not evidence of the selected RC component contract.

Read [Setup guide](https://shopify.dev/docs/api/app-home/latest/patterns/compositions/setup-guide). Its purpose is essential configuration tasks with progress and expansion. The native Search & Discovery screenshot and [Homepage example](https://shopify.dev/docs/api/app-home/latest/patterns/templates/homepage) put this before metrics. Guide order is useful evidence; other example sections are content-dependent.

## Checklist Design and Vercel

The bundled [Empty State checklist](https://www.checklist.design/web-app/empty-state) calls for a clear missing-resource heading, brief supporting explanation, a first-item action, contextual imagery if used, and distinct zero/error/no-results states. It does not require multiple sections or imagery tied to an arbitrary product category.

The bundled [Onboarding checklist](https://www.checklist.design/web-app/onboarding) calls for orientation, progress, a clear first action, contextual teaching and completion acknowledgment. Existing guide mechanisms cover these needs; its product-highlights item is not an instruction to repeat a feature tour below the guide.

Freshly fetched the actual [Vercel Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md). Relevant rules concern real empty-state handling, long text, semantic actions/links, labeled controls, visible focus and image accessibility. There is no viewport-fill, minimum-height, card-count or illustration requirement. Its heading title-case rule conflicts with the project's Shopify direction; Shopify sentence case continues to govern. Vercel is not evidence for adding content here.

## Actual empty-shop work

With no Shopify product, the supported primary task is Add product through the current Shopify handoff and its real failure recovery. After a product exists, select/configure it; after a draft exists, resume that draft. Actual title, thumbnail, state and destination become available then. These facts can enrich Home without hypothetical sample resources.

Theme setup is a real independent route and is already present in the guide. Test instructions are a real route, but testing requires a published product. A decoration-method library exists, yet adding a Home shortcut without a known merchant need or missing-method fact would be a speculative competing task. Products, Orders and Settings already have navigation; repeating them as empty cards creates no new work. No supported template library, news feed, tutorial-video collection or extra sample catalog justifies another section.

Keep the introduction to one generic sentence if it adds orientation beyond the guide title. Keep the actual next step visible after dismissal or manual completion. Preserve urgent artwork before education, a relevant incomplete guide before metrics, and completed/restored guidance after primary operating content. Preserve real empty and permission/error distinctions. Further changes need a distinct supported merchant task or resource, not more page height.
