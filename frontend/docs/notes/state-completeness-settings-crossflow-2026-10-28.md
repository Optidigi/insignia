# Settings and cross-flow state audit — 28 October 2026

## Scope and evidence

Read-only review of Settings landing, permissions/readiness, Storefront setup and customer-flow testing, Billing, product-editor returns, and Methods navigation. The audit used current source and delivery decisions, focused Node 24 unit/browser tests (22 passed), an ephemeral fixture-browser probe, and Shopify developer documentation. No application or test source was changed; no build, reset, store write, or provider write was performed. Native Shopify billing-host behavior was not exercised.

## Finding

### P2 — Product setup return loses the selected test product when browser storage is unavailable

**Confidence: high for the reproduced local browser behavior; moderate for frequency in Shopify-hosted use.**

The Storefront customer-flow picker selection is intentionally an in-memory choice with optional `sessionStorage` backup. `remember()` swallows storage failures because storage is not required ([StorefrontProductTest.tsx:40-47](../../../apps/web/src/components/StorefrontProductTest.tsx#L40)). On return, cached selection is only read from storage ([StorefrontProductTest.tsx:90-103](../../../apps/web/src/components/StorefrontProductTest.tsx#L90)). The “Open product setup” link sends the editor to a bare Settings return path with no product identity or test-task fragment ([StorefrontProductTest.tsx:194-197](../../../apps/web/src/components/StorefrontProductTest.tsx#L194)). The editor breadcrumb returns to that bare path ([MerchantConfigEditor.tsx:1168-1170](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1168)), and `productEditorReturnPath()` currently allows only that exact Storefront path (otherwise Products) ([products-return-path.ts:83-85](../../../apps/web/src/shared/products-return-path.ts#L83)). The existing `#test-product` handler only scrolls/focuses the task if that hash is present ([StorefrontProductTest.tsx:123-147](../../../apps/web/src/components/StorefrontProductTest.tsx#L123)).

**Reproduction and actual result.** In `/tmp/insignia-settings-crossflow-probe.mts`, a loopback fixture provided an unpublished product and made the `sessionStorage` getter throw `SecurityError`. Select the product, choose “Open product setup,” then use the actual editor breadcrumb. Observed: return URL `/admin/settings/storefront`; returned page had no selected product and showed “Choose a product.” The merchant can pick the product again, so this is a continuity cost rather than a dead end or a lost server-side change.

**Minimal recommendation.** Preserve only the validated numeric product ID as the `testProduct` picker preselection, and the `#test-product` task fragment, in the editor return URL. The existing `storefrontProductTestSetupHref` helper supplies the product-test URL shape; extend the return-path parser to allow only the exact Storefront route plus a validated product ID and known fragment. Keep the contract explicit: preselection only. Do not infer a product handle or public URL and do not publish or enable anything automatically. Re-selecting the product remains the recovery when the requested product no longer exists or cannot be verified.
