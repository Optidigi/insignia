# Product setup reuse and calibration review B — 23 October 2026

This is an independent product review for the loopback placement preview under `apps/web/test/admin/support`. It does not authorize changes to the production product configuration or pricing contracts.

## Current preview and constraints

The placement preview keeps drafts in `sessionStorage`, keyed by setup example and Shopify product ID ([storage](../../../apps/web/test/admin/support/placement-preview-storage.mts#L50)). It can duplicate a view, or copy one placement to another view in the same product. Those operations create independent IDs, carry settings and prices, and ask the merchant to review alignment ([model](../../../apps/web/test/admin/support/placement-workflow-model.mts#L225), [editor](../../../apps/web/test/admin/support/placement-workflow-preview.tsx#L190)). There is no cross-product copy in this preview.

The production editor already has a separate whole-draft copy path. It copies only to an unconfigured product, remaps configuration IDs, preserves the target product, and removes source base and variant image references. The destination must still be reviewed and published ([editor](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L2900), [service](../../../apps/web/src/server/merchant-config.ts#L484)). Products overview selection is page-scoped and currently offers a summary download and product-ID copy action ([ProductsOverview](../../../apps/web/src/islands/ProductsOverview.tsx#L241)). Treat these as context, not as preview behavior to alter implicitly.

Decoration method pricing has two preview cases: a fixed per-item amount and a product-priced amount per placement/size. A blank product price is unavailable; an entered zero is valid. The preview permits incomplete setup to save as a draft, while invalid nonblank prices block applying the method edits. Readiness must therefore be reported at method × placement × size, rather than inferred from a method checkbox ([method editor](../../../apps/web/test/admin/support/placement-workflow-preview.tsx#L790), [setup issue](../../../apps/web/test/admin/support/placement-workflow-model.mts#L325), [save](../../../apps/web/test/admin/support/placement-workflow-preview.tsx#L1126)). The production Lean contract also says missing price is unavailable and explicit zero is a real price ([implementation plan](../../architecture/implementation-plan.md#L192)).

The preview stores placement boxes as normalized image percentages and keeps optional `widthCm`/`heightCm` production references separate ([model](../../../apps/web/test/admin/support/placement-workflow-model.mts#L30), [inspector](../../../apps/web/test/admin/support/placement-workflow-preview.tsx#L1833)). Changing an image currently retains those values and asks the merchant to review placement alignment ([image picker](../../../apps/web/test/admin/support/placement-workflow-preview.tsx#L2203)). A ruler calibration must not quietly convert the view preview into a manufacturing measurement.

## Recommended MVP

Use one preview-only copy workflow from both entry points: the editor action **Copy setup to products** starts from the current product, and the Products bulk action **Copy setup from…** uses the selected page products as targets and asks for one source. Reuse Shopify’s App Bridge Resource Picker for product selection; it provides a native catalog search/selection flow, while Polaris resource-list patterns cover compact search, selection and bulk actions ([Resource Picker API](https://shopify.dev/docs/api/app-home/latest/apis/user-interface-and-interactions/resource-picker-api), [resource list](https://shopify.dev/docs/api/app-home/latest/patterns/compositions/resource-list)). Keep the new surfaces on the project’s Polaris 2.0 RC target, with the same pinned component version ([project guidance](admin-ui-guidance-2026-10-20.md#polaris-2-preparation), [Shopify versioning](https://shopify.dev/docs/api/app-home/v2.0-rc/web-components/versioning)).

For an editor-originated copy, use the current in-memory draft, including unsaved but valid edits; say **Using current draft** before apply. For overview-originated copy, use the source product’s saved preview draft and identify it by product title and saved state. Do not make either flow silently switch sources. Refuse already-configured destinations for this MVP; do not merge or replace an existing target draft. Preflight the whole target selection and block apply if it contains the source product or any configured target. Report storage or target-specific failures by product, and leave the affected target drafts unchanged.

Copy scope should be explicit but small:

- Default to all source views and placements. Let the merchant select a subset of views for partial setup reuse; copy all placements and decoration sizes belonging to each selected view. Disallow an empty selection.
- Copy view and placement names, normalized artwork rectangles, decoration-size names/scales, selected method references and artwork-later settings. Clear source physical width/height references; they describe the source garment.
- Copy methods so the target keeps the same choices. Reuse method-library IDs where they are shared catalog identities; create fresh IDs for target-owned views, placements and sizes. If a method is absent or incompatible in the target, report it and leave that selection unavailable for review rather than manufacturing a duplicate silently.
- Add a **Copy prices** option, off by default. When off, clear both fixed method amounts and product-specific size prices, while retaining sizes and method selections. Show **Prices need review** in the resulting draft. When on, copy both pricing forms, and show a source/target price summary before apply. Never turn blank prices into zero.
- Do not copy calibration or source image membership into the target product’s media library. Preserve target product identity and target media.

For images, do not transfer source imagery or guess a target mapping. Represent each copied view with an explicit unassigned-image state, preserve the target’s media list, and keep the normalized source rectangle only as a geometry suggestion. After the merchant chooses a target image, show the rectangles over that image and require alignment review before treating the setup as ready. If the target has no images, leave the draft incomplete and direct the merchant to add/select product media. Do not match by array index, and do not assume same names or dimensions prove matching framing. This avoids source garment images appearing on another product and avoids a per-product × per-view mapping wizard in bulk copy. The preview’s current view schema requires a URL, so this needs a deliberate nullable/unassigned image state rather than an empty or fabricated URL.

Show the created draft’s source product, selected views, price-copy choice and count of views without target images. Keep it unpublished and open each target’s editor for alignment review. Normalized percentages can be reused as a starting point, but a front flat lay and a model photo can have different crop, aspect ratio and garment position. DecoNetwork advises consistent image canvases and separately recommends testing product colors; its view documentation also says product imagery may be single-image, per-color or absent. Zakeke allows print-area sizing from product measurements, but explicitly says AI-generated areas can need manual adjustment ([DecoNetwork views and areas](https://help.deconetwork.com/hc/en-us/articles/235607368-Configuring-Product-Views-Assigning-Decoration-Areas-for-Products), [Zakeke print areas](https://zakeke.zendesk.com/hc/en-us/articles/360016879139-How-to-define-a-Print-Area)). So the review state is essential, not a nice-to-have.

## Method selection and pricing

Keep the compact selection experience for many methods, but make selection and price editing distinct tasks. In the large-method dialog, use a searchable checkbox list with **All** and **Enabled** filters. Show only methods that can be selected in that list; do not make merchants open price disclosures merely to inspect or toggle unrelated methods. After selection, show a separate, compact price table for enabled methods and their decoration sizes. Fixed prices can be read-only summaries; product prices are editable per size. Keep the dialog staged: **Cancel** discards changes and **Done** applies one undoable edit.

The price table should distinguish **Unavailable** (blank), **Free** (zero), and a valid positive amount. Report coverage as `2 of 3 sizes priced`, not merely `2 size prices`. A method with no valid price can remain in a saved draft, but cannot be offered; each valid method × placement × size combination remains independently eligible. This fits the current preview rules and the Lean pricing contract. DecoNetwork’s current pricing guides show the additional process-specific and quantity-based schemes available in the category; these are reasons to keep color-count, stitch-count, quantity-break and setup-fee rules out of this editor MVP ([process settings](https://help.deconetwork.com/hc/en-us/articles/39200008381467-How-to-Configure-the-Decoration-Process-Settings-in-DecoNetwork), [decoration pricing](https://help.deconetwork.com/hc/en-us/articles/236150748-Decoration-Pricing)).

## A–B calibration

Add calibration per view image as an optional ruler tool. The merchant sets a line between A and B on the image, enters a known distance in centimetres, and sees `pixels per cm` plus read-only approximate physical width/height for the selected artwork rectangle. Use original image coordinates, not viewport coordinates: compute `linePx = sqrt((Δx × imageWidth)² + (Δy × imageHeight)²)` and `pxPerCm = linePx / knownCm`. A diagonal line is valid. Require positive finite distance, reject a zero-length line, constrain both endpoints to the displayed image bounds, and account for canvas contain-fit, pan and zoom when mapping pointer input back to original image space. Changing canvas zoom must never alter the calibration result.

Keep these dimensions read-only and separate from `widthCm`/`heightCm`. Existing production references remain manually entered. State **Approximate image scale; verify production dimensions** beside the estimate; apparel photography can contain perspective and fabric curvature. Do not make calibration a save or pricing-eligibility requirement.

Persist the A/B points and known distance with the exact image identity/revision and its native pixel dimensions. One calibration applies to that view image only; do not assume it applies to a different crop, a different view, or a variant image. A duplicated view may inherit the scale only while it points to the same exact image. Cross-product copies always clear it because the reference garment changes. On image replacement, clear the saved calibration and derived estimates immediately and show **Image changed — set scale again**. Add separate controls for **Reset line** (cancel draft A/B points) and **Clear calibration** (remove the saved scale). Clearing calibration removes only the scale and read-only estimates; manually entered production dimensions remain intact.

ImageJ’s first-party guide follows the same A/B pattern: draw a line on a known feature, enter its known distance and units, and keep calibration local to the image unless deliberately made global ([Set Scale](https://imagej.net/imaging/annotating-images#Set-Scale)). It also calls out the scale marker as a way to keep reference visible on the image ([spatial calibration](https://imagej.net/imaging/spatial-calibration)). Adobe likewise defines measurement scale as a link between image pixels and a real-world unit and supports only one active scale per document ([Photoshop measurement scale](https://helpx.adobe.com/photoshop/desktop/use-grids-measurement-guides/measure-scale/measurement-scale-and-scale-markers.html)). These sources support the interaction model; they do not establish that a garment photograph is accurate for production.

## Separate legacy review

The sibling `insignia-legacy` app has related precedents, but they are a different implementation and should not be conflated with this preview. Its overview clone copies setup records without images, geometry or calibration; its view editor clone replaces placement layout, maps views by perspective, preserves target images, and has no compatibility preview. Its ruler stores one calibration on the view, even though the selected variant image can differ; its pointer conversion also needs to account for stage transforms. That independent historical review reinforces keeping target images and calibration image-bound, and showing geometry review before reuse. It does not change the findings above about the current `/insignia` preview.
