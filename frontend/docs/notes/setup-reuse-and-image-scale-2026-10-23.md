## Implemented behavior

Large method catalogs keep a bounded three-method summary. Price coverage reads N of M sizes priced, and its action opens that method's price editor directly. Manage methods opens a searchable staged checkbox list. One selected product-priced method can be edited at a time in the same modal; returning preserves search, filter and scroll. Blank means Not offered and zero means Free. Cancel preserves the draft; Done applies all changes as one undoable edit. Small method sets retain inline controls. Native wrappers, rather than display-contents component hosts, position the mobile row controls.

Editor > More actions > Copy setup to products uses a snapshot of the current valid editor draft without saving the source. Products selection > Copy setup from uses a saved session draft or the catalog fixture's persisted initial draft. Invalid stored sources are excluded. Both use the same dialog. All views are selected initially; selected views provide partial reuse. Methods and sizes are copied together by default, with product-specific size prices optional and off initially. The destination's same-ID method definitions remain authoritative, and price copying only applies where both definitions use product pricing. No live linkage or new inheritance rules are introduced.

Copies go to empty destination setups only. The apply-time check rereads destination storage and blocks the whole preflight if any selected target is occupied, missing or is the source. New view, placement and size IDs prevent identity collisions. Product identity and target media remain intact. Source images, measurement calibration and manual production centimetres do not travel. Each copied view has an explicit unassigned image and alignment-review state. Choose image and Mark alignment reviewed complete that review. Per-target results distinguish success from storage failure, offer review links and allow failed-target retries. Results replace the configuration form after success. Reset demo clears both drafts and copy reports.

The separate Copy setup · 2 empty products example supplies a configured hoodie and two empty targets without altering the normal example. Its drafts remain separately namespaced.

Set scale starts a per-view ruler using two image points and a known distance in centimetres. Pointer input uses contain-fit, camera pan and zoom to return to intrinsic image coordinates. A coordinate-entry alternative supports keyboard use. Apply validates the points and distance; out-of-range entries remain editable rather than being silently moved. The selected artwork area's approximate dimensions update from its rectangle and the image scale. Manual production dimensions remain independent. Cancel/Escape keep the saved calibration, Undo/Redo includes applied scale changes, and replacing an image or copying across products clears calibration. On phones, starting the ruler brings the canvas into view; the second tap returns to and focuses the distance field.

## Optional measurement tool, 23 October

The ruler is now an occasional canvas utility rather than a permanent Image scale section. A bottom-right ruler button mirrors the bottom-left help control and shares the zoom control's vertical centerline. The glyph is a small app-owned decorative SVG inside a public Polaris tertiary button: the pinned icon catalog's `measurement-size` glyph represents dimensions with arrows, rather than a ruler. Native hover, keyboard focus and tooltip behavior remain with the public button.

The entry label is **Measure image**. Active controls use **Known length**, **Use measurement**, **Redraw line**, **Cancel** and **Clear measurement**. Mark A/B on a known length and enter centimetres. Use measurement applies an undoable draft change; the existing Save draft action persists it. The form appears in the inspector only during measurement. Without a saved measurement, routine view and placement settings contain no measurement section. Once applied, they show the estimated dimensions and the production-verification caveat. Manual production dimensions remain separate and clearing the estimate preserves them.

The active canvas prompt provides step-specific instructions and a visible Cancel action. It uses one live status message rather than duplicating the accessible instructions. On phones, marking expands the canvas and completing B returns to Settings and focuses Known length, retaining the previously tested handoff. No new modal or floating form obscures the garment. A saved line can be reused by editing its known length or replaced by marking a new line.

Three independent Luna xhigh reviews informed the control placement and wording and inspected the resulting implementation. The cancellation concern raised by one review was checked against the existing measuring/image-identity effects, which already reset pending points. The related mid-session Redraw concern was real: it retained a pending A when the parent line reset. A failing browser regression reproduced that case, and resetting pending points on line changes fixes it. The same regression also covers keyboard entry and cancel/restart.

## Canvas-local measurement refinement, 23 October

The optional ruler now keeps the whole task on the canvas. The first state shows the A/B instruction, Cancel and a keyboard coordinate-entry alternative. Completing B reveals a compact Known length / Apply panel; numeric coordinates stay collapsed. Normal placement settings contain no active measurement form. Applied output says Estimated size because it describes width × height, not an area. There is no phone tab switch, post-B canvas resize, forced touch focus or scroll into the inspector. On small screens, explicitly activating the ruler still enlarges the canvas to make room for precise marking and the field; the unnecessary scroll-to-top was removed. Routine setup remains unchanged.

Three independent Luna xhigh reviews and the Vercel interface/design guidance informed the reduction. The actual Shopify theme editor was recovered through the browser's user-tab claim API: its Connect dynamic source control is a quiet 24px utility that opens contextual content, and Save remained disabled after that popup was inspected and dismissed. This is a hierarchy/reference observation, not evidence that Shopify has this ruler workflow. An app-owned canvas panel intentionally keeps point capture interactive; it uses public Polaris fields/buttons rather than a modal or popover that would intercept the marking task.

A browser regression reproduced the ruler tooltip moving its trigger by 3px. Tooltip hosts were participating in the ruler's grid and inspector header's flex layout. Those overlay hosts now sit outside the control tracks, without changing Polaris internals. The ruler uses the public empty icon slot to retain the same native 28×28 icon-only button shape as Help, with a decorative 16px ruler drawing in the reserved slot. Both trigger and glyph remain stationary on hover and keyboard focus; the inspector menu still opens and its actions remain reachable.

The new canvas-local entry exposed a second real interaction issue: the trailing click from point B could activate a newly mounted native number field. Marking completes on pointer release, and the canvas suppresses that gesture's trailing click while allowing the next pointer gesture and keyboard activation. Keyboard coordinate entry now transfers focus to the revealed point fields. Raw coordinate edits preserve a cleared value and block Apply rather than reusing a stale number; correcting a point clears its stale error. Enter in Known length applies, while the coordinate disclosure and Redraw/Cancel retain their own keyboard behavior. The form encloses only Known length / Apply, so the review concern about its Enter shortcut intercepting those other controls did not reproduce.

Focused checks pass across the final runs: combined drag/resize/snap/pan/zoom, on-demand help, stationary ruler/inspector hover and focus, keyboard coordinate entry/cleared values, and the ruler's desktop/390px/320px lifecycle. Scoped TypeScript and Biome checks and Polaris 2.0 RC main-editor revision 15 / canvas revision 3 pass. No production code, persistence contract or publication behavior was changed. Evidence: `/tmp/insignia-ruler-simple-desktop.png`, `/tmp/insignia-ruler-simple-phone.png` and `/tmp/insignia-ruler-simple/`.

## Publication and a single size concept, 23 October

Three independent Luna xhigh reviews researched the save/publication boundary, size semantics and copy-dialog workflow before implementation, then reviewed the resulting changes. Fresh authenticated Shopify theme-editor DOM confirmed its separate status and Save affordances. The new Themes-list reference tab did not load its embedded application, so no claim is made of freshly observing its Publish menu. No native Shopify writes were made. Primary references were [theme publication](https://help.shopify.com/en/manual/online-store/themes/managing-themes/publishing-themes), [Canvas save versus publication](https://help.shopify.com/en/manual/online-store/themes/canvas/customizing), [product duplication](https://help.shopify.com/en/manual/products/add-update-products), [Shopify forms](https://shopify.dev/docs/apps/design/user-experience/forms), [public resource lists](https://shopify.dev/docs/api/app-home/v2.0-rc/patterns/compositions/resource-list), [Clickable](https://shopify.dev/docs/api/app-home/v2.0-rc/web-components/actions/clickable), [ImageJ calibration](https://imagej.net/imaging/spatial-calibration), and Printful's [Design Maker](https://help.printful.com/hc/en-us/articles/50264179910673-How-does-the-Design-Maker-work), [templates](https://help.printful.com/hc/en-us/articles/50263591495185-What-s-a-product-template-and-how-does-it-work) and [copying](https://help.printful.com/hc/en-us/articles/50263450185873-Can-I-copy-my-products). Current Vercel interface guidelines informed focus, responsive disclosure and keyboard checks.

Save draft now sits alongside a clear primary Publish action, including on phones. Publish reviews a frozen copy of the current setup; confirmation includes current edits, so a separate preliminary save is unnecessary. Readiness checks identify missing images, copied alignment review, invalid geometry/names and placements without an offered price combination. Review links return to the relevant view/placement and field or method section. Blank unavailable size prices do not incorrectly block an otherwise offered placement. After successful local publication the header says Preview published; later edits restore Save draft / Publish and show Draft changes. Draft saving does not change the published snapshot.

This remains a frontend prototype. The review explicitly says that publishing is simulated in the current browser tab and does not update Shopify. One versioned envelope atomically stores draft, published snapshot and revision under the existing example/product-scoped storage key. Legacy raw drafts migrate on write. Malformed state fails closed, revision conflicts require reopening the review, and failed storage writes preserve the previous state and current editable work. The loopback-only catalog adapter uses a published snapshot for its demo status/summary when available. Those simulated Products badges are enclosed by Local demo chrome; no production catalog status or publication API is changed. The existing production save/version/publish operations remain the future integration seam.

Code inspection established that preview placement widthCm/heightCm were stored and validated but had no downstream consumer. Their inputs were removed rather than maintaining two competing size concepts. Existing values are preserved for compatibility and ignored by this preview's save/publication validation. A browser test caught and fixed the initial hidden-validation save blocker. Real production dimensions are per decoration-size physicalMm and are still used by production sheets; this change does not remove or reinterpret them. The optional ruler remains an image-based approximation, with its source/100%-artwork-area explanation. Each calibrated placement now displays its own quiet, single-line estimate beside its name. Long names truncate; hover/focus reveals the existing actions without overlapping the estimate.

Copy setup now uses the public resource-list composition: native Clickable row, checkbox, thumbnail, name and status. Keyboard row selection and checkbox toggling do not double-toggle. The default includes methods and sizes; the confusing option to exclude them was removed because it produced unusable empty shells. Customize copy retains selected views and optional product-specific prices, with the scope explained in words. Destination images and alignment still require review. Existing published targets are protected even when their newer draft has no views; unreadable state is protected too. Preflight rereads state and keeps blocked targets removable. Failed-copy retries preserve their original scope, and newly occupied targets no longer strand other retryable failures. The latter mixed retry recovery was verified by code review; the three-product browser fixture cannot represent that larger combination.
