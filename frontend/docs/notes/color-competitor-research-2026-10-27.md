# Multi-color product customization: competitor evidence and Insignia recommendation

**Reviewed:** 2026-10-27. Researcher recommendations below are input to the final decision, not an implementation commitment. The final synthesis narrows conditional behavior and separates photograph alignment from physical production differences.
**Scope:** First-party help-center documentation for Customily, Zakeke, Kickflip, Teeinblue, and InkyBay. I reviewed docs, not vendor admin apps. The root task also inspected the published Customily variant-matching and Teeinblue assignment article DOM/screenshots; those were documentation pages, not logged-in app screens. Captures: [Customily match-values article](/Users/pc/Development/Insignia/.artifacts/color-variant-research-2026-10-27/customily-match-values.png), [Teeinblue grouping article](/Users/pc/Development/Insignia/.artifacts/color-variant-research-2026-10-27/teeinblue-group-by-mockup.png).

## Recommendation for Insignia

Build around **color-and-view asset groups**, with Shopify color and size choices remaining the merchant’s source of truth:

- Map each Shopify **Color option value** to a real product image for each buyer-facing view (for example, Navy → front and Navy → back). Apply that group to every size variant of the same color. Allow an exact variant override only for genuine exceptions.
- Keep each view’s print placement shared by default across color images. Add optional placement overrides at the color/view level; introduce size-specific print areas only when production dimensions or physical placement actually differ.
- Preserve the current buyer flow: a labeled color swatch changes the product gallery/preview; the size/quantity matrix selects the Shopify size variants. Keep one shared artwork/customization state per selected design.
- Provide explicit variant-driven show/hide rules for personalization fields or groups. Start with simple conditions based on selected Shopify option values; defer a general-purpose rule builder until real products require it.
- Use actual supplied color photography for buyer-facing product views. Do not automatically tint product photos to simulate garment colors. A CSS swatch can represent the option; it should not imply the gallery image is a real photo of the selected color unless it is.

This combines Customily’s documented shared placement across color images, Teeinblue’s reusable bulk mockup assignment, and the finer variant-specific exceptions documented by Zakeke. It also avoids generating and maintaining a separate image for each Color × Size combination. That last point is a recommendation inferred from the documented variant-matrix workflows and Insignia’s current size/quantity-matrix UX.

For the current Insignia architecture, bring the old shared-image / variant-images concept forward as a color-grouped, per-view asset mapping, while retaining a default shared placement and sparse overrides. The current editor’s view-image/placement model does not yet express color mapping, and the current preview adapter is limited to one color and one size (project context supplied by the root task).

## Evidence by product

### Customily

- **Color images and placement:** Product Base accepts one blank product image per color/material/finish. Upload filenames become color option values, and the print area is positioned once and reused across the images. The vendor warns images should have the same or very similar size and layout. This is the closest documented match for Insignia’s shared-placement default. [Setting up product images](https://help.customily.com/articles/9628015600-setting-up-product-images-in-your-product-base) and [creating a Product Base](https://help.customily.com/articles/8796195814).
- **Shopify variant behavior:** Product Variants can assign a function to each variant; the documented color example swaps a dynamic image when a garment color is selected. Size can select another Template when the print file needs to change. Product Bases configure these functions automatically, according to the docs. [Add functions to product variants](https://help.customily.com/articles/6457305403).
- **Conditions:** Conditions can show or hide a single option or a whole Option Set based on selected product variants. Multiple conditions support AND/OR. [Conditions with Product Variants](https://help.customily.com/articles/8832570537).
- **Views:** A Template can have independently configured previews for front/back or lifestyle views. Buyers can switch views; previews can also switch when they edit a field associated with a view. The docs specifically warn that preview selection itself should not hide required personalization fields. [Multiple previews](https://help.customily.com/articles/9278953739-multiple-previews).
- **Shopify mapping:** For an existing Shopify listing and merchant-owned Product Base, Customily asks merchants to match each Shopify option name and value to its Product Base equivalent, such as Color → Color and White → White. It warns that an unmatched color may stop the preview from updating. The root task captured the published match-values screenshot linked above. [Match variants to a Product Base](https://help.customily.com/articles/7057019054).
- **POD mapping:** For an existing Shopify listing and POD product, Customily likewise asks merchants to match every option name and value to the provider equivalent; it warns unmatched variants can fail fulfillment and may not update preview color. [Personalize an existing product with a POD provider](https://help.customily.com/articles/4521597764).
- **Tradeoff:** Low-friction shared setup when color images align; per-color image assets remain necessary for accurate product photos. Size-dependent production differences can require a separate Template.

### Zakeke

- **Variant matrix and images:** Zakeke imports attributes from the store and generates combinations. Each combination can have its own image and variant-specific print-area adjustment. When all attributes/options are imported, it can import store variant images on supported integrations; if only some are imported, images must be assigned manually per combination. [Variants guide](https://zakeke.zendesk.com/hc/en-us/articles/360015501299-Variants-Detailed-guide-on-setting-them-up-for-your-customizable-product).
- **Buyer controls:** With one imported attribute, variants appear as images; with multiple attributes, they appear as dropdowns. The guide says this presentation is automatic and not merchant-selectable. Non-imported attributes remain on the store product page and are still passed to cart. [Variants guide](https://zakeke.zendesk.com/hc/en-us/articles/360015501299-Variants-Detailed-guide-on-setting-them-up-for-your-customizable-product).
- **Views and exceptions:** Products have sides (views) and print areas. A side can be removed for a particular variant, so a buyer can see/edit the back only for variants where it exists. [Sides](https://zakeke.zendesk.com/hc/en-us/articles/360009494599-Side-s) and [creating a customizable product](https://zakeke.zendesk.com/hc/en-us/articles/360026668693-Create-a-customizable-product).
- **Tradeoff:** Strong exception handling where a specific size/color truly needs a different print area, image, or available side. A full variant matrix can become a large manual assignment surface, especially when only some attributes are imported. The docs reviewed do not describe bulk assigning images/print areas across combinations.

### Teeinblue

- **Bulk image assignment:** Merchants can assign one or multiple mockups to selected variants; the UI supports select-all, grouping by mockup or variant, and bulk-assigning multiple mockups to multiple variants. Assignments can live in Product Base and be reused by campaigns. When synced to Shopify, the first assigned mockup becomes the variant image. [Assign variants to mockup](https://support.teeinblue.com/en/article/assign-variants-to-mockup-13wqtx6/).
- **Approximate recoloring:** Transparent mockups can use a variant’s Color Hex to change the visible background color, avoiding a separate mockup for every variant. The same documentation says the gallery thumbnail does not change color and that this hex is preview-only, not the print file. [Change mockup background by variant color](https://support.teeinblue.com/en/article/change-background-color-of-mockup-as-variant-color-2idxxb/).
- **Print areas:** Custom variant print areas exist for genuinely different output dimensions (such as poster sizes or different mug sizes). Several variants can share one print area when its name and dimensions match; once enabled, each variant must be connected to a print area. [Custom variant print area](https://support.teeinblue.com/en/article/custom-variants-printarea-5plxay/).
- **Shopify and conditions:** Product Base variants carry Color and Size; docs describe importing/exporting variants by CSV and bulk editing rows. Its “Campaign by Shopify products” flow leaves variant data in Shopify and can connect different artworks to selected Shopify variants, showing an artwork’s fields only for linked variants. [Variants of Product Base](https://support.teeinblue.com/en/article/variants-of-product-base-ajxiit/) and [existing Shopify products](https://support.teeinblue.com/en/article/personalize-existing-shopify-products-with-campaign-by-shopify-products-1wo8urm/).
- **Tradeoff:** Most directly useful reference for efficient image-to-variant assignment. Its background recolor feature is a useful optional preview technique, but its thumbnail limitation and preview-only behavior make it a poor substitute for actual product-color photography in Insignia.

### Kickflip

- **Layered views and color:** Product images are built from layers; an image answer can contain an image for each view. A linked color question can dynamically apply a color to an image, and shared color answers can be imported across layers. For color accuracy, the docs require near-white/desaturated source assets; dynamic tinting avoids creating a separate layer for every color. [Adding product images](https://help.gokickflip.com/en/articles/4586187-adding-images-to-display-the-customizable-parts-of-your-product), [dynamic colors](https://help.gokickflip.com/en/articles/4668498-applying-colors-on-an-image), and [first customizer guide](https://help.gokickflip.com/en/articles/5647561-build-your-first-customizer).
- **Conditional options:** Logic rules can restrict answers and show/hide questions based on earlier answers. [Conditional logic](https://help.gokickflip.com/en/articles/4586211-adding-conditional-logic-to-your-customizer).
- **Shopify mapping and bulk:** Inventory Sync explicitly links each Kickflip variant to a Shopify variant and supports bulk linking/unlinking. Kickflip documents that it cannot create new variants on Shopify products with multiple option groups (such as Size and Color); those combinations need to exist in Shopify before linking. [Shopify inventory sync and linking](https://help.gokickflip.com/en/articles/15326682-shopify-inventory-sync-linking-and-unlinking-kickflip-variants) and [multi-option limitation](https://help.gokickflip.com/en/articles/15424618-inventory-sync-with-shopify-limitations-when-creating-shopify-variants).
- **Buyer integration tradeoff:** One Shopify integration mode replaces the product page with the customizer; its Customize Button mode hides the Shopify variant picker, quantity input, and buy buttons. [Shopify integration](https://help.gokickflip.com/en/articles/15197177-integrating-your-customizer-in-shopify).
- **Tradeoff:** Great reference for component/layer color logic and variant linking, but it expects carefully prepared layered imagery and its Shopify integration can take over product selection. Dynamic tinting is not the right default for Insignia’s actual color gallery.

### InkyBay (additional apparel configurator)

- Product Color Sets can use color hex values, but also support **an image instead of a color** with a separate product image for each color. Color Groups allow different product panels to have independent color sets; linking panels into the same group synchronizes their color. [Set up product colors](https://docs.inkybay.com/spf/en/how-to-set-up-product-colors) and [configurable products](https://docs.inkybay.com/spf/en/how-to-create-configurable-products-using-inkybay).
- Its product-page settings describe color swatches whose selection carries into the design tool, plus a size list with quantity boxes. The docs note that theme image selectors may need configuration for the product image to update. [General settings](https://docs.inkybay.com/spf/en/category/general-settings).
- **Tradeoff:** Useful apparel precedent for preserving color + size quantity selection and for multi-panel garments. Its docs say the app does not provide POD fulfillment; fulfillment is handled by the merchant or an external provider. The docs reviewed do not establish a direct mapping to each native Shopify Color × Size variant, so that integration should not be assumed. [InkyBay help center](https://docs.inkybay.com/spf/en).

## Decision summary

| Insignia need | Best documented pattern | Insignia implication |
|---|---|---|
| Per-color, per-view imagery | Teeinblue assigns multiple mockups to multiple variants; Customily models multiple independent views | Store assets by color and view, then assign one color group across its size variants |
| Shared print placement | Customily reuses one placement across color images; Teeinblue permits variants to share a print area | Make a per-view shared placement the default |
| Rare placement/output differences | Zakeke allows variant-specific print-area edits; Teeinblue maps variants to custom print areas | Offer targeted overrides, including size-specific output only when production requires it |
| Conditional personalization | Customily has variant conditions; Kickflip has answer/question logic; Teeinblue can connect artwork to Shopify variants | Ship a small explicit variant-condition model first |
| Merchant bulk setup | Teeinblue mockup bulk assignment; Kickflip Shopify variant bulk linking | Bulk-assign color assets across all sizes, and show unmapped color/view warnings |
| Shopify inventory/cart | Customily maps every value to POD; Kickflip links app variants to Shopify variants; Teeinblue’s Shopify campaign leaves variants in Shopify | Keep Shopify color/size variant identity authoritative through add-to-cart |

**Strongly supported:** Shared color-image placement, multi-view previews, bulk image assignment, variant-driven option visibility, and sparse per-variant print-area exceptions are all documented capabilities in these products.
**Inference:** For Insignia’s stated buyer UI, mapping at Color-value × View and inheriting across Size is the best balance. No competitor documentation reviewed proves that its internal data model is identical; this is a product recommendation from their documented workflows and the Insignia architecture summary above.
