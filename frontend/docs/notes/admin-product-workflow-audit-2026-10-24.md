# Product workflow audit

24 October 2026. The owner requested a broad product review with Luna Max agents, then narrowed the emphasis to the areas already being designed. This pass covers Products, Methods, product setup, customer preview and Orders. Untouched Settings and homepage presentation is excluded. Account/readiness observations are retained only when they affect a workflow across screens.

## Review method and sources

Six independent reviewers used GPT-6 Luna at maximum reasoning. They reviewed realistic merchant/buyer tasks, source contracts and actual local UI evidence. They did not grade code style or assume every possible feature belongs in Lean V1.

## Decisions and implemented changes

| Issue | Outcome |
| --- | --- |
| Two Methods destinations look like competing product versions | `/admin/methods` is the canonical application destination. The old Settings URL redirects there while preserving embedded query context. Navigation, Settings and the application editor point to that destination. The local rich workflow uses the same route. Older template-only gallery captures are available only under **Template implementation checks**. |
| Global default prices appear to govern existing product prices | The rich local editor explicitly calls these **Default pricing** and explains snapshot copying. Product availability controls which library choices can be added later. Existing copies, prices, publication snapshots and orders remain independent. Silent propagation is rejected. |
| Eligibility counts look like usage, and readiness uses old fixture data | The local index shows **Products using** from saved product methods actually enabled on placements, with available-product counts secondary. It reads the selected local example's saved setup rather than the older separate method fixture. **Configured** distinguishes setup from publication. Changing a library default cannot invalidate a saved product's own price. Scale fixtures remain synthetic. |
| A retained fixed product price has no edit path | Confirmed by the skeptic after changing a library default. The editor now exposes an explicit product-price task from both compact and large method controls. Scope text says all placements using this method on this product. Cancel drops it; Done stages it; Save draft persists it. Other products and library defaults remain unchanged. |
| First product requires leaving setup to create a method | **Add method** now creates a product-only method and continues to placement prices in the chooser. This works with empty and populated libraries. Creation and prices remain staged until Done. The reusable-library path remains available for reusable work. |
| Optional library description is dropped on product import | The field is now explicitly **Library note**, with its limited scope stated. It does not promise a customer-facing description. A customer-facing method description would require a deliberate product/buyer contract. |
| Artwork download loses test/hold context | Orders shows Test alongside identity. The ZIP dialog uses the freshly prepared purchase snapshots and the worksheet's shared order-level checks to retain Test and named hold reasons before download. Download remains available; payment, fulfillment and production decisions are not invented by this app. |
| Copy review omits customer movement from its stated scope | Copy details now name enabled movement areas and their target-image review. Existing target alignment review already mentions artwork and movement and blocks unresolved publication, so no extra mandatory step was added. |

The saved product price example was €5.00. A library default edit left it at €5.00. An explicit product edit to €9.50 survived saving/reopening while another product stayed at €5.00. This is local preview evidence, not a Shopify price write.

## Remaining work and rejected findings

The largest integration gap remains the richer Methods/placement workflow's production persistence. The application template service still stores names and optimistic versions. Production imports create independent product-method identities without source-template provenance. Integrating default prices and trustworthy usage requires versioned source-template provenance and explicit snapshot materialization into the final product price table. Do not infer usage by matching names, relabel preview assignments as production facts, or ship the prototype's session storage as an authenticated service. Canonical navigation and a single current review surface are implemented; the richer production workflow is not claimed complete.

The phone product-identity finding is addressed in the no-image first-use state by showing the full product name beside the guidance. A generic illustration can no longer be the only visual context when the host title is truncated. The host header itself retains its normal truncation. The source-only publication/readiness terminology observation belongs to the integration follow-up; untouched Settings presentation is not added to this polish queue.

The copy/movement concern was initially overstated. Verification found an existing explicit movement-area review and publication gate, so it is a clarity improvement rather than an unsafe bypass. Blank price vs explicit zero was correct in the checked editor. The buyer's live prototype totals, placement undo/removal and review updated correctly in the tested scenarios. No speculative tier pricing, RFQ, fulfillment engine, dashboards, automatic reminders, or extra confirmation steps were added.

## Verification and scope

Focused browser and model verification covers canonical routing/embedded context, existing template recovery, first-product library selection, in-place creation, fixed-price Cancel/validation/Done/save/other-product independence, large method dialogs, library recovery, defaults/readiness separation, current-original ZIP content and named multi-order folders. Fresh desktop/phone galleries cover the changed surfaces. Final results: 30 distinct relevant browser workflows and 13 model/storage checks pass. All 18 Methods workflows pass, alongside six placement workflows, two canonical navigation checks, two application-template import/recovery checks and two archive workflows. The application web build passes with 147 checked files and zero diagnostics. Strict admin-test TypeScript, source contracts and 24 scoped Biome checks pass. Public Polaris validation passes for the changed Methods index/editor, placement method manager and artwork archive controls at `2.0-rc`, resolving to the `v2.0` catalog. Imported custom components remain outside that validator's public-component checks and are covered by project types and browser tests.

All three capture areas pass. The final gallery has 86 states and 171 images, including two added method tasks. It opens on 11 latest states; 77 current states and nine template implementation states remain separately selectable. The portable ZIP contains 181 files and was checked for CRC, exact current file bytes and actual PNG dimensions. The primary implementer visually checked the final desktop/phone images, including the inset fixed-price form and full product identity in the no-image guide. The independent skeptic found no unresolved blocker in the local scenarios it checked. This is focused verification, not the complete application test suite or production qualification.

All writes were to local source, disposable test contexts or tab-local preview state. No Shopify product/order, live publication, checkout, deployment or production database was changed. The separate buyer prototype and merchant preview are not an end-to-end production test. Owner visual acceptance and release approval remain separate.
