# Current product editor and method library controls

Observed from source on 20 October 2026, branch `codex/ui-redesign`, commit `1a18b463631ef162cdb577a8a4268500630a7e82`. This is a source and regression-test inventory. No native Shopify session, provider mutation, browser acceptance, or newly executed test result is claimed. The current merchant presentation remains owner-unaccepted. Its layout, section sequence and wording are not a reference or ceiling for the future UI. This note inventories behavior to preserve and gaps to resolve, not a design to reproduce. The intended product behavior is in [specification section 7](../../architecture/implementation-plan.md#7-admin-application).

The line links below point to this checkout's implementation. `MerchantConfigEditor.tsx` supplies both the product picker and product editor. `MethodLibrary.tsx` supplies the independent reusable-name library.

## Product picker

Route `/admin/products` mounts picker mode. It has a product search input, explicit Search button, result count, product thumbnail or No image text, linked product title, Shopify status badge, variant count, next-page table navigation, and an empty state with Clear search. Search writes nothing. Next-page reads use `cursor` and the current search input. There is no previous-page control declared here, bulk action, config-state column, product creation control, or Shopify product editing control. [Picker request](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L573), [rendered picker](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1261).

## Product configuration workflow

Route `/admin/products/:productId/config` reads the current product/config. A product without a config gets its title, Shopify status, optional image and Create configuration button. Unsupported draft versions receive a status message rather than typed editing controls. A missing or denied editor has Retry session. [Read/create behavior](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L573), [create command](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L829), [empty config](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1408).

The editor has four sections, selectable directly or with Back/Continue actions, plus All settings. Section changes update browser history and preserve the unsaved draft; they are not validation or write checkpoints. Sections are Product rules, Images and print areas, Prices, and Review and publish. Deep links use their anchor or `?view=all`. A Preview anchor jumps to the persistent aside. Settings and Products navigation remain available. [Step model and URL state](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L333), [section selector](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1437), [Back/Continue](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L2326).

### Customer options and prices

Customer options have an Option name, per-value name fields, Remove option, Add value and Add production option. New options start with one generated value. Removing an option removes its option and nested value labels. There is no ordinary individual-value removal, reorder, per-value price or conditional availability control. [Customer options](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1955).

The price table expands every allowed method × placement × allowed size combination. Each cell accepts a final nonnegative shop-currency surcharge per garment with up to two decimal places. Blank removes the rule and means unavailable; explicit `0` saves a free choice. Make unavailable removes an existing rule. Prices are added across the buyer's selected placements to the garment price. Names identify the choices; colliding names get disambiguating suffixes without changing IDs or saved labels. [Cell generation and updates](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1195), [decimal validation](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L162), [table and unavailable action](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L2077).

Historical pricing is rendered read-only, including existing setup/unit scope, fixed or tiered amounts, and presentment overrides. Set decoration prices explicitly clears local historical pricing and starts an empty Lean proposal. This does not change a published revision. There are no ordinary controls to create setup fees, quantity tiers, price layers, presentment overrides or method multiplicity. [Historical pricing](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L2045).

Advanced configuration JSON is still available to any editor who can reach these controls. It opens a full draft text area and Apply JSON button. Local application checks only the draft marker and valid geometry; full contract and domain validation still belongs to the save endpoint. Invalid JSON/geometry raises an error and blocks ordinary Save. This is a broad escape hatch, not a read-only diagnostic. [JSON controls](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L2173), [local draft check](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L127), [strict draft schema](../../../packages/contracts/src/v1/merchant-draft.ts#L37).

## Save, publication, copying and recovery

Save uses `PUT` with config ID, current draft version, a trimmed-label snapshot and an idempotency key. Success checks the expected next version, then reads the saved config again before enabling publication for that exact draft. A stale save becomes conflict state. An interrupted response triggers a matching read; an unproved outcome retains the exact original request and offers Retry saving. The browser does not merge competing edits. [Save implementation](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L844).

The host App Bridge Save Bar is preferred; fallback controls are Save draft and Discard changes. Discard requires a confirmation modal and restores the saved draft without a write. Normal same-tab links and unload are guarded while dirty. Unresolved writes disable editing, discard and load-other-draft actions until reconciled. Conflict state can show Review latest saved draft and Reload current draft. Invalid price text, invalid JSON and historical pricing block normal saving. [Save bar wiring/recovery actions](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L2430), [host/fallback/navigation confirmation](../../../apps/web/src/components/AdminSaveBar.tsx#L36).

Review and publish shows publication status and a collapsed Technical publication details disclosure containing latest/effective revision IDs, reason, all-channel hold and Function readiness. Publish saved changes requires clean/saved valid prices and current server eligibility. Continue publication resumes a pending immutable request, preserving its source draft version and installation generation even if local edits change. Storage in `sessionStorage` supplements deterministic command keys. Publication can temporarily pause product availability; the UI warns before the action. Operator hold, restoration conflict and Shopify conflict disable publication and ask for support. A five-second passive read refreshes publication/readiness without overwriting local edits or save recovery. [Publication labels/details](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L270), [request recovery](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L517), [passive refresh](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L641), [publish implementation](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1054), [publish button](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L2240).

Copy to another product is collapsed by default. Search destination products and Find destination products return up to 20 candidates. The selector excludes the current product, displays title/status and has no pagination. Copy configuration requires a chosen candidate and clean/saved valid state. It sends a copy command and navigates to the destination editor. It copies the saved draft into an independent destination that needs its own review/publication; the UI says existing destination configuration is not overwritten. Create and copy have no dedicated exact-request retry UI equivalent to save/publication. [Copy UI](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L2281), [copy behavior](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1121).

Authorization failures clear private editor data. Hidden-page returns reload only when there is no dirty/saving/ambiguous/conflict state; periodic publication reads are separate. A draft may remain editable while its earlier publication continues, but busy work and an unresolved save lock edit controls. Section navigation and sample artwork preview are not draft writes. [Authorization clearing](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L476), [visibility reload](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L618), [edit lock](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L464).

## Cases the UI rebuild must preserve or resolve

- Removing a product method deletes its ID and display label but does not clean placement allowed-method references or pricing rules. Changing allowed methods/sizes also leaves existing prices in place; `leanPricing` treats rules outside those allowed combinations as historical. Removing a method alone can instead leave dangling allowed-method/price IDs for server validation. This is source-observed behavior, not a newly reproduced runtime bug. A rebuild needs a deliberate removal/cleanup interaction, while preserving server validation. [Method removal](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1583), [allowed choices](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1797), [Lean classifier](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L163).
- A successful library refresh alone does not unlock an uncertain operation, despite copy telling merchants to refresh before continuing. The existing regression explicitly refreshes then retries the original change. [Source](../../../apps/web/src/islands/MethodLibrary.tsx#L65), [regression](../../../apps/web/test/admin/editor-browser.test.mts#L3095).
- The advanced JSON editor, customer production options and historical display are real current controls. Do not accidentally describe the UI as only mode/method/placement/size/prices. [JSON/options](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L1955).
- Source and browser regression names establish implemented behavior and intended checks, not present native acceptance. Current tests already cover independent library copies, guided steps, numeric geometry before blur, variant-image inheritance, exact-zero pricing, invalid-price gates, publication retries across reload, stale conflicts, uncertain-save fencing, discard, and modal cancellation. [Editor regressions](../../../apps/web/test/admin/editor-browser.test.mts#L291), [price regressions](../../../apps/web/test/admin/editor-browser.test.mts#L2744), [guided/import regressions](../../../apps/web/test/admin/editor-browser.test.mts#L2952), [save/recovery regressions](../../../apps/web/test/admin/editor-browser.test.mts#L3486). Durable tests cover independent copies/CAS/reinstall boundaries and library template isolation. ## Frontend work versus API or product changes

The existing `PUT /api/admin/products/:productId/config` saves a complete draft with CAS and idempotency. It already accepts the geometry/options/labels/rules structures needed for ordinary deletion, reordering, override removal and option-value removal. These tasks need correct draft transformations and regression checks, not new delete endpoints. They must preserve at least one geometry view, matching product/geometry placement IDs, valid allowed-step references, valid labels, and valid Lean prices. Current geometry bounds are 16 views, 64 steps, 64 placements per view, 100 variant images per view and 100 rectangle overrides per placement. These are validator limits, not commercial capacity promises. [Save handler](../../../apps/web/src/server/admin/http.ts#L255), [server draft validation](../../../apps/web/src/server/merchant-config.ts#L79), [geometry validation/bridge](../../../packages/visualizer/src/geometry.ts#L140).

An exact sum of selected decoration surcharges can be presented from current saved/draft price cells using exact minor-unit arithmetic. It does not need a new mutation API. A full customer quote that includes contextual Shopify garment prices, Market eligibility or cart discounts is a different task: the current `CatalogProduct` DTO has no variant prices. That would require an existing qualified quote/read integration or a deliberately extended server read contract, rather than inventing prices in the browser. [Catalog DTO](../../../apps/web/src/shared/admin-view.ts#L2), [Lean pricing entry](../../../packages/domain/src/pricing/lean.ts#L26).

Clearing sample artwork and making shared/overridden geometry visible are frontend state/presentation work. The renderer already accepts an artwork `none` state and geometry already distinguishes defaults from override arrays. [Editor state](../../../packages/visualizer/src/geometry.ts#L51), [geometry model](../../../packages/visualizer/src/geometry.ts#L24).

Supporting all product media or browsing beyond the returned 500 variants needs catalog query/DTO work. Supporting arbitrary merchant-uploaded product mockups needs stable image registration/resolution and the matching ownership/asset lifecycle; the existing browser image map only resolves product/variant image references. Copy destination pagination can reuse the existing products endpoint cursor contract. New artwork policies, per-option prices, setup/tier/FX offers or linked library inheritance need a product/domain contract decision before implementation. [Catalog shape](../../../apps/web/src/shared/admin-view.ts#L2), [current image resolver](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L793), [cursor read](../../../apps/web/src/islands/MerchantConfigEditor.tsx#L580).
