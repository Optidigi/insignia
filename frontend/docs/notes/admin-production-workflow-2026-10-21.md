## Original artwork archives

Download artwork prepares current originals for one order or the selected orders. It reads explicit file metadata through the existing purchase-authorized endpoint with `metadata=1`. Ordinary signed-download responses retain their existing shape. MIME type, exact byte length and SHA-256 come from the existing inspection manifest, with unchanged tenant/staff/retention checks.

The client verifies every original's byte length and SHA-256, fetches without credentials, and never displays or executes original SVG content. A small pinned `fflate` dependency builds a ZIP using stored entries and cancellable chunks. Bounds are twenty orders, two hundred unique files and sixty-four MiB of original bytes. Individual reads have a twenty-second deadline. These bounds do not establish a universal device-memory guarantee.

Paths identify order, design and placement. Placement filenames use P1/P2 to match worksheet instructions. Indexed paths prevent collisions and strip path separators/control characters from merchant-supplied labels. A single-order archive name includes order, artwork version and a UTC timestamp; batch names include order count and timestamp. Reused assets within one order share a file, and the manifest maps every placement to its file. Every included binding caps the archive's expiry, including deduplicated placements.

Missing, expired or failed files appear as exclusions in the preparation report and manifest. The report shows short filenames and marks shared files, with full paths in tooltips and the manifest. Single-order reports omit repeated order numbers. Partial download labels state the file count; all-failed reports offer preparation again. Large reports paginate twenty placements at a time. Immediately before ZIP creation the app re-reads each order and rejects changed facts. Closing, changing selection or losing authorization clears retained bytes. Expiry is checked during ZIP creation and immediately before starting the download.

The existing signed storage URLs require browser-readable CORS for original-file fetches. Local service-worker/route fixtures qualify the archive behavior, not native object-storage CORS. Existing individual signed downloads remain available as a fallback. Native storage/browser qualification remains a release check; this pass does not change provider CORS settings or broaden access.
