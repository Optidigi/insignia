# Home V1 preflight

26 October 2026. Source-grounded acceptance checklist for the in-progress Home V1. This is a preflight, not a visual review: no rendered Home was available, so it records criteria and likely owner objections without asserting that any are present. The implementation is a frontend scenario-fixture exercise; the fixtures should make their facts explicit and must not imply backend aggregation or production readiness.

## Likely owner objections to screen for

- **Does Home earn its place?** It should combine product setup, storefront setup when relevant, and customized-order work in one compact overview. Products remains the product index/editor; Orders owns search, filters, selection, bulk actions and detailed recovery. If Home is only a row of links or a second Products table, it adds a stop without cross-resource value.
- **Is the hierarchy tight and aligned?** Start with one centered column. Keep each task's name, reason/status and action close together; make headings, body copy and controls share the actual Polaris content edges. Use section dividers for related rows. Check desktop and narrow phone widths (the existing gallery baseline is 1440, 390 and 320 px); preserve task/action association without horizontal dashboard scrolling. Do not compensate for native input insets with guessed margins, repeat nearby labels, or let transparent illustration padding shift the stack.
- **Does every word earn its space?** Prefer a short task/resource heading and one direct instruction/action. Supporting copy belongs only when it explains a consequence, choice or recovery. Remove greetings, taglines, internal implementation notes, repeated product names, generic “ready” claims and decorative mini storefronts that do not show this merchant's real store or outcome.
- **Is the first useful action obvious without adding a wizard?** First use should route to existing product selection; if Shopify has no products, offer the actual Shopify product-creation destination first. A saved draft should resume by product name. Storefront tasks should link to the existing setup page. Customer testing remains a separate, explicit action and acknowledgment. Do not add a second picker, forced sequence, account fields, a mandatory Methods/Billing tour or a celebratory completion panel.
- **Does order work stay truthful and actionable?** Once customized orders exist, show a bounded “Recent customized orders” summary (3–5 rows is the proposed first layout sample) and a View all orders link. A task row needs the named order, the actual reason/actor where known, and a supported direct destination. Keep ordinary recent orders distinct from tasks; a non-ready badge alone is not urgent. Do not call the summary a complete queue or claim “all caught up.”
- **Are readiness and counts evidence-based?** Keep saved draft, effective published configuration, Shopify product status, published-theme activation and customer-test acknowledgment separate. A theme check must not invalidate saved product configuration or say the shop is ready to sell. Do not invent conversions, revenue, fulfillment backlog, global totals or zeros from a partial page. Surface artwork recovery only when its reason and permitted next action are known; deferred customer artwork and retention expiry/erasure are different conditions.
- **Do states fail locally and clearly?** No configured products, no customized orders, inaccessible order data, changed/unknown theme state, an actionable issue, a failed panel and loading are distinct states. One failed summary should retain successful sections and get a local explanation/Retry; it must not replace the page or masquerade as empty/zero. Permission-limited users should not see fabricated zero orders. Initial slow loading should use the existing silent, accessible skeleton convention, matching section geometry; don't flash first-use emptiness or leave an indefinite spinner. Retry only follows an actual failure.
- **Are fixture facts visible only where useful?** Each scenario should declare the underlying facts independently (product/draft/publication/theme/test/order reason, actor permissions, and per-panel availability). Fixture labels or controls stay out of merchant-facing output. A simulated test order must not read as actual customer activity. Do not infer “recent,” “complete,” “empty,” or “actionable” from fixture order alone.

## Checklist lenses and limits

The installed Checklist Design [Dashboard](https://www.checklist.design/web-app/dashboard) lens covers recent work, truly critical attention items, useful quick actions and a useful quiet/empty Home. Its metrics item does not override Insignia's lack of a trusted analytics source; configurable widgets are not needed for this compact V1. The [Onboarding](https://www.checklist.design/web-app/onboarding) lens supports a clear first action, but Home is a returning merchant work overview, not the separate first-time walkthrough. Progress, welcome, account setup, product highlights and completion are not automatic requirements where tasks are independent or unsupported.

The [Empty State](https://www.checklist.design/web-app/empty-state) checklist calls for a plain heading and real next action, and distinguishes genuine empty, no-results and load-failure states. Its illustration item is contextual guidance, not a mandate for artwork. [Loading](https://www.checklist.design/design-system/loading) and [Skeleton](https://www.checklist.design/design-system/skeleton) are secondary prompts; project guidance requires silent route skeletons. For errors, use the [Alert](https://www.checklist.design/design-system/alert) ideas of descriptive, local copy and a relevant inline action, with Shopify's banner use kept sparse.

Shopify Polaris 2.0 App Home contracts and Shopify content/layout guidance govern component choice and merchant copy. Apply Vercel's supplementary accessibility/focus, responsive layout, semantic link and recovery checks only where compatible; this Astro/Preact app is not a React/Next migration target. A rendered comparison and interaction check are still needed before calling Home visually or behaviorally accepted.
