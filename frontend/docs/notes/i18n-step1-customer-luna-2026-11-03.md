# Selected customer modal localization inventory

3 November 2026. Source-only audit of the selected designer-prototype native Preact modal. Scope is the light/dark customizer launched from Shopify: Shopify owns the product page, cart and checkout; the local /product route is a labelled development host stand-in. The separate apps/storefront UI is not the selected design.

Customer source paths below use ../designer-prototype relative to the main insignia repository root; line numbers refer to the current inspected source.

Read the main repository AGENTS.md, the complete localization plan dated 2 November, its source inventory and edge-case review, then reread the current customer source. No application files, dependencies, catalogs, tests or Shopify settings were changed. I also inspected the current-language 320px customer baseline at .artifacts/i18n-step1-2026-11-03/customer-320.png. In that light-mode capture the artwork-choice filename shows a clipped stem with `.svg` retained. This is the current layout only, not translated-fit acceptance; no translated render was inspected.

## Newly surfaced source details

- The Shopify variant adapter synthesizes both a row name and axis label of “Selection” for a one-axis tuple with no row option (../designer-prototype/src/shopify-variant-matrix.ts:106-132). Translate that app fallback if it reaches the UI; option names and values used for other generated labels remain Shopify content. The reversible IDs remain technical.
- The German-English long-content scenario sets locale to de-DE but contains mixed merchant labels and English app controls; locale currently changes formatting/search, not UI copy (../designer-prototype/src/scenarios/long-content.json:2-10; ../designer-prototype/src/model.ts:85-89; ../designer-prototype/src/quantity-entry.tsx:46-51). This fixture is useful content stress, not proof of a German catalog or translated layout.
- AdminPreview receives actual editor draft data and produces draft-specific counts/labels. Its selected editor-preview copy belongs in admin.preview, separate from the connected Designer bundle. The same Vite document also supplies its own title and `lang="en"` on the adminPreview query route (../designer-prototype/index.html:2,28; ../designer-prototype/src/main.tsx:9; ../designer-prototype/src/preview-shell.tsx:35-37). The scenario gallery, fixtures and simulated host page remain separate development surfaces (../designer-prototype/README.md:24-28; ../designer-prototype/scripts/runtime-check.mjs:367-391).
- The 320px baseline shows clipping in the artwork-choice filename, but source provides a full filename through the FileName title and screen-reader text; that choice does not itself enable a visible disclosure. The Change action opens the artwork library, where a truncated name exposes “Full filename,” and Review has a separate disclosure (../designer-prototype/src/file-name.tsx:10-45,48-82; ../designer-prototype/src/designer.tsx:1244-1255,1755-1765; ../designer-prototype/src/review-panel.tsx:220-263). Record these distinct routes for translated-state verification; the baseline does not establish a clipping defect.
- Quantity no-results, fallback “Selection”, generic “Option”, and configured Shopify/merchant option names look alike in the rendered controls but have different ownership. Extract only app defaults and interface labels; preserve supplied labels as content.

## Content ownership rules confirmed in the customer source

- Translate app-written UI around values, not the values: config.productName, color/option names, view labels, placement names, method labels, configured sizeLabels, artwork names, image alt content, uploaded filenames and exact Shopify variant IDs are supplied content (../designer-prototype/src/config.ts:28-74, ../designer-prototype/src/designer.tsx:786,858-885,966-997, ../designer-prototype/src/review-panel.tsx:74-80,124-139,165-167).
- optionPresentation labels are configuration text when present. Only the generic fallback Option in ../designer-prototype/src/option-presentation.ts, the defensive fallback in ../designer-prototype/src/quantity-entry.tsx:232,270, and the adapter-generated fallback Selection in ../designer-prototype/src/shopify-variant-matrix.ts:106-121 are app-generated defaults.
- printSizeLabel returns a merchant label when available; otherwise it builds a dimension plus cm (../designer-prototype/src/position-geometry.ts:105-114). Localize the unit construction while retaining the configured physical dimension.
- Uploaded names, extension, file path and URL are not UI strings. Translate Full filename and descriptive copy around the name. The current full filename remains in screen-reader text even when the visible stem is clipped (../designer-prototype/src/file-name.tsx:31-43).
- Dark/light choice is persisted under a technical key and exposed with an app-owned accessible label/title; translate the label/title only, not "dark", "light", storage key, theme attributes or CSS variables (../designer-prototype/src/theme.tsx:4-7,60-91).
- UI count prose currently has English singular branches in the quantity editor, review, footer and validation summary. Search counts are currently unformatted integers. Move each to whole plural messages with required count/name/max parameters; preserve the quantity values and arithmetic as numeric domain data (../designer-prototype/src/quantity-entry.tsx:178-180,244-257; ../designer-prototype/src/review-panel.tsx:109-128; ../designer-prototype/src/designer.tsx:389-402,1576-1587; ../designer-prototype/src/color-picker.tsx:59-63).

## Risks that need translated renders or runtime checks

1. The footer combines price, validation-return and changing next/cart/pending labels inside a fixed lower region. Test expanded/pseudolocalized copy at 320, 390 and 1440 px in both themes, including long product names, larger currency strings and keyboard-visible focus. Source CSS shows constraints but does not prove overflow.
2. Check all four quantity layouts at those widths, with long translated labels, long unbroken merchant option names, zero/one/many locale plurals, unavailable saved quantities, filtered results, maximum errors and a 20-option list. Confirm quantities survive resize and Review/Edit; preserve the focused cell when search/filter rerenders.
3. Test the browser's actual locale-specific number input behavior for each advertised language: type, edit, paste, clear, invalid draft and return to Review. Current source reads validity.badInput/valueAsNumber and stores numeric state (../designer-prototype/src/quantity-entry.tsx:67-99); it has no explicit Unicode digit normalization.
4. Verify accessible names and announcements for count changes, no results, unavailable selections, errors, pending cart work, upload, Undo and expiry on the supported screen readers. Keep focus on the corresponding input after validation and confirm focus recovery when a recovery toast disappears.
5. Use mixed-script content and long filenames to check bidi punctuation, extension preservation, visible clipping, full-name disclosure and accessible naming. Do not localize filename characters, use bdi/dir="auto" where app punctuation surrounds supplied names, and inspect actual grapheme boundaries.
6. Verify the connected Shopify adapter passes storefront localization.language.iso_code and direction to the modal's owned root, leaves the parent page language/direction alone, and does not reset the design, quantities, pending operations, recovery, undo state or cart idempotency on a same-mounted locale change.
7. Keep the editor preview bridge's loading/error/count states separate from gallery/lab copy. Confirm failed or malformed preview messages produce a complete localized admin fallback, while product/config labels and diagnostic details are not presented as translation values.

No translated UI, pseudolocalized capture, native Shopify cart mutation, or owner acceptance is established by this source audit.
