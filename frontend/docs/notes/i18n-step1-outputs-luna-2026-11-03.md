# Step-one localization inventory: Orders, artwork and outputs

3 November 2026. This note is a source inventory only; it does not implement application, UI, dependency, catalog, Shopify-store or output-schema changes. It follows the [complete localization implementation plan](localization-implementation-plan-2026-11-02.md), especially its text-ownership rules, typed-message/state boundary, bounded API error mapping and generation-time output rules (plan sections 1, 4, 6, 7; [text ownership](localization-implementation-plan-2026-11-02.md#1-define-exactly-which-text-belongs-where), [state and errors](localization-implementation-plan-2026-11-02.md#4-typed-messages-state-and-safe-rendering), [generated output](localization-implementation-plan-2026-11-02.md#7-outputs-and-content-contracts)).

## Findings to carry into implementation

1. **The selected customer customizer and current theme integration are different code paths.** The plan selects the sibling designer-prototype as customer modal. The existing extension blocks load the apps/storefront compatibility/runtime bundle, whose authored launcher is apps/storefront/src/element.tsx; Vite generates the bootstrap and copies built chunks into the extension. Treat built extensions/insignia-theme/assets/*.js as generated artifacts and regenerate them from their owner, rather than mining older/minified bundle strings. Do not describe the selected prototype upload as already connected to Shopify or the web guest API. ([plan](localization-implementation-plan-2026-11-02.md#research-and-current-facts), [Liquid launcher](../../../extensions/insignia-theme/blocks/customize.liquid#L1), [authored element](../../../apps/storefront/src/element.tsx#L39), [build entry](../../../apps/storefront/vite.config.ts#L19), [asset copy](../../../apps/storefront/scripts/copy-theme-asset.mts#L20); mechanical coverage: [files.csv](../../../.artifacts/i18n-step1-2026-11-03/files.csv))

2. **The plan’s “standalone artwork upload” label covers existing embedded components; there is no separate guest page in this repo.** Seller upload is embedded in order and product-editor flows; the guest component is used inside the current buyer customizer and is also exposed from an authored custom element. The web route tree has guest artwork API routes but no separate guest upload page. The selected prototype has its own upload UI but its checked-in demo adapter is local-only. Inventory the two current upload audiences and selected modal seam separately; do not infer a new standalone page or upload feature. ([guest component](../../../apps/web/src/islands/GuestArtworkUpload.tsx#L35), [current customizer use](../../../apps/storefront/src/customizer.tsx#L926), [API route](../../../apps/web/src/pages/api/artwork/guest/index.ts#L1), [selected prototype upload UI](../../../../designer-prototype/src/designer.tsx#L1701), [local-only adapter](../../../../designer-prototype/src/demo/local-runtime.ts#L4))

3. **Upload and export reducers keep display strings.** Admin artwork upload state stores a message and receives English progress/error strings; prepared-export state stores message and progress; purchase attachment and buyer recovery state similarly carry messages. This is the plan’s render-time mapping boundary, not just a catalog-extraction task. When localizing, change the render-time text mapping only; do not change operation, request, asset, selection or accepted-record facts. ([upload state](../../../apps/web/src/islands/artwork-upload-state.ts#L7), [upload adapter](../../../apps/web/src/islands/use-artwork-upload.ts#L118), [prepared export state](../../../apps/web/src/shared/prepared-export-state.ts#L2), [purchase attachment state](../../../apps/web/src/islands/purchase-attachment-state.ts#L7), [buyer recovery state](../../../apps/storefront/src/buyer-state.ts#L29), [plan](localization-implementation-plan-2026-11-02.md#4-typed-messages-state-and-safe-rendering))

4. **There is a concrete server-message exposure in authenticated upload.** admin-request turns a failed JSON response’s message/error into Error.message; use-artwork-upload.failure stores any Error.message in visible state. Most owned artwork API responses currently use English text and do not return a separate semantic error code. Localize bounded known conditions from status/reason codes and use reviewed generic copy for unknown prose; do not put arbitrary server messages in a catalog. This note records a boundary for later implementation, not authorization to change the API. ([admin response parser](../../../apps/web/src/shared/admin-request.ts#L39), [upload failure mapping](../../../apps/web/src/islands/use-artwork-upload.ts#L118), [artwork HTTP response](../../../apps/web/src/server/artwork/http.ts#L90), [plan](localization-implementation-plan-2026-11-02.md#4-typed-messages-state-and-safe-rendering))

5. **PDF and ZIP human text currently has no captured locale.** The production-sheet renderer, batch progress and archive builder construct English copy directly. The PDF is a rasterized canvas page embedded into A4; it is not a vector-text PDF. Canvas line behavior is materially different from DOM wrapping and deserves its own output acceptance checks. Source establishes implementation mechanics; it does not establish whether a future translation clips. ([renderer](../../../apps/web/src/shared/production-sheet-render.ts#L33), [PDF construction](../../../apps/web/src/shared/production-sheet-render.ts#L720), [archive builder](../../../apps/web/src/shared/artwork-archive.ts#L212), [plan](localization-implementation-plan-2026-11-02.md#7-outputs-and-content-contracts))

## Namespace refinement relative to the mechanical file inventory

The final machine coverage CSV assigns ArtworkUpload.tsx to artwork:merchant-context and GuestArtworkUpload.tsx to artwork:guest-context, while the selected prototype is customer. These are message-ownership labels rather than finalized resource filenames. Preserve **audience and recovery semantics** in the implementation: authenticated merchant upload, existing guest embed, selected customer modal, production-sheet output and archive output each have their own context. Share an artwork message only if its wording and state contract actually agree. Keep product CSV UI in products; do not make the CSV cells part of an export catalog. Theme schema and storefront locale files are Shopify-managed resources, not a third copy of the customer catalog. ([final inventory](i18n-inventory-2026-11-03/files.csv), [plan namespaces](localization-implementation-plan-2026-11-02.md#3-one-package-two-frontend-build-arrangements))
