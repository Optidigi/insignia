# Customer wording and defaults review

4 November 2026. Independent source and rendered review of the current working tree. No application code changed during this review.

Current verdict: no outstanding material findings in the reviewed change. A merchant can change one or two phrases, find their customized text, restore one field, or restore all wording for the selected language. Empty fields clearly use the English defaults. The implementation does not imply that adding a language supplies a complete translation.

Sources were the repository's admin UI guidance and UI delivery workflow, the [translation reference research](translation-settings-reference-research-2026-11-04.md), the actual editor/workflow/state source, and the browser regression assertions. Shopify's public [Clickable contract](https://shopify.dev/docs/api/app-home/v2.0/web-components/actions/clickable) was checked against the selected `polaris-2.0-rc.js` runtime and `@shopify/polaris-types` 2.0.0-rc.3. The retained [Translate & Adapt resource hub](../../../../.artifacts/home-research-2026-10-26/translate-adapt-resource-hub.png) was inspected directly. It supports the grouped-resource and language-context composition; it does not establish editor or reset behavior. The lead agent's fresh native observation found that clearing an unsaved adaptation disables Save, and found no row reset control. The explicit restore controls here are an Insignia interaction decision, not a claim of native pixel identity.

Two source findings were corrected. Query results now remain pinned during phrase editing, preventing a row from disappearing when its custom wording was the search match. The active section uses a localized accessibility label because an isolated test of the pinned runtime showed that host `aria-current` was not forwarded to the internal button. Individual restore returns focus through the shared, bounded textarea compatibility helper. It calls standard native focus without changing shadow DOM values, attributes or styles.

The final images inspected were Customized text at 1440, 390 and 320 px; individual-restored desktop; restore confirmation at 320 px; restored-defaults desktop and 320 px; and layout probes at 761, 901 and 1200 px. They are in the [translation capture directory](../../../../.artifacts/admin-popup-review-2026-10-24/translations/). Comparison columns remain aligned, narrow layouts retain whole controls, restore actions remain reachable, and the empty state offers an All text recovery. The corrected individual-restored image now shows disabled Save with the saved announcement. The earlier transient host-button capture issue is resolved.

The lead agent reports the final full gallery regression passed in 10.3 seconds, including native textarea focus assertions, stable custom-wording search during edits, individual restore/discard/save/reload, bulk restore cancel/confirm/save/reload, authoring-language navigation, and target-width/overflow assertions at the requested breakpoints. This reviewer inspected the corresponding assertions and final images; this was not a separate rerun.

This verdict covers local implementation and simulated browser behavior. Overrides remain sparse, exact-locale browser storage, with English as the only shipped catalog. No automatic translation, new backend persistence, deployment, native embedded-app acceptance or owner release approval is established. The focus helper depends on the pinned runtime's open shadow roots; its public host fallback does not guarantee equivalent focus behavior if those internals change.
