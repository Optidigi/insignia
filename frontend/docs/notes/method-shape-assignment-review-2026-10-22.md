# Reusable method assignment review

Workflow research, 22 October 2026. This is a product-shape recommendation based on public Shopify and vendor documentation. It is not a claim of native Shopify admin observation or app behavior.

## Recommendation

Start with one assignment mode: choose exact Shopify **products** from the Shopify Resource Picker and apply a method as an explicit batch action. Do not add a tag rule editor, general condition builder, and collection selector together. If merchants later need a changing target group, add Shopify collection selection as one dynamic mode and let Shopify own its membership rules; do not recreate Shopify's rule builder inside Insignia.

Shopify's current collection documentation describes a new model that is replacing legacy manual and smart collections. Collections can combine manually or automatically included products, variants, other collections, and app sources, with exclusions and deduplication. Conditions can match all or any rules; manually included products remain until explicitly removed. This is a capable grouping system, but importing its full semantics into method assignment would require resolving mixed sources, variant-only membership, exclusions, and membership changes. [Shopify: Creating collections and adding products](https://help.shopify.com/en/manual/products/collections/create-collection), [Shopify: Understanding collection conditions](https://help.shopify.com/en/manual/products/collections/conditions)

The App Home Resource Picker already supports multi-product selection, preselected items for editing, product/variant/collection resource types, and filters for draft, archived, and hidden products. Use the product resource type, hide variant-level selection, and preserve Shopify product IDs as the selected targets. Let merchants prepare draft products; exclude archived products by default or show them with a clear status and explicit include control. Do not use storefront publication or missing imagery as silent assignment filters. [Shopify: Resource Picker API](https://shopify.dev/docs/api/app-home/latest/apis/user-interface-and-interactions/resource-picker-api)

## Method and product responsibilities

Keep reusable method data limited to values that genuinely apply across products. For the current MVP, that means the method name and optional short customer explanation. That is reusable descriptive data, not behavior-changing process configuration. If merchants need a method to change what buyers can submit or what production receives, add only a concrete constraint with end-to-end support; the domain spec already names allowed artwork constraints, but the current library/product/buyer path does not expose or enforce them. Do not present an unenforced setting as operational configuration. Placements, garment-specific geometry, decoration sizes, variant fit, and final method × location × size prices remain on the product. Missing final prices mean unavailable. The MVP proposal defers physical size presets and automatic fit because product areas and garment variants change the usable space. [Method MVP proposal](decoration-method-workflow-proposal-2026-10-21.md), [MVP source check](decoration-method-mvp-source-check-2026-10-21.md), [implementation plan: product and price model](../../architecture/implementation-plan.md#31-configuration-and-publication)

Assignment should copy a method into each product's editable draft, with an origin method ID/version kept only to recognize the same source on a later apply. The copy is independent: editing or removing the library entry affects future assignments only. Do not infer origin from matching names, silently merge same-name methods, or update existing product drafts/publications in the background. A future “apply updated defaults” action would need its own before/after preview and explicit scope. This follows the existing contract that published revisions snapshot resolved values and that editing a library entry does not change them indirectly.

## Preview, readiness, and collisions

Show two separate concepts before applying a batch:

- **Matched** is the exact product set selected by the current source. In the first release, that is the manually selected set. The preview should say how many products will receive a local method copy and identify already-applied copies and name collisions.
- **Product setup** reports each product's actual state: no Insignia configuration, draft needs setup, draft passes publication checks, or currently published. A matched product is not thereby ready or customer-visible. A product with no placement, missing valid price tuples, or another publication error can still be assigned into a draft, but it must be marked as needing setup with a direct recovery path. Do not label missing configuration “excluded.”

Allow multiple methods on a product because the product model permits multiple method choices across placements. Assignment is additive and has no precedence: applying another method must not replace existing methods or product settings. Make repeat application idempotent for a known source method. When a product already has an unlinked same-name method, warn and let the merchant skip or deliberately add/rename; name equality is not identity. Keep assignment product-level: a method applies across the configured product variants because current Insignia eligibility is not variant-specific.

An exact product selection needs no separate exclusion rule; merchants remove items from the selected list before applying. If collection mode is added later, preview the resolved deduplicated product list, show products excluded by the collection, and disclose that it is a live set whose membership can change. New matches may be offered for draft setup, but a product leaving the collection must never silently lose its copied method or have its configuration unpublished. Collection membership sourced only from variants must be rejected or explicitly treated as whole-product assignment; it cannot imply variant-specific Insignia eligibility. Avoid tag conditions in Insignia: tags are merchant-editable labels that Shopify allows staff and workflows to add or remove, so changing a tag can change a rule's target set. [Shopify: Creating and using tags](https://help.shopify.com/en/manual/shopify-admin/productivity-tools/using-tags)

## Draft and publication effects

Applying a method creates or updates only product drafts. It does not publish the product configuration or make the Shopify product customizable. A newly matched product with no Insignia config may receive a new draft with the method copy and a “Set up placements and prices” next step. Existing product drafts keep their own method values. Publishing remains a separate per-product action after the product configuration passes its existing publication checks; published revisions and orders remain immutable snapshots.

## Competitor patterns

The documented vendors support the split between reusable methods and product-level assignment. DecoNetwork has central decoration processes with both manual product assignment and per-process Smart Select rules; enabling a process does not update existing products, and disabling it previews affected products. InkSoft's product Decoration tab activates account-enabled methods on each specific product and then handles product-specific price grids and regions. Zakeke allows a reusable printing method to apply across products, variants, or a side, but that scope depends on behavior it implements in the method itself. These are precedents for reusable definitions and scoped assignment, not requirements to copy their production-rule depth. [DecoNetwork: Decoration Processes](https://help.deconetwork.com/hc/en-us/articles/234946427-Decoration-Processes-Overview), [DecoNetwork: Smart Select Rules](https://help.deconetwork.com/hc/en-us/articles/235205227-Smart-Select-Rules-All-Decoration-Processes), [InkSoft: Product Decoration](https://help.inksoft.com/hc/en-us/articles/46724037237787-Edit-Products-Decoration-Blank-Products), [Zakeke: Printing Methods](https://zakeke.zendesk.com/hc/en-us/articles/360016836099-Printing-Methods)
