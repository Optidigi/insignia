# Interface language pickers — 5 November 2026

Settings now contains an **App language** preference, separate from the storefront wording editor. The selected customer modal has a compact language picker beside theme and close controls. Both offer English, Nederlands, Deutsch, Français, Español and Italiano. The admin defaults to the supplied Shopify staff locale; the customer defaults to the supplied storefront locale. Automatic resets the full original host tag, including region. These controls change Insignia, not Shopify accounts, published store languages, product content, markets or currency values.

The [Checklist Design audit](../../../.artifacts/language-picker-2026-11-05/checklist-audit.md) records applicable dropdown and Settings criteria rather than inventing menu features. ## State and implementation

Admin uses its existing per-document locale controller across independently mounted Preact islands. A successful preference is retained in document memory and optionally in `insignia.admin.language.v1`. Navigation carries the original host locale, preventing an override from becoming the new automatic default. Persisted history returns refresh a durable choice; blocked writes retain the mounted session’s preference. Failed preparation keeps the previous complete snapshot and shows the native field error. The Settings skeleton matches the additional preference section.

Customer uses the selected sibling `designer-prototype`, not the older `apps/storefront` integration UI. It preserves the same controller and designer session; selecting a language dispatches no commerce events. Artwork, quantities, step, uploads, pending cart identity and retry identity remain in their existing reducers. Exact-locale merchant wording remains scoped to that locale. `insignia.customer.language.v1` is optional browser storage, with mounted-state fallback. The modal subtree’s `lang` updates while the Shopify document stays unchanged. The reduced merchant artwork-only preview intentionally omits this buyer control.

Only complete shipped languages are advertised; malformed saved values fall back to the host. App-language defaults do not publish Shopify languages or translate supplied product/variant/placement names. The picker’s 11 new English message/field-label keys have complete Dutch, German, French, Spanish and Italian counterparts; the translation-review pass covers 66 strings. German retains the existing formal `Sie` convention.

## Correction passes and evidence

A final native-field interaction check found that temporarily disabling the admin select lost keyboard focus. A red regression reproduced it; the correction restores focus through Polaris’s public method after activation only when the document has no newer focused control. The regression also confirms that focus moved to another link is not taken back. Independent Sol rechecked the correction and all 4 preference tests passed.

Independent review reproduced an admin storage edge: after a session-only successful choice, a later preparation failure incorrectly reset the select to automatic. The document preference cache, persistence-status distinction, BFCache refresh and tests now preserve the actual active choice. Testing the pinned Polaris runtime also found that an empty option value becomes its label; the admin’s automatic option therefore uses the explicit token `automatic`. The buyer’s native HTML select retains the normal empty reset value.

Root’s 800/1024px render caught a later CSS override reserving 96px for a 227px utility group, overlapping the third step. Both constrained grids now reserve automatic utility space and show the compact 44px language control through 1100px. The proven 460px step track remains; actual text bounds are tested in all six languages and both themes.
