# Storefront setup: independent Checklist Design review

26 October 2026. This review covers the final local captures after the illustrative SVG examples were removed, alongside `StorefrontSetup.tsx`, `StorefrontProductTest.tsx`, and the composition CSS. It is a setup guide inside Settings, not a full first-run onboarding wizard: the theme tasks are independent, and product setup is needed only for the final customer-flow test. I use Web app Onboarding as a partial lens, not as a demand to add wizard steps.

## Checklist Design audit

Auditing against [Onboarding — Web app](https://www.checklist.design/web-app/onboarding). The checklist describes an experience that introduces new users to a product and gets them to first value. This page serves existing merchants returning to manage theme setup, so several onboarding items are deliberately not needed.

| | Item | Why |
|---|---|---|
| ⚪ | **Progress indicator** — An indication of how many steps are involved and where the user currently is in the sequence. *Tip: Every step beyond five is another opportunity to lose the user — 3 to 5 is the reliable range.* | The customization block and cart embed can be set up in either order; a numbered sequence or completion percentage would falsely make one depend on the other. |
| ⚪ | **Welcome message** — A brief message acknowledging this is a new experience and orienting the user toward what the product does. | This is a revisitable Settings page, not a new-user introduction; “Storefront setup” and “Save theme changes in Shopify” give enough context without a greeting. |
| ⚪ | **Account setup** — The minimum information needed to personalise the experience, gathered at the start. *Tip: Delay any fields not genuinely needed to start using the product.* | The merchant is already in the installed app, and no profile or account fields are needed to configure the theme. |
| ⚪ | **Product highlights** — Key features introduced through short contextual tips or a visual walkthrough. *Tip: Offer a skip route for user who has seen content before or prefers to learn by doing.* | A feature walkthrough is not needed for this task guide: the two real theme actions explain what to configure, and the customer test leads to the actual buyer flow. The removed generic mini storefronts did not show a real store or teach an extra step. |
| 🟢 | **First action prompt** — A clear prompt directing the user to an action or feature. | In the not-added state, each theme task places its next action beside the instruction: “Add to theme” and “Enable in Shopify”; the final test offers “Choose a product.” In the published-product state, “Preview in theme editor” leads into the test steps. |
| ⚪ | **Completion confirmation** — A clear acknowledgement that setup is complete, transitioning the user into the main product. | A theme status only describes the published theme; it does not confirm the customer journey. Keeping the product test visible and unmarked until the merchant tries it avoids a false “all set” state. |

## Render observations

Reviewed the fresh [1440 px not-added](../../../../.artifacts/admin-popup-review-2026-10-24/storefront/desktop/settings-storefront-not-added.png), [390 px not-added](../../../../.artifacts/admin-popup-review-2026-10-24/storefront/mobile/settings-storefront-not-added.png), and [320 px not-added](../../../../.artifacts/admin-popup-review-2026-10-24/storefront/narrow/settings-storefront-not-added.png) captures, plus the [1440 px](../../../../.artifacts/admin-popup-review-2026-10-24/storefront/desktop/settings-storefront-test-published.png), [390 px](../../../../.artifacts/admin-popup-review-2026-10-24/storefront/mobile/settings-storefront-test-published.png), and [320 px](../../../../.artifacts/admin-popup-review-2026-10-24/storefront/narrow/settings-storefront-test-published.png) published-product test states. I also checked the [expanded compatibility help at 320 px](../../../../.artifacts/admin-popup-review-2026-10-24/storefront/narrow/settings-storefront-guidance.png) and the [mobile status-check error](../../../../.artifacts/admin-popup-review-2026-10-24/storefront/mobile/settings-storefront-error.png).

- **Space and hierarchy:** The desktop view is a single centered content column: “Published theme” groups the two independent rows in one card, then “Test the customer flow” starts a separate card below. Within each task, the title/status, plain instruction, and one relevant action read together; a divider separates the tasks. At 390 and 320 px, the action moves below its own copy, and long instructions wrap without horizontal clipping. The final product test remains distinct and reachable below the theme work.
- **Imagery:** The current captures have no decorative product or cart drawings. That is the right call here. Before removal, the generic shirt-and-button miniatures occupied a full desktop task column and the top of each mobile task, while repeating labels already present in text. They resembled interface screenshots but did not show a merchant’s theme or an actual customer outcome. The real editor handoff and product test provide better evidence. Shopify describes its Media card as visual information alongside actionable educational content; these miniatures did not add either. [Shopify layout guidance](https://shopify.dev/docs/apps/design/layout) also describes single-column layouts as supporting top-to-bottom scanning and one obvious task, which fits this page better than a decorative two-column presentation.
- **Help and recovery:** The primary instructions stay inline. “Other themes and compatibility” keeps product-template, unpublished-theme, and compatibility details available without crowding the default state; the expanded 320 px capture keeps the customer test visible below it. The status-check error shows one contextual “Retry” and the theme-editor actions remain available. This matches Shopify’s guidance to keep content scannable, use plain language, and place clear actions beside relevant information. [Shopify content guidance](https://shopify.dev/docs/apps/design/content)
- **Focus:** Still captures cannot confirm keyboard focus appearance or focus recovery. The reviewed 320 px layouts show no horizontal clipping that would cut off a ring, but that is not proof of keyboard behavior; the separate interaction check is the evidence for that.

## Verdict

The revised composition is clearer at desktop and narrow widths. The removed illustrations were not useful onboarding highlights; keeping the real theme tasks and customer test in a single-column flow is better matched to the page’s job. No visual correction remains from this Checklist Design pass. Static captures alone do not establish native Shopify rendering or keyboard behavior.
