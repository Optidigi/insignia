# Experimental callback lifecycle controls

These local controls are offline preparation for one private APP_UNINSTALLED experiment. They grant no deployment, provider mutation, production generation, uninstall or privacy authority. This startup correction uses accepted PR72 main 2f7aa2bfb304a80ac08a2965ed20c63e4c85fe8e. It binds startup to the authenticated immutable experiment identity without changing historical mapping bytes, accepted manual recovery/erase APIs, provider verification or generation semantics. Earlier source and failed-control snapshots remain preserved privately. Fresh source review and natural CI remain pending; host qualification and M5/G7 PASS are not claimed.

## Fixed startup and owned-process control

`startSupervisor({directory, signingFd, port=0, deadlineMs=10000, expectedIdentity?})` starts only the adjacent fixed service through current `process.execPath`. The exact Node 24.21.0 binary and receiver runtime/verifier SHA pins are checked in an owned metadata child. The caller cannot select an executable, module or generation. The private experiment must be absolute and canonical, its parent private 0700 and its basename equal the authenticated immutable mapping's experiment. Only original authenticated acceptance/erasure deadlines appear on metadata stdout. An authenticated immutable-mapping identity is carried over a bounded private inherited pipe; it never appears in argv or public output. Elapsed acceptance refuses startup.

Every supervisor serving child starts in fixed `--bound` mode. The supervisor forwards the inspected identity through inherited FD4, which is separate from signing FD3. The service requires exactly 64 lowercase hexadecimal identity bytes and a newline followed by EOF, with a 66-byte read limit. Missing, malformed, oversized or mismatched identity refuses; bound startup never falls back to legacy mode. `openBoundReceiver({directory, clientSecrets, expectedIdentity, ...})` validates the identity format and compares SHA-256 of authenticated immutable mapping AAD while holding the existing lifecycle guard, before acquiring receiver ownership or listening. A same-name replacement between inspection and signing EOF is preserved and refused. Identity is never placed in argv, environment, READY/status output or receipts.

A separately trusted caller may supply `expectedIdentity` to require the inspection itself to match a previously frozen mapping. The caller expectation and presence of its field are captured before asynchronous inspection; later caller-object mutation cannot remove the requirement. An explicit invalid or undefined field refuses. Omitting that additional caller constraint still binds the child to the supervisor's own inspected identity. Accepted direct `openReceiver` calls without an identity field and direct service invocations without `--bound` retain their legacy local semantics. An explicit `expectedIdentity` field on `openReceiver` always selects strict bound startup. Legacy calls provide no intended-identity guarantee; host mapping qualification must use a separately trusted expectation.

An already-open trusted signing descriptor is inherited directly as child FD3. Supervisor code checks descriptor metadata, never reads or persists signing bytes, and supplies a minimal literal child environment. The READY deadline starts before metadata qualification and is at most 10 seconds. Owned child isolation bounds metadata reads or FD3/FD4 writers that never end; subsequent termination has a separate maximum five-second confirmation budget. No automatic restart, capability change or expiry restamp exists.

Success exposes only READY/observed port plus private operator `stop()` and fixed-result `done` interfaces. Stop sends TERM then KILL to the process group this supervisor created and waits for child exit and group absence; uncertainty remains STOP_UNCONFIRMED. Original acceptance expiry triggers the same stop. TERM/INT handling is installed during standalone startup. Fixed stdout grammar, a 128-byte actual-byte bound and empty stderr are required; duplicate/extra fields, EOF before READY, malformed port, further output and reflected child errors refuse. `observeReadyProtocol` is only a real-stream test seam and never chooses or signals an executable.

## One-experiment deadline erasure

`eraseAtDeadline({parent, experiment, supervisor?, exports=[], deadlineMs=10000})` is a one-shot local operator control. It authenticates the same original mapping in bounded child work, refuses an early deadline and permits only one exact canonical owner-private experiment. Unknown parent siblings, untracked local exports, symlinks, hard-linked files, unknown entries and oversized/nonprivate files refuse. An optional supervisor handle can stop only its matching owned experiment; caller objects cannot choose a PID or module. Runtime CLI arguments contain only the trusted parent and fixed experiment label.

The fixed eraser child independently checks actual `Date.now()` against original `eraseBy`; the test clock seam cannot force early runtime erasure. An expired experiment with a receiver lock uses the accepted `recoverDeadReceiver` API, which refuses live, ambiguous or reused/live unrelated PIDs. It never sends an unowned process a terminating signal. The deadline path uses `eraseExpiredExperiment` under the existing lifecycle guard. It reauthenticates and compares the original inspected immutable identity, checks actual time, validates the exact tree, recovers a dead receiver lock when safe, removes the experiment and fsyncs the parent while holding that same guard. A same-name replacement is refused and preserved. Spool permits only `.bin`; reservations and commits permit only `.json`. Accepted manual `recoverDeadReceiver` and `eraseExperiment` APIs retain their original semantics. A crash inside a critical section leaves the guard outside the experiment and returns BLOCKED: no stale guard is automatically removed. BLOCKED needs explicit manual diagnosis of the owner's process group; UNCERTAIN never means completed erasure. Only local removal can return LOCAL_FILES_REMOVED_EXTERNAL_COPIES_UNQUALIFIED.

The one-shot executable supports invocation after a missed deadline or reboot without restamping time. A persistent timer, reboot ordering, ingress shutdown and host supervisor are still required; no daemon or host unit is implemented here. Zero untracked exports/copies is an operator prerequisite. The local tree check cannot discover outside copies or prove that copied purpose keys, plaintext exports, logs, backups, device remnants or restore tombstones are gone.

```sh

```

The supervisor controls use real inherited FD3, local HTTP/socket listeners, FIFO EOF/metadata stalls, real synthetic child streams, standalone TERM during startup, original acceptance expiry and confirmed refusal after shutdown. The erasure controls cover original deadlines with an independent runtime-clock check, private path/export refusal, fresh-process catch-up, blocked metadata, an unfinished-body durable reservation surviving a serving-child crash, active/live unrelated PID refusal and a real critical-section SIGKILL leaving an untouched stale guard. Corrected artifact qualification, formatting and final combined results are recorded separately by the integrating parent; source acceptance requires fresh independent reviews and natural CI.

## R1 rejection and R2 regressions

Both completed R1 reviews rejected the first candidate despite ten successful attempt1 workflows. Real public worker/operator controls reproduce concurrent erase/recreate deletion and wrong-directory suffix removal, then pass on R2 while preserving the replacement/unexpected files. Explicit process-boundary doubles cover failed inspection and completed erasure with unconfirmed group shutdown; they do not claim an actual unkillable OS process. Inspection/startup retain STOP_UNCONFIRMED, deadline erasure retains UNCERTAIN, and valid child output never substitutes for confirmed owned-group cleanup. Historical R1 source, reports and failures are unchanged.

## Exact remaining limits

Unmanaged SIGKILL of the supervisor cannot execute JavaScript cleanup. A detached service blocked before FD3 EOF can outlive that killed supervisor. Future host control must terminate the whole cgroup and perform catch-up before ingress. Kernel stalls, PID/group reuse, escaped/native descendants, host clock rollback and trusted FD3/FD4 provider/supervisor behavior need actual host qualification. The fixed existing service allocates 4097 bytes, reads at most that amount and refuses input above 4096 bytes. A synchronous read still needs trusted EOF; the startup timer bounds a stalled reader, while actual host resource limits remain unqualified. The earlier provisional contract misstated this buffer bound; its snapshot remains historical evidence. These local process observations do not prove OS isolation, a production ten-second host READY guarantee or privacy lifetime enforcement.

Host allocation, persistent timers/systemd, OS confinement, privileges, TLS/Traefik routing, confidential host logs, external erasure/export accounting and key backup policy remain unimplemented/unqualified. There are no tenant/bootstrap/database/queue/provider requests or new credential stores. CURRENT_CAPABILITY_COMPROMISE, unsigned metadata, native signed-Shop semantics, registration gaps, genuine uninstall authority, Admin revocation, delayed privacy obligations and all other configuration/legacy effects remain unresolved under the existing contracts.
