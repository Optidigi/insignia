# Experimental local TLS edge

This three-file candidate terminates synthetic TLS locally and relays one request to the accepted experimental receiver. It is preparation for a possible dedicated TLS destination behind shared Traefik TCP passthrough. Deployment, resource allocation, real callback feasibility, production authority and M5 privacy remain **NOT_RUN / UNQUALIFIED**. The original private qualification at PR70 main `b2a874089482ec6f98938385da65453bd3b85d11` is preserved. The current base is accepted PR71 main `b0949587efbcf9cdd6b2cef0b7700d6f85c32dd3`; this candidate's independent reviews and exact-head CI remain pending.

## Interfaces and bounds

`openTlsEdge({ publicHost, key, cert, upstreamPort, port = 0 })` accepts trusted operator Buffers and ports only. The option set is closed. It checks the certificate's current validity and exact DNS SAN, rejects wildcards and CN-only matches, requires exact SNI and a single exact Host header, and listens on `127.0.0.1`. Test ports may be dynamic. The upstream hostname is always literal loopback; a caller cannot supply another address or executable.

The CLI uses pinned Node 24.21.0 and takes only the public hostname in argv. The already-open inherited FD3 carries the TLS private key and FD4 the certificate: neither comes from env, a credential store or a private filename argument. Each reader allocates exactly 65,537 bytes and rejects empty or over-65,536-byte input. Reads still wait synchronously for EOF. Both FD stalls were exercised in fresh processes, emitted nothing and were killed/reaped by their test owner. An external ten-second READY bound and owned cgroup termination are required before host use; they are not implemented by this edge. CLI ports are fixed: receiver `127.0.0.1:43127`, TLS edge `127.0.0.1:43129`.

The only normal CLI output is `{"status":"READY","port":43129}` followed by a newline. Startup refusal emits `{"status":"REFUSED"}` and exits 20. stderr is suppressed. The process denies ordinary fetch, HTTP, TLS/socket, DNS and child-process escape APIs after reading the inherited material; the privately saved relay factories remain bound to loopback. This source guard is not OS confinement and does not cover every engine/native escape path.

Inbound limits are 64 KiB body, 16 KiB headers, 40 header pairs, four connections, one request attempt per actual TLS connection, one second for a started body and five seconds from connection acceptance through complete headers, including slow continuing input. A second pipelined request destroys that connection before its body/upstream admission; an already admitted first request can consequently lose its ACK. Only POST origin-form targets are eligible. Absolute URLs, network-path targets and fragment/whitespace targets refuse; there is no URL normalization, redirect, alternate destination or retry. The exact parsed raw target and body bytes go to loopback. Observed `x-shopify-*` header values and duplicates are retained; this does not claim preservation of HTTP wire whitespace or of non-Shopify headers.

Each upstream attempt has a 1.5-second total deadline and a 32-byte response bound. Only HTTP 200 with the exact bytes `RECEIVED` permits a success ACK. Accepted receiver 400/404/503 stay negative; all other responses, redirects, errors and timeouts become fixed 502 `REFUSED`. No upstream headers or bodies are reflected. The accepted receiver supplies the durable encrypted reservation/receipt boundary before its 200; the edge does not create a separate persistence layer.

`close()` stops admission, destroys owned inbound and upstream sockets, awaits server closure and in-flight handlers, and wipes its own copied key Buffer. SIGTERM/SIGINT after READY await this close. Real controls close unfinished headers and an admitted backend connection within their local bounds. This is healthy-runtime evidence, not a hard bound under an event-loop stall, kernel hang or unmanaged SIGKILL. TLS engine copies, JS body/header copies and opaque secure-context memory are not proven zeroized. No raw target, headers, HMAC, body or reflected error is written by the edge to logs or files.

## What local controls prove

Tests use real Node HTTPS/TLS/HTTP, fresh private temporary directories, ephemeral OpenSSL-generated synthetic certificates, the unchanged accepted receiver and its public private-operator extraction boundary. They cover exact body/HMAC/topic/domain reconstruction, durable success, negative HMAC/body/topic, immutable OLD labels, raw target/query behavior, duplicate Host/HMAC, ingress limits, backend redirect/timeout/refusal, connection ceilings, close/client abort, fresh CLI fixed output and inherited-FD bounds/EOF stalls. Synthetic TLS files are removed by their test owner. No actual signing material or confidential callback path is published or hashed as an artifact.

The private evidence retains RED before GREEN and harness mistakes. Corrections include exact certificate identity, origin-form filtering, redirect suppression, body/header/connection bounds, deadlines, close, closed options, CLI startup, exact ACK bytes and duplicate Host refusal. A later real TLS control found two simultaneous backend requests on one connection while the first ACK was withheld; the original frozen source failed before the per-connection admission guard was added. Early teardown lost a mistakenly opened listener; an invalid unsigned-domain fixture wrongly expected verifier success; reset-only/431-only expectations were too narrow. The initial guarded relay used a socket factory ignored by `agent:false`, causing a constructor failure and hung test harness; a private owned HTTP agent repaired it. Guard-disabled and fixed nonsecret phase probes are diagnosis only, not passing qualification. Owned hung test processes were terminated; failures and original snapshots remain private. The ACK-byte title was narrowed to match its actual assertion.

## Remaining authority and host gaps

The edge never receives the application signing secret, chooses a generation or calls a provider/dispatcher. Header topic/domain/time/IDs remain unsigned observations. Accepted `app/uninstalled` eligibility and separately qualified signed Shop identity stay receiver responsibilities. An unchanged old capability retains OLD immutable binding even with forged metadata; possession of the current capability plus an old same-shop signed body remains **CURRENT_CAPABILITY_COMPROMISE**. Identical-body later arrivals are not deduplicated away. This endpoint is not a compliance handler, and it does not resolve preauthorization, missing/removed callbacks, revoked Admin access, retention copies or tombstone completeness.

The [Traefik source research](../../docs/delivery/notes/m5-callback-edge-v3-6-20261010.md) identifies pre-router and ERROR-level URI exposure outside HTTP-router observability switches. TCP passthrough is conditional on unique SNI with no specific HTTPS collision and a DNS-only chain with no terminating CDN. Missing/wrong SNI and configuration drift can reach another handler. Research and this local TLS relay do not prove live routing or confidential host sinks.

The library's host-loopback listener is not a Docker bridge destination proof. Bind interface/reachability, exact watched route, certificate issuance/trust/renewal, DNS/Cloudflare, OS UID/permissions, cgroup/FD supervision, core/journal/log sinks, host timers, backup keys, external exports/copies and erasure remain unqualified. No deployment units, route writes, actual callback URI, subscription, production configuration or resource mutation are included. Parent integration must qualify accepted dependency changes, obtain independent reviews and exact-head CI, then prepare any separate owner resource request.
