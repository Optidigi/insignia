# Private callback feasibility receiver — experimental, offline qualified

This standalone receiver records experimental `APP_UNINSTALLED` evidence only. Production deactivation, tenant/bootstrap, database, queue, provider calls and general compliance handling are absent. It preserves existing production code, authority failures and registration/privacy gaps. HTTP loopback controls are local evidence; actual HTTPS delivery, host/TLS/Traefik/logging, native destination preservation and privacy completion are **NOT_RUN / UNQUALIFIED**. Deployment and installation/subscription mutation need separate exact owner allocation, frozen independent CLEAR/CLEAR review and CI.

## Public interfaces agreed for local qualification

Run `node --test scripts/m5-callback-qualification/receiver.test.mjs scripts/m5-callback-qualification/supervisor.test.mjs scripts/m5-callback-qualification/cleanup.test.mjs` using pinned Node24.21.0:24 receiver and15 lifecycle controls. Tests use real loopback HTTP, actual durable files, private operator interfaces, killed/restarted child processes, synthetic signing material and an external fake clock. No SDK/runtime or mocked internal storage/HMAC collaborator is used. The receiver imports `packages/shopify/src/webhook.ts` directly and leaves it unchanged.

`createExperiment({directory,binding,acceptUntil,eraseBy,...})` exclusively creates one private directory. Its parent must already be0700, owned by the current UID and canonical without symlink ancestors. Binding is the immutable experiment/era/app/provider Shop ID/domain/AppInstallation and a fixed label, such as B_PRIMARY. It generates32 random capability bytes and a distinct32-byte AES-GCM purpose key. The private600 mapping is authenticated with that key; editing an old binding fails instead of rebinding it. Signing credentials are never stored here. Defaults:45 arrivals,64KiB body,1000ms body deadline. HTTP parsing explicitly bounds headers at16KiB. Mapping/lock reads are at most64KiB, purpose-key reads32 bytes, mapping-seal reads28 bytes and commit-marker reads32 bytes. A spool read separately allows ceil(bodyBytes/3)×4 base64 expansion,128KiB for bounded header/JSON metadata and28 bytes AES-GCM framing; maximum8MiB bodies remain reconstructable through status/private extraction/export. Ceilings:45 arrivals,8MiB,5000ms, six-hour acceptance window and seven-day erasure bound from creation. Owner/privacy instructions may shorten those bounds.

`privateEnrollment(directory)` returns the literal callback path to the private operator only. It must never be printed, hashed publicly, embedded in public manifests or placed in command arguments/logs. `openReceiver({directory,clientSecrets,port,now})` binds only127.0.0.1. Exact POST path selects that original mapping; queries, altered paths and every GET—including private-status—reject. The accepted Shopify verifier authenticates raw bytes and validates required headers; those headers still do not sign topic/time/delivery/domain or choose an era. The observed unsigned topic must equal app/uninstalled for a success ACK. Other/compliance topics retain encrypted negative evidence with the original binding and get400. This is experiment observation eligibility, not signed topic or generation authority. A separate local JSON check requires signed Shop `id` and `myshopify_domain` to equal the frozen original Shop binding. Native payload/identity semantics remain unqualified; this check is only demonstrated with synthetic Shop-shaped payloads.

Every request admitted by Node HTTP parsing reserves a private arrival before body processing. A bounded matching-path body is encrypted with random AES-GCM IV, authenticating the immutable mapping and receipt index as associated data. Only encrypted evidence includes raw body, observed Shopify headers/HMAC, original binding, fixed label, accepted-verifier result, unsigned-topic observation eligibility and signed-Shop equality. Invalid signatures/Shop bodies or ineligible observed topics get400 after private durable negative capture. A200 requires reservation file+fsync+directory fsync, encrypted spool file+fsync+directory fsync and commit marker+fsync+directory fsync. The receiver checks acceptance/retention again before200. Storage failure stops further capture and produces no success ACK. Oversize/timeout/aborted bodies close the connection and leave uncertainty, rather than fabricating complete evidence. Invalid HTTP parsing and connection-limit refusal happen before admission and cannot be counted as reserved arrivals; rejected excess traffic is not a bounded provider-delivery/privacy claim.

`status(directory)` is the local private-status interface. Before expiry it counts reservations and authenticated committed receipt files, with uncertainty explicit; after expiry it reports RETENTION_EXPIRED and null committed/uncertain values, and does not decrypt raw receipts. `privateReceipt(directory,index)` is privileged private extraction before eraseBy. `exportReceipt(directory,index,destination)` exclusively fsyncs a600 plaintext private export into a0700 directory; its fixed result explicitly creates an additional copy requiring separately owned erasure. Neither interface is HTTP-exposed.

`recoverDeadReceiver(directory)` removes only a lock whose PID is confirmed absent; active/ambiguous/reused PIDs refuse. Creation, receiver startup, recovery, receiver-lock release and erasure share one exclusive cross-process lifecycle guard in the canonical private parent, outside the erasable directory. Contention refuses without waiting or unlinking another actor’s guard. Receiver release checks its original directory and lock identities plus its random ownership token while holding that guard. A crash inside a critical section leaves a fail-closed guard: no automatic stale-guard removal or PID-based ownership inference is authorized. Explicit operator diagnosis of the owned process group is required before separate cleanup. Successful erasure does not create a tombstone; a privileged operator may subsequently create a new experiment at the same name, with a new capability, but never gains authority to reinterpret old receipts.

Restart preserves original reservations/commit records. Identical raw bodies and repeated deliveries produce distinct arrival receipts—there is no generic body-hash dedup. An incomplete reservation remains uncertain and is never manufactured into a committed receipt. Shutdown stops admission, destroys tracked HTTP connections including unfinished headers, and settles admitted handlers before wiping the mutable purpose-key buffer and releasing its owned receiver lock. Failed startup also cleans its key/lock. The deadline is armed after the startup guard has been released; `close()` is idempotent. Filesystem failure or ambiguous lifecycle ownership remains fail-closed, not a guaranteed successful erasure. The service process then terminates naturally; JavaScript signing-secret/capability strings cannot be reliably zeroized in an embedded caller, which must close/terminate its own process.

`eraseExperiment(directory)` refuses an active receiver, removes this experiment's local files and fsyncs the parent. Its result is LOCAL_FILES_REMOVED_EXTERNAL_COPIES_UNQUALIFIED. It does not promise secure device deletion, exported-copy/backup/log/host erasure, restore tombstones or completed privacy duties. The operator must arrange termination and erasure by eraseBy, own every export and shorten retention when required. Expiry blocks access/ACK but is not an erasure worker or permission for indefinite preservation. A copied whole directory includes the purpose key and therefore defeats encryption-at-rest protection against that copy; key/spool backup separation and external copies need independent native qualification.

## Threat boundary and deployment gate

An unchanged old URI plus old valid body/forged headers remains bound to the old experiment era. Headers cannot select a new era. Possession of the **current capability** plus a captured valid same-Shop body/HMAC can target the current endpoint: CURRENT_CAPABILITY_COMPROMISE remains a residual. No replay/freshness/actual-uninstall authority, intrinsic body-to-destination authentication or complete genuine-uninstall handling is claimed. Pre-authentication, pending/lost registration ACK, registration overlap, missing/removed subscriptions, Admin access revocation and delayed privacy obligations remain unresolved. A receipt200 does not pass any of these gaps or M5/G7.

`service.mjs` reads at most4097 bytes from inherited FD3 and rejects anything above4096. This is a trusted local operator channel; synchronous reads wait for EOF and have no built-in startup deadline. A missing/stalled writer can hang startup, so the local `supervisor.mjs` now requires exact bounded READY within10 seconds, passes an already-open FD3 without reading it, and TERM/KILLs its owned child group with a separate five-second exit-confirmation bound. Original authenticated acceptance expiry stops that child with no automatic restart. `cleanup.mjs` is a one-shot local deadline/catch-up eraser for one exact experiment; it checks the original authenticated deadline again using its own actual clock, refuses active/live unrelated PID locks, stale lifecycle guards and untracked local exports, and uses the accepted fsync erasure API. See [lifecycle contract](LIFECYCLE-CONTROLS.md) for real process/HTTP controls and fail-closed results. Host cgroup supervision, persistent timer/reboot-before-ingress ordering and whole-host guarantees remain unimplemented/unqualified. Unmanaged supervisor SIGKILL can leave a detached service; a successful local erasure result cannot prove outside copies or privacy fulfillment. The service reads synthetic-test/authorized future signing material from FD3 only, uses fixed sanitized READY/REFUSED output, and never reads environment secrets or creates an app-credential store. `network-guard.mjs` denies global fetch, outbound HTTP/TLS/socket/DNS and child-process paths; literal127.0.0.1 resolution is answered locally so inbound listening can work. This is source/process denial with local tests, **not OS isolation**. Core dumps, alternate native escape paths, TLS and external logging are not qualified by it.

SERVICE-PROPOSAL.json specifies the artifact and requested service restrictions after real local PASS. It is a proposal, not an executable host deployment. Dedicated UID, actual origin/port/storage/signing-FD handoff, immutable artifact installation, systemd/OS egress enforcement, Traefik no-redirect TLS and path/query/HMAC/body-free access/error/tracing/metrics policy are unallocated and must be independently frozen and tested on the selected host. Route by an exclusively allocated hostname without embedding the capability in router rules. Preserve every canonical/compliance destination; this receiver cannot discharge induced production effects or delayed privacy accounting.
