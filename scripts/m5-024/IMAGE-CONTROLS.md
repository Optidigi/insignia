# Disposable worker image qualification

The existing M3 runtime pull-request/main workflow runs `image-runtime.test.mjs` after the frozen portable worker build. It builds the reviewed Dockerfile locally on the disposable Ubuntu runner, records the actual image ID, and never pushes an image or accesses production. The package, pinned base digest, Node version and application command stay unchanged.

The one launcher correction is `ENTRYPOINT []`: the [official Node Dockerfile](https://raw.githubusercontent.com/nodejs/docker-node/main/24/bookworm-slim/Dockerfile) declares an inherited `docker-entrypoint.sh`. Source inspection identifies the risk; only actual CI image inspection qualifies the pinned resulting configuration. The local launcher control rejects that wrapper before accepting the explicit direct Node configuration. Historical M5-024 reports and NOT_RUN evidence are unchanged.

The runtime control owns a new PG18 container, internal IPv4 bridge, synthetic database and restricted consume login. Existing dbmate migrations, `install-queue.mjs` and `queue-roles.sql` provision the fixture separately from worker startup. Owner provisioning targets port 5432 at the actual owned database container's internal IPv4 address directly from the Linux Docker host. Both containers have no requested or actual published ports; the worker has no executable mounts. The endpoint qualifier binds the exact created container/network IDs and names, the single internal bridge, and an RFC1918 literal inside its native subnet; it rejects foreign or ambiguous addresses with no fallback. [Docker documents host access to bridge container ports](https://docs.docker.com/engine/network/port-publishing/#publishing-ports), but this fixture's host connection remains an inference until the corrected natural CI run executes it. The worker must pass actual readiness/liveness, full resolved executable inventory and Node hash equality, `/proc/1` argv/UID/GID/capability/no-new-privileges observations, EROFS write denial, SIGTERM exit0 and fresh-process restart. Negative qualification controls are supplied observations, not native image proof.

Networking checks require exactly the internal network, IPv6 disabled, no IPv4 default route and failed TCP to documentation-only `192.0.2.1:443`. [Docker's internal network contract](https://docs.docker.com/reference/cli/docker/network/create/#network-internal-mode---internal) still permits host-gateway communication. These observations do not establish DNS filtering, arbitrary host topology or a production egress policy; no provider endpoint is contacted. No queue acknowledgement is treated as uninstall/privacy completion.

Every Docker command retains raw stdout/stderr and exit status. Source commit/tree, Dockerfile hash, image configuration, inventories, native observations, result and cleanup receipts are uploaded with the natural workflow run/attempt for 30 days. Fixture logs are collected before removing owned containers and their anonymous volumes, the internal network and the temporary local image tag. Parent integration must retain required receipts durably before artifact expiry. Registry digest and exported image-tar hash, production topology/secret parity, deployment, native backup/rollback, provider behavior and uninstall/privacy effects remain NOT_RUN.

All migrations, the unchanged guarded queue installer and role/privilege queries run in bounded child processes. The role-check pools use 3-second connection, 5-second client query and 4-second server statement limits; the whole child lifetime bounds pool shutdown too. A 300-second body deadline and the Node test abort signal kill and await the child process group before finalization, preventing later fixture database work. Each log collection and owned Docker removal gets a fresh cancellation signal covering its command and 5-second raw-log write allowance; an earlier timeout cannot consume a later removal's budget. Two logs at 10 seconds each, four removals at 15 seconds each, context cleanup at 15 seconds and receipt retention at 5 seconds total 100 seconds within the 120-second finalization reserve, leaving 20 seconds for child shutdown and scheduling. Any per-container log or cleanup failure records FAIL and fails the test after receipt retention. Local controls exercise real synthetic child cancellation and external-command failure fixtures, without claiming actual Docker behavior.

The original PR69 attempt1 image build/direct launcher qualified, but its requested loopback publish produced no actual internal-network binding and provisioning stopped before worker startup. That CI failure, synthetic merge source identity and original reviews remain historical evidence. The correction removes publishing, fixes the assembled inventory probe syntax and strengthens failure/cancellation handling; no original result is relabeled as final-head qualification.

Original local qualification on the authoring host: the writable-root and frozen-inventory/OS controls, inherited-wrapper control and IPv6-boundary control each failed before their enforcement and passed afterward; three tests, zero skips. R2 adds five retained RED/GREEN cycles for endpoint selection/drift, assembled syntax, child cancellation and log finalization; ten final tests, zero skips, including an actual nested Node-test timeout that reaches finalization after child cancellation. R3 adds a retained RED/GREEN control using scaled real child deadlines and marker files: all four owned removal processes must actually launch after earlier log/removal timeouts, and the expected timeouts still record FAIL. The eleven local tests do not qualify an image. The R2 natural CI physical qualification remains historical; this finalization correction requires fresh source reviews and a new natural CI run. `image-runtime.test.mjs` fails immediately because Docker is unavailable (`spawn docker ENOENT`), retaining a NOT_RUN receipt and raw failure log. No image/OS runtime PASS is claimed locally.

Next execution is the existing naturally applicable CI workflow after the reviewed candidate is pushed. No manual workflow trigger is needed. On a disposable Docker-ready host with the already-built frozen package, the exact command is:

```sh
M5_WORKER_PACKAGE_ENTRY=/tmp/insignia-m5-024-worker/dist/main.js \
M5_IMAGE_EVIDENCE_DIR=/tmp/insignia-m5-024-image-evidence \
node --test scripts/m5-024/image-observations.test.mjs scripts/m5-024/image-runtime.test.mjs
```

The evidence directory must be new. A missing Docker daemon, package or failed native assertion fails qualification; no conditional skip supplies a green result.
