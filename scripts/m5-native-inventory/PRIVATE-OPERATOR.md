# Private exact-app inventory operator

This tool prepares a fresh one-token/three-read allocation after the original 10 October 2026 phase stopped. The original grant and sealed native phase are consumed, immutable and cannot be retried or resumed. This new resource phase is NOT authorized until the owner separately grants and the orchestrator records `owner-token-inventory-effective-scopes-allocation-20261010.json` with status `OWNER_GRANTED_FRESH_ONE_TOKEN_PLUS_THREE_READS` for the same exact app/shop, one token acquisition, three Admin reads and zero retries. There is no fallback to the original grant. It does not authorize a native run by itself. Production writes, installation changes, subscriptions, scopes, versions, Search and merchant fixtures are excluded.

Run only after the orchestrator freezes the source, obtains independent CLEAR/CLEAR reviews and natural exact-head CI, and qualifies the current app/store/organization and token-impact premises:

```sh
node scripts/m5-native-inventory/private-cli.mjs --gate /absolute/private/gate.json
```

An old v1 gate is rejected before IO. The private owner-owned `0600` gate must have schema `insignia-private-inventory-gate-v2`, status `FROZEN_NATIVE_GATE`, `validUntil`, `retentionDeleteBy` (at most seven days), exact app `429028933633`, client `1443cf6d03d39edae7c101a943c5c684`, shop `insignia-rewrite-dev.myshopify.com`, and the three exact `expectedGrants`: `write_products`, `read_publications`, `read_product_listings`. The source SHA256 map binds `private-operator.mjs`, `private-response.mjs`, `collector.mjs` and `private-cli.mjs`. `ownerGrantSha256` binds the separately recorded allocation. `specReview=CLEAR`, `securityReview=CLEAR` and `exactSourceCI=ATTEMPT_1_SUCCESS` are trusted orchestrator attestations, not cryptographic verification of GitHub or provider facts.

The independently qualified current premises are `currentActiveVersion=1158986629121`, `currentSameOrganization=true` and `currentDesignatedInstallationPresent=true`. `tokenOperationalQualification=SUPPORTED_EXACT_STORE_ISSUANCE_OWNER_ALLOCATED` records the orchestrator's supported-operation assessment under the exact owner allocation. `tokenLifecycleGuarantee=UNKNOWN_NOT_ASSERTED` explicitly preserves the absence of a universal no-revocation/coexistence guarantee. Supported-operation qualification is not proof of that stronger lifecycle property. The parent assessment must document the official supported grant and current eligibility without claiming new owner risk acceptance. An actual unsafe effect, identity/grant drift or ambiguous settlement stops without retry. The gate is operator-owned local evidence, never browser-controlled release/installation authority.

Native execution has one fixed phase directory: `/home/serveradmin/insignia-milestone-autonomy-handoff/native-token-inventory-effective-scopes-20261010`. This future fixed directory must not be created before the fresh resource allocation and source gate pass. A pre-existing directory consumes this allocation permanently; a second invocation reports its charged counts or UNKNOWN and issues no further requests. Closed runs are not resumed. A crashed process's reservations can be inspected without sending:

```sh
node scripts/m5-native-inventory/private-cli.mjs --inspect-closed-phase /absolute/private/phase
```

Every fixed SSH/OAuth/Admin operation has an fsynced reservation in the shared phase journal before IO. Unknown settlement remains consumed. The collector also maintains its narrower original Admin journal. No second directory can reset the native allocation. A 30-minute technical deadline and individual time/byte caps bound execution; they are not a renewal window for permanent VPS read access.

The remote producer runs absolute `/usr/bin/docker` under `/usr/bin/env -i`, selecting `--host unix:///var/run/docker.sock --config /nonexistent`; remote PATH, Docker context and environment cannot select another daemon. SSH host pinning alone would not establish this daemon identity. The pinned SSH identity reads only a fixed projection from `insignia-rewrite-m5-019-web`, requiring exact client ID, canonical `APP_URL` and image `sha256:8aa439cb733160ce6b99165e8401cfbc60f612851aeef0d76735db92917dc3f5`. Docker itself handles the full container environment, but its fixed Go template exports only the image and three exact named keys; no separate remote process captures the full environment. Duplicate/missing projected keys fail closed. This is neither field-level host privilege nor credential isolation; the existing SSH key's server-side command restriction remains unproven. Only the exact selected secret and public identity metadata cross the private process pipe. No secret goes into native argv, environment, chat, disk, raw OAuth capture or a new token store. JavaScript strings/GC do not establish cryptographic memory erasure. Issued-token expiry is not proof of early provider revocation.

The process privately captures its supported HTTPS transport, denies ambient HTTP/HTTPS request/get and global fetch, and requires explicit transport for inventory v2. It uses strict TLS trust/hostname checks, fixed HTTPS origins/paths/methods/documents/form, no redirects and no retries. OAuth bytes stay ephemeral. Before any Admin response body is persisted, both credential strings are checked literally and in every lexical JSON string, including keys and values lost by duplicate-key parsing. Malformed, oversized, partial or reflected bodies are withheld. This does not detect arbitrary covert encoding.

Inventory-only v2 takes the first fixed TLS-authenticated provider response as its authoritative shop/install tuple, after exact domain, app/client and current-grant validation, then fences every subsequent page and the final boundary against that tuple. This avoids inventing current IDs from stale history or browser inputs. It changes neither production bootstrap nor installation generations. V2 explicitly records `private-process-pipe-and-memory` as its credential channel; V1 still requires `inherited-file-descriptor` and its independent expected IDs. Two pages/500 subscriptions plus final boundary fit the three-read ceiling; incomplete or drifting observations stop. Collection success retains `STOP_PRE_INSTALL_DESTINATION_EFFECTS_UNQUALIFIED`: it does not prove callback safety, all downstream privacy effects or M5/G7 completion.

Local qualification uses real loopback HTTPS/certificates, subprocess secret projections, concurrent filesystem operations and SIGKILL after actual Admin dispatch. An equivalent local execution control substitutes only a synthetic Docker executable to demonstrate that hostile remote PATH/DOCKER_HOST/DOCKER_CONTEXT/DOCKER_CONFIG are removed and the fixed socket/config flags prevail. A separate invocation-shape assertion binds the absolute native executable. Actual Docker CLI/daemon execution is not claimed by these local controls. The frozen neutral prototype's 49 controls are predecessor evidence; they are not relabeled as integrated operator tests. Fresh integrated and unchanged inventory controls run through `pnpm test:m5-inventory` and natural CI. The test-only public API accepts only loopback HTTPS and a local Node fixture producer; the native CLI has no endpoint/producer override.
