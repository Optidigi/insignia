# M8 worker qualification

`INSIGNIA_M8_PURCHASE_ENABLED=1` enables independently read order reconciliation in the existing worker. It is off by default. The webhook body supplies only the retained, digest-verified order identity and current installation. Confirmed queue handoff and a durable five-attempt/one-minute claim precede provider access. The purchase repository atomically commits facts and marks that exact claimed inbox processed; stale leases or generations cannot commit. Failed reads release the claim with a fixed safe error class, without recording successful processing. Recurring order discovery remains independent of exhausted individual webhook jobs.

Discovery uses a durable per-installation updated-at window and continuation cursor. Initial lookback is bounded to the default 60-day `read_orders` boundary. A five-minute overlap avoids treating a boundary timestamp as exclusive; duplicate reads are idempotent. The exact window survives provider, individual-order and page-completion failures. Its watermark advances only after all discovered order reads and durable reconciliation succeed; terminal pagination closes the window. A ten-minute lease and exact claim/window/current-generation/current-read-permission checks reject stale completion. A failed pass backs off for five minutes; subsequent pages are immediately eligible. The default cycle selects at most five installations, with a hard maximum of twenty. Each discovery page contains at most twenty orders, each read has bounded provider IO, and the ten-minute lease exceeds the 20 × 10-second provider deadline budget. Access-denied older known orders remain explicit, never evidence of deletion. No `read_all_orders` approval, history guarantee or new manifest scope is inferred.

Private purchase payload cleanup uses `core.purchases.cleanupDue(100)` with database time and runs independently of order-discovery, artwork-storage and other maintenance errors. `runtime-grants.sql` is a separate owner-applied operation after migration31 for the existing qualified `insignia_queue_consume` capability role. It checks flags, parent memberships, ownership and excessive private/mutation privilege drift. Purchase access consists of append-only facts, bounded inbox leases/cursors, private offer metadata, artwork readiness columns and purpose-scoped historical offer/revision helpers; it does not create a login. The existing M3 credential grant is retained, without a new credential grant. Existing historical schema-20 operators are unchanged. Native migration/grant/deployment and protected installation changes have not been performed.

Local qualification uses PostgreSQL 18 `synthetic_m8` and synthetic per-test installations. Cursor tests exercise failed-page preservation, concurrent claim exclusion, continuation versus terminal advancement, stale-token rejection and generation fencing. The actual durable worker test supplies provider reads as explicit doubles but uses real inbox handoff, durable attempts, purchase persistence and completion, proving failed reads remain recoverable and webhook price fields are not authority. Unit tests exercise page partial failure, independent cleanup and safe error classes. The owner-grant qualification runs the exact script with a substituted isolated NOLOGIN test role and rejects privileged flags, inherited parent membership, owned tables, raw private-key reads and forbidden purchase mutation grants. A separate qualification connects as an actual non-owner LOGIN member of the intended capability role and runs the real durable purchase runner, initial/renewed signatures, first-paid/refund/replay history, historical retained revisions, encrypted credential acquire/refresh, cursor recovery and permission denials. The temporary test roles and their grants are removed. Ordinary no-marker orders complete their verified inbox without creating an Insignia purchase ledger. These checks are not native Shopify order/payment/refund/fulfillment proof.

The actual-login qualification is opt-in through `M8_RUNTIME_DATABASE_URL` and requires an owned loopback database named `synthetic_m8_runtime*`, prepared with all31 migrations. It installs the existing pg-boss43 contract and applies the existing queue grants plus the M8 script only in that isolated database. See [runtime role qualification](../../docs/delivery/evidence/m8-context-runtime/runtime-role-qualification.md). Production Order context remains unverified; provider/context doubles in this qualification are explicit local evidence only. Native grant/deployment execution is not authorized by this script or test.

CI runs `node scripts/m8-purchase/qualify-runtime.mjs` after the ordinary worker suite using its existing loopback owner `DATABASE_URL`. The wrapper creates a unique isolated database, records migration source hashes, migrates, requires the actual-login test to execute without skips, saves sanitized logs/result and drops only its owned database. It leaves the caller's database intact; credentials remain in environment variables. The bootstrap safety check is `node --test scripts/m8-purchase/qualify-runtime.test.mjs`.

The wrapper accepts only the `insignia_test` CI database or an owned `synthetic_[a-z0-9_]+` database on loopback, and rejects endpoint query overrides before connecting. Owner connections are bounded to10 seconds for connect and30 seconds for queries/statements; subprocesses are bounded to5 minutes and1MiB combined output, with their owned process group killed before database cleanup on a limit. Current CI outputs remain generated artifacts; preserved local observations use `runtime-role-local.*`.

The synthetic member login uses an ephemeral random password, supporting the CI service's SCRAM authentication without relaxing authentication. Its password stays in private SQL/in-process connection configuration and is not emitted. Every wrapper invocation initializes fresh FAIL artifacts before validating configuration, preventing invalid invocations from reusing an earlier PASS receipt.
