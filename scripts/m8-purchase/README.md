# M8 worker qualification

`INSIGNIA_M8_PURCHASE_ENABLED=1` enables independently read order reconciliation in the existing worker. It is off by default. The webhook body supplies only the retained, digest-verified order identity and current installation. Confirmed queue handoff and a durable five-attempt/one-minute claim precede provider access. The purchase repository atomically commits facts and marks that exact claimed inbox processed; stale leases or generations cannot commit. Failed reads release the claim with a fixed safe error class, without recording successful processing. Recurring order discovery remains independent of exhausted individual webhook jobs.

Discovery uses a durable per-installation updated-at window and continuation cursor. Initial lookback is bounded to the default 60-day `read_orders` boundary. A five-minute overlap avoids treating a boundary timestamp as exclusive; duplicate reads are idempotent. The exact window survives provider, individual-order and page-completion failures. Its watermark advances only after all discovered order reads and durable reconciliation succeed; terminal pagination closes the window. A ten-minute lease and exact claim/window/current-generation/current-read-permission checks reject stale completion. A failed pass backs off for five minutes; subsequent pages are immediately eligible. The default cycle selects at most five installations, with a hard maximum of twenty. Each discovery page contains at most twenty orders, each read has bounded provider IO, and the ten-minute lease exceeds the 20 × 10-second provider deadline budget. Access-denied older known orders remain explicit, never evidence of deletion. No `read_all_orders` approval, history guarantee or new manifest scope is inferred.

Private purchase payload cleanup uses `core.purchases.cleanupDue(100)` with database time and runs independently of order-discovery, artwork-storage and other maintenance errors. `runtime-grants.sql` is an owner-applied cleanup-only grant to the existing qualified queue role. It checks direct flags, parent memberships and function ownership. It creates no login or data-read capability and does not qualify the queue role for purchase reconciliation or credential access. Existing historical schema-20 operators are unchanged. Native migration/grant/deployment and protected installation changes have not been performed.

Local qualification uses PostgreSQL 18 `synthetic_m8` and synthetic per-test installations. Cursor tests exercise failed-page preservation, concurrent claim exclusion, continuation versus terminal advancement, stale-token rejection and generation fencing. The actual durable worker test supplies provider reads as explicit doubles but uses real inbox handoff, durable attempts, purchase persistence and completion, proving failed reads remain recoverable and webhook price fields are not authority. Unit tests exercise page partial failure, independent cleanup and safe error classes. The owner-grant qualification runs the exact script with a substituted isolated NOLOGIN test role: privileged flags and inherited parent membership are rejected before grants; a qualified role can execute cleanup but cannot read private purchase tables. The temporary test roles and their grants are removed. Ordinary no-marker orders complete their verified inbox without creating an Insignia purchase ledger. These checks are not native Shopify order/payment/refund/fulfillment proof.
