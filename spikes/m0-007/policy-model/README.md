# M0-007 local policy projection

This prototype reads two app-owned product metafields, `m0_007_registration` and `m0_007_policy`, plus the shop's app-owned `m0_007_public_config`. The product fields use `single_line_text_field` values with exact ASCII grammar `generationHex:revision:state`: 32 lowercase hex digits, a positive canonical decimal `u32` revision, and `pending`/`ready` for registration or `required`/`optional` for policy. Example: `11111111111111111111111111111111:1:ready`. These values carry no buyer input or quote price. The shop config retains the M0-005 v2 JSON shape and current generation/key semantics.

The two fields must agree on generation and revision before an unmarked line can be plain optional or known required. A surviving malformed, missing-partner, pending, or stale field makes an unmarked product uncertain and Validation rejects it at checkout. Signed complete offers continue through a same-installation policy revision, including a partial rollout, because the v2 signature and economic terms are still verified. A legible wrong-generation field rejects signed offers as well. Transform emits no operation for unsigned or invalid sets; Validation leaves `CART_INTERACTION` open for repair.

`publication.rs` is a pure journal/store model. It tests withdrawn availability, pending registration, CAS writes, readback, observed Function projection, stale concurrent writes, idempotent resume, and both policy-change directions. It does not call Admin or write a database. A real publisher must bind its intent to an authenticated app installation, use Shopify `compareDigest`, persist the journal, and verify Function projection before exposing purchase channels. No PostgreSQL/Shopify transaction is assumed.

When **both product fields are absent**, an unmarked required product is observationally identical to unmanaged merchandise and is allowed. This is an explicit joint-loss limitation, not a complete required-product guarantee. A separate durable membership anchor or an approved uncertain-product checkout policy is needed before adopting that guarantee. The 200-line fixtures exercise source boundaries locally; they are synthetic and do not prove live query cost or propagation.
