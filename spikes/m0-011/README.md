# M0-011 local provider adapters

This module supplies a bounded Partner read client and a guarded App Events transport for the existing M0-010 billing proof. It does not create a subscription, plan, meter, credential, buyer order, or paid usage. No authenticated provider request was run while developing it.

## Public seams

- `PartnerClient.readActive(shopId)` executes only M0-010's fixed `PARTNER_ACTIVE_QUERY` and uses its runtime parser. `readHistory(shopId, from, through)` executes only the fixed scoped history query and returns `COMPLETE_PAGES` after all requested pages. That result means pagination finished for that explicit range; it does **not** assert an exact historical trial interval or coverage outside the range. `readLiveEnvelope(shopId)` supplies a fresh identity-checked current response for the no-charge guard.
- `AppEventsClient.send(event)` is dry run unless a `LIVE_ZERO_PRICE_TEST` manifest, `PartnerClient`, and `FileRunJournal` are all provided. It pins the designated staging Shop GID, checks Partner before credential acquisition, then checks Partner again after journal fsync and immediately before the POST. It uses M0-010's `encodeAppEvent` for the original body, time, key and `value: 1`. A new event must have an occurrence timestamp within 60 seconds of its first reservation; an exact retry keeps the original timestamp. HTTP 202 yields `RECEIVED` only, with status, an allowlisted request ID and a three-state replay-header observation; billing validation remains asynchronous.
- `FileRunJournal` defaults to `.local-run/journal.json` under this module. Real transport refuses an alternate journal path; Node's isolated synthetic test runner can inject a temporary path. It creates a 0700 directory and 0600 journal/temp files, reserves the exact serialized body and attempt count before any event POST, and fsyncs the file and directory. A concurrent lock or corrupt/different run journal fails closed. It caps this one journal at three unique keys and six total reserved attempts, including ambiguous sends; failed auth before reservation consumes no POST attempt. Never delete, replace or reset the journal to restart a live run. This local file is an operator safeguard, not a tamper-resistant package-wide billing authorization service. A crash while holding the lock requires inspection of that run's journal and lock before any manual recovery.

Credentials are injected separately as `partner()` and `appEvents()`; neither is an Admin token. `AppEventsTokenClient.getToken()` implements the fixed Dev Dashboard client-credentials exchange and verifies the App Events write scope and token lease; it can supply the `appEvents()` port. The clients do not read environment variables or credential files. Credential providers can return a token string or a token with `expiresAt`; the latter is rejected within 30 seconds of expiration. HTTP responses are limited to 128 KiB, Partner request bodies to 16 KiB, App Events bodies to 4 KiB, and requests to 10 seconds (tests may inject a shorter positive deadline). Credentialed fetches use manual redirect handling and refuse every redirected response. Provider error bodies, URLs and tokens are never returned to callers. 404/410 event responses are `UNSUPPORTED_ENDPOINT`; there is no URL fallback.

The live manifest must name the exact app, designated shop, plan, `customized_order_paid` meter, active cycle, run and operator observations. Its `appGidVerified`, `meterVerified` and `installationVerified` booleans are operator assertions that require independent, recorded provider/Dashboard evidence. The Partner App GID is not yet known, so the adapter cannot independently pin it to the approved OAuth Client ID; no live manifest can honestly be certified in this PR. The adapter confirms the fresh Partner response has the same app/shop/cycle, one active zero-priced flat item and one active zero-priced two-tier graduated meter, zero current usage cost, no trial and no pending update or cancellation. A missing cycle, changed price, unsupported tariff, stale observation or failed Partner read blocks the POST. This is narrower than possible Shopify private test-plan shapes; a differently shaped built-in test plan needs a separately reviewed parser, not relaxation of M0-010's production hybrid parser.

## Source binding and limits

The [current App Events reference](https://shopify.dev/docs/api/app-events/latest) on 2026-09-28 selects `2026-07` latest and explicitly documents `POST https://api.shopify.com/app/2026-07/events`, its bearer-token flow, 202 receipt and asynchronous billing validation. The [billing tutorial](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing/subscription-billing/build-billing-event) still contains `unstable` examples. This adapter uses the explicit versioned reference; M0-010's earlier source receipts and fixtures remain unchanged. The [Partner API reference](https://shopify.dev/docs/api/partner/2026-07) documents the organization endpoint and Partner token, while its [active subscription](https://shopify.dev/docs/api/partner/2026-07/active-subscription) and [historical events](https://shopify.dev/docs/api/partner/2026-07/historical-events) pages define these read shapes.

`RECEIVED`, `COMPLETE_PAGES`, and synthetic contract tests are not a live eligibility, billing, deduplication or cleanup result. The module has no live CLI or subscription mutation path. A live run requires the owner's separate verification of App Pricing eligibility, exact Partner App GID and its link to the approved OAuth app, organization, installation, meter, pricing and no-charge terms, plus credential availability. The actual Partner App GID is still unknown; setting `appGidVerified: true` without independent evidence would be false. The file counter is not a global attempt authority: a deleted/replaced file, a different run, or an intentionally altered test environment can reset it. Before any live send, the one staging operator must maintain a durable package-wide attempt register, count all POSTs across restarts and files, and stop if that register is absent or ambiguous. A Partner read cannot establish every Dashboard-only prerequisite. Do not enable live mode in CI.

Run `corepack pnpm install --frozen-lockfile` and `corepack pnpm check` in this directory. Tests inject synthetic HTTP responses and credentials; they make no provider calls. The repository CI must add this new package's check as a separate integration-owner edit.
