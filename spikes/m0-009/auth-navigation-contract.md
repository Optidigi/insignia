# M0-009 embedded Admin contract

Status: scoped G7 prototype. The current v1.2 architecture and M0-008 publisher remain separate. This package neither publishes product policy nor adopts v2.

The two file-based document routes (`/` and `/draft`) serve only a public shell. Shopify App Bridge loads from its CDN using the public client ID. The shell fetches `/private/home` or `/private/draft` on the same origin after App Bridge initializes. Its fetch interceptor supplies a short-lived ID token. The Astro server verifies that token on **every** private fragment and POST, derives the shop from verified claims, exchanges for a user-associated online token, and checks a per-use-case edit permission. A query parameter, launch `host`, cookie, referrer or bare iframe location never authorizes content. Ordinary anchors cause full-page navigation and a fresh shell/fetch cycle; they are not assumed to carry a bearer token.

Only after verification does Astro render merchant-specific markup. The draft fragment supplies escaped text and initial values to a page-local Preact island. POST `/api/draft` validates `{label,version}`, requires an ID token, same configured origin, online staff-associated permission and the expected tenant, and changes only in-memory synthetic state. Cache headers on private responses are `private, no-store`; the browser clears old private markup before each fetch, including page navigation. No session/access token or client secret is put in HTML, browser storage, our URLs or logs. On a fetch with an expired ID token the backend returns `401` with Shopify's one-retry hint; the frontend does not build its own unbounded retry loop.

Live mode is limited to the existing `insignia` installation on `insignia-staging.myshopify.com`. It needs existing credentials from the CLI's server environment; the shop is allowlisted before the exchange URL is constructed. Synthetic mode uses test credentials/fake exchanges and binds to loopback only; an HTTP parameter cannot enable it. The online session is cached per shop/user/session with expiry and a single-flight exchange. A local-memory edit disappears on restart. Production persistence, refresh/recovery, full G7 staff matrix and deployment are out of scope.

Current public sources: [Shopify ID tokens](https://shopify.dev/docs/apps/build/authentication-authorization/id-tokens), [custom-framework token exchange](https://shopify.dev/docs/apps/build/authentication-authorization/implement-token-exchange?lang=node), [Astro Node](https://docs.astro.build/en/guides/integrations-guide/node/), [Polaris stable CDN](https://shopify.dev/changelog/polaris-cdn-1-1-is-now-stable). These describe interfaces, not evidence that this integration works in Admin.
