## Live Admin path

1. Cold launch in the authenticated Shopify Admin embedded frame rendered only the public shell first. App Bridge supplied a bearer ID token on the private same-origin fetch; the Node Shopify SDK performed a real **online** token exchange. The minimal read-only Admin query returned the exact staging shop and existing installation above. The protected home fragment showed local synthetic edit permission for the current staff session. No personal staff identifier was recorded.
2. The deep route `/draft` rendered the protected server fragment and Preact/Polaris text field/button. Keyboard traversal reached the field and button. A first POST failed safely with 403 because the tunnel's internal Astro request URL was HTTP while the browser Origin and configured public host were HTTPS. The corrected rule requires the exact public Origin and exact public host, allowing only the tunnel's internal HTTP scheme. A local regression test covers the same-host success and wrong-host rejection.
3. With that correction, the current staff session saved the local label `G7`. The UI displayed “Synthetic draft saved locally.” Reloading `/draft` read `G7` from the same server process. Keyboard navigation from the draft page to Overview reauthenticated and displayed the same shop/installation. Parent browser history back and forward returned to the protected draft and home routes with fresh content. After the reviewer correction added a viewer binding, a second local-only save on a new process also succeeded in the live iframe; the 15-second same-viewer recheck left the entered value and feedback intact.
4. Clearing the field and activating Save showed the Polaris validation error and focused the field. The current label remained `G7`. At 390 × 844 CSS pixels, the embedded page, field, error and button stayed visible and usable. This was a resized desktop browser, not a real mobile-device test.

The first live attempt exposed an Astro script transformation: normal `<script src>` generated module imports for App Bridge/Polaris and left App Bridge unavailable. Marking those CDN scripts `is:inline` preserved external classic scripts; cold launch then authenticated. The failed state and correction are preserved here rather than counted as an initial pass. Several fresh tunnel hostnames briefly failed DNS resolution in the shared browser; local DNS then resolved them. One subsequent Admin route returned a transient Shopify 500 while the store Home loaded, and a fresh route load succeeded. These are not counted as app passes.

## Limits and boundary

- Live evidence covers one current staff session and one installed shop. Alternate real staff and second live tenant were unavailable; their permission/tenant cases are synthetic tests only.
- The final conceal/inert behavior added after the live same-viewer polling observation passed local type/build review and independent source review; its exact browser transition was not separately captured live.
- Actual Shopify ID-token expiry and third-party-cookie-blocked browsing were not independently observed. The SDK's expiry path, exchange-time expiry classification and fresh retry header are tested with synthetic tokens; no forged live token, clock change or cookie-policy weakening was used.
- The editor is process-local and intentionally non-durable. Online grant cache is bounded to five minutes or grant expiry and must be revisited for production permission-revocation timing. Credential persistence/recovery is not implemented. The browser conceals and disables private content during its visible 15-second/focus viewer check, but an in-place staff change can leave the prior view visible until that check starts; no actual alternate live staff switch was available. The stale-editor POST guard is synthetic and built-output tested.
- The T3 browser screenshot metadata includes unrelated Admin identity/dev-console content and short-lived iframe URL parameters, so raw screenshots/network traces are intentionally not committed. This sanitized textual receipt records visible app content, route and result. No raw bearer token, client secret, CLI GraphiQL key or staff details are included.
- No product, policy, order, payment, discount, inventory, Function or billing resource changed. Development app-preview state remains because cleaning it currently removes previously granted staging scopes. This is partial G7 evidence, not a full gate pass, production v2 adoption, publisher activation, protocol freeze or M1 readiness.
