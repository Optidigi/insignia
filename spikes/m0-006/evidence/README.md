# M0-006 retained live prototype evidence

This is a sanitized record of the 26 September 2026 UTC experiment on the existing `insignia` app (`942e6668fd1177524c0fc48b104b0ac3`) and `insignia-staging.myshopify.com` (`gid://shopify/Shop/78935261342`). The source branch starts at the verified normal PR #8 merge `9f08c8ff6ee8a6a908b976c26f8435e4301308c5`. Order #1001–#1004 and their fulfillments were read-only. `order-1001..1004-before/after.json` are equal. The single staging operator used the shared native Admin for payments, discount, cancellation and publication; direct app API and Shopify Function logs supplied structured receipts. JSON Function receipts are projections of actual CLI execution logs, with raw-log SHA retained in each receipt; they are not synthetic fixtures. The raw logs are omitted, so their hashes cannot be independently recomputed from this PR. Customer data and browser session material are omitted.

## Artifact provenance and repeatable checks

`preview-bundle-identity.json` is a filtered copy of the CLI 4.8.2 development bundle manifest. It records only two Function handles/UIDs/targets/app identity and the SHA-256 of each bundle `dist/index.wasm` file. The CLI stored those files as base64 text, retained as `live-preview-{target}.base64`; decoded executable Wasm is retained as `live-preview-{target}.wasm`. `scripts/capture-manifest.py` checks encoded hashes against the filtered manifest and byte-for-byte decodes against retained executables. Decoded preview executables match the contemporaneous target build hashes: Transform `f98e32af930b7e3cb27b9b48bed245515510bcdc141e5e0c43a68b3cf4296639`, Validation `701582c4d750c8ce42abfff3d9627814459e522d1d0f225f466d242759e5b9fb`. Later builds can differ; CI records both instead of implying binary identity. The unfiltered CLI manifest is omitted because it contains live tunnel URLs. This PR verifies the retained local preview bundle and replay, but does not independently attest which bytes Shopify executed remotely.

`preview-replay.json` independently executes those exact decoded preview Wasm files with the pinned Shopify Function runner and synthetic valid, 10-signed/190-ordinary, 32-signed and 64-signed fixtures. The valid 10/190 Transform emitted ten operations in 3,246 bytes at 6,350,137 instructions; Validation emitted no error at 6,290,093 instructions. Both rejected 32/64 signed buckets without partial Transform output. These off-store replays support bounded output for this experimental ten-bucket cap; they do not prove live 190-line cart operation, stack peak, numeric query cost or product capacity. The historical 64-bucket failure remains.

From `spikes/m0-006`, with pinned Node 24.21.0, Rust 1.98.1, Shopify CLI 4.8.2, and the locked M0-005 helper dependencies:

```sh
python3 -B scripts/check-evidence.py
./scripts/check-local.sh
```

`check-local.sh` runs Rust format, Clippy, six tests for each Function, CLI Wasm builds, exact preview-bundle replay against retained outputs, and source/receipt hash verification. The local host additionally needed its existing project-local Zig C-linker wrapper via `CC` and `CARGO_TARGET_X86_64_UNKNOWN_LINUX_GNU_LINKER`; GitHub's Ubuntu runner has its ordinary host linker. `live-artifact-manifest.json` binds source, imported M0-004/M0-005 source, sanitized receipts and bundle bytes. CI writes its rebuilt artifact comparison to ignored/generated `ci-manifest.json` and `ci-preview-replay.json`.

The temporary Ed25519 private key was removed after this run. No credentials, storefront password, browser session, customer identity or private Function request-body capture are retained. Signed synthetic values and the ephemeral public key are included for reproducibility. The observed one-cent discount discrepancy, missing-policy obligation, untested last-line/wallet paths and absence of a second paid order remain open for principal adjudication. The v2 protocol is a prototype, not adopted architecture or a gate pass.
