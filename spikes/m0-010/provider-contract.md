# M0-010 provider contract and capability matrix

Checked 27 September 2026 against Shopify's primary documentation. The executable shapes in `src/partner.ts` and `src/app-events.ts` pin Partner API and App Events **2026-07**. They parse/encode data only; this package has no authenticated HTTP client, credential or merchant call. Synthetic response bodies in `test/provider.test.ts` are contract fixtures, not observations from the existing app.

| Capability | Documented fields / behavior | Local decision and remaining proof |
|---|---|---|
| Current subscription | Partner API `activeSubscription(appId: ID!, shopId: ID!)`; shop identity, `billingPeriod`, `trialEndsAt`, `currentBillingCycle{startTime,endTime}`, `items{handle,price,usage}`, `pendingUpdate`. Null means no active current contract. Only **public apps** can query it; the Partner API client needs **Manage apps**. [Active Subscription, 2026-07](https://shopify.dev/docs/api/partner/2026-07/active-subscription). | Parser validates exact shop, monthly period, current trial/cycle time, active flat item, currency agreement and two-tier graduated meter shape. Provider `Z`/offset timestamps are normalized to UTC milliseconds. Raw decimal overage amount is retained; actual configured plan/allowance/price agreement remains a live prerequisite. Unsupported/malformed, auth and public-app errors refuse entitlement. Null does not prove a past order was unbillable. Existing app's public eligibility and Partner API access are unverified. |
| Subscription history | Partner `events` filters `subjectId` and `shopId`, explicit `occurredAtMin/Max`, `first <= 250`, `after`, `pageInfo`; default 30 days, maximum 365-day query range. `SubscriptionStatus` exposes `occurredAt`, `eventType`, `state`, `cancelEffectiveOn` (a **Date**) and plan handle/trial-day fields. `subject` can be an `AppReference` with ID. [Historical Events, 2026-07](https://shopify.dev/docs/api/partner/2026-07/historical-events), [SubscriptionStatus](https://shopify.dev/docs/api/partner/2026-07/objects/SubscriptionStatus), [Subject](https://shopify.dev/docs/api/partner/2026-07/unions/Subject). | Fixture parser requires scoped explicit range and verifies returned app subject and shop IDs; it returns page metadata. It does **not** manufacture a complete historical interval from one page or infer a precise time from `cancelEffectiveOn`. Complete pagination, installation baseline, exact effective transitions and historical trial boundaries remain the production normalizer's obligations. Unknown time means `PENDING_HISTORY`, not a charge. |
| Trial and plan changes | During an active trial `trialEndsAt` is populated and `currentBillingCycle` is null; afterward those fields reverse. `pendingUpdate` is future configuration, not current entitlement. Shopify tracks consumed trial days over a rolling 180-day period across uninstall/reinstall. [Active Subscription](https://shopify.dev/docs/api/partner/2026-07/active-subscription), [free trials](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing/subscription-billing/offer-free-trials). | Business fixture waives a provider-confirmed 14-day chosen-plan interval once. No local reinstall/upgrade reset. Documentation alone does not establish every historical trial end or proration instant; ambiguous cases remain pending for reconciliation. No assertion is made that Shopify automatically waives usage during trial. |
| Hybrid tariff | Combined recurring and usage pricing is monthly. `TieredPrice.tiersMode` must be `GRADUATED`; an initial zero-cost band models included order units, followed by overage. Volume pricing reprices all units. Shopify documents fractional unit prices, including `$0.005`. [Combined subscription and usage](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing/subscription-billing/combined-subscription-and-usage), [usage setup](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing/subscription-billing/setup-usage-charges). | Three **artificial** plans in `TEST_PLANS` have distinct feature/allowance/mock-cent values. Every non-trial qualified order emits `value:1`, including included units; the fake tariff applies the allowance once. Parser accepts valid decimal precision as a string; fake cents do not model provider fractional rounding. Actual names, handles, feature assignments, prices and merchant currency remain unset. The real configured tier and selected plan must be compared before a live test. |
| App Events transport | `POST https://api.shopify.com/app/2026-07/events` with `shop_id`, matching `event_handle`, original ISO `timestamp`, `idempotency_key` (≤64 chars) and `attributes:{value:1}`. One event/request. Billing keys are permanently deduplicated; generic event keys have a 24-hour window. Timestamp cannot be >5 minutes in the future. [Create an event, 2026-07](https://shopify.dev/docs/api/app-events/latest/creating-events). | Encoder emits only the unit value and a once-generated random opaque key; no order/customer attributes. The key and original time persist in the local outbox. Future occurrences are deferred without rewriting time. Timeout, 409, 429, 5xx replay the same key/time. Retry-After is honored; after twelve local attempts, review is required. This is a fake transport, so no Shopify receipt is claimed. |
| Auth separation | App Events uses its own Dev Dashboard client-credentials token at `/auth/access_token`; the billing guide calls for App Events access. Partner API has an organization-scoped client and **Manage apps**. Neither is the Admin session/online token. [Billing event guide](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing/subscription-billing/build-billing-event), [Partner API](https://shopify.dev/docs/api/partner/2026-07). | No credential acquisition exists here. Existing eleven Admin installation scopes do not establish Partner API or App Events access. Exact credential setup and scope availability require later authorized preparation. |
| Acceptance/reconciliation | App Events returns HTTP `202` on receipt even if billing validation fails; no synchronous billing failure webhook is documented. Billing logs in Dev Dashboard show asynchronous errors including `PERIOD_CLOSED`, `NO_SUBSCRIPTION` and meter mismatch. Partner current usage gives cycle quantity/cost; documented per-event query/correlation is absent. Pre-uninstall usage has 24 hours after uninstall for submission. [Create an event](https://shopify.dev/docs/api/app-events/latest/creating-events), [billing event guide](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing/subscription-billing/build-billing-event). | `TRANSPORT_ACCEPTED` is never `BILLED`. Fake later processing and aggregate comparison return `AGGREGATE_MATCH_ONLY` or review; equality does not verify each event. Known closed window and terminal validation preserve the original event for operator disposition. Real dashboard result visibility, cycle/contract agreement and failed-event correlation remain untested. |
| No-charge later proof | On a development store in the same Partner organization, available plans can be selected at no charge; other-org testing is limited to free or marked-free-to-test plans. A no-charge paid-plan contract has effective $0 recurring and usage prices. [Shopify App Pricing testing](https://shopify.dev/docs/apps/launch/billing/shopify-app-pricing). | The app's public eligibility, pricing method/plan availability, app/store Partner ownership, meter, Partner API client and App Events access are unverified. A $0 test can prove the flow/count, not real-price invoice math. This PR authorizes none of that setup or selection. |

The tutorial's illustrative App Events code still shows `unstable` in places; the versioned reference supplies the 2026-07 endpoint used here. A successful local parser is not proof that the existing app is eligible for that API or that its future plan configuration matches the synthetic catalogue.
