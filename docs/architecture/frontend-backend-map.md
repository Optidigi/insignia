## Persistence ownership and exact compatibility conclusions

1. **Product drafts/revisions:** C-SCHEMA validates draft, pure domain validates economic rules, C-B binds tenant/product/entitlements and executes idempotent commands, C-DB owns CAS rows and immutable revision records. Selected PlacementProduct has different root fields, per-placement sizes, local URLs and review/calibration/movement metadata. Saving it directly is not valid. JSONB storage capacity does not grant semantic support for unknown fields.
2. **Global Methods:** M-B schema/service/repository/migration jointly prove name-only standalone catalog. New explanation/default policy/assignment/provenance need deliberately owned fields/relations and migrations, or another explicit persisted model; no exact schema design is authorized here. Default propagation must version affected drafts, preserve explicit overrides, preserve published revisions and handle concurrent edits. No numeric-equality inference.
3. **Images:** CAT is a read-only bounded Shopify catalog projection. ASSET captures frozen preview bytes/revisions in private storage for historical use. These are different from selected browser upload/data URL library and variant grouping authoring. Select actual owner and lifetime before implementing upload/removal. Existing artwork storage is not automatically a garment-media upload API.
4. **Geometry:** GEO validates strict views/default+variant images, placement/default+variant rectangles and global step fractions/physicalMm. It does not persist selected calibration, movement bounds/permission, review markers or group rules. Existing shape must be extended/versioned or accompanied by an explicitly owned editor presentation record; unknown retention/version semantics remain Q.
5. **Customer production placement:** `packages/contracts/src/v1/pricing-config.ts:79` has no buyer position. Domain canonical identity owner is `packages/domain/src/customization/identity.ts:1`; frozen quote material owner `packages/application/src/quote/material.ts:1`. Movement must travel through validation, identity, quote snapshots, purchase payload, historical renderer and production sheet—not merely a canvas offset. Whether this requires changed authorization bytes is unresolved; WIRE requires explicit version decision for incompatible byte/meaning changes. Do not assume UI extension alone requires or permits new wire bytes.
6. **Orders:** O-B/O-ART/C-DB purchase migrations own immutable bindings, mutable append-only attachment events and erasable payload. Selected archive requires verified original metadata; date/filter query needs service+repository extension. No persistence is required just to choose columns, make a client PDF or download a browser Blob.
7. **Translations:** `customer-translations-workflow.ts:80`/`:106` proves localStorage owner. Current merchant presentation is labels only and BuyerConfig lacks wording overlays. New merchant-wide authoring/distribution needs explicit ownership and policy; do not claim there is already a database translation model because the selected browser workflow says “save.”
8. **Sessions/designs/quotes:** BUY-DB owns real buyer sessions, design versions, proposal/acceptance/application records; buyer DTOs use capabilities and complete sets. Selected local Design/Artwork/cart receipt is not an accepted quote. Existing backend capabilities can power the new UI through real ports without inheriting fake totals/IDs.
9. **Capacity is not a UI limit:** selected positions permit up to 100 (`designer/config.ts:112`), BuyerDesired placements/variants/groups are bounded at 32 (`packages/contracts/src/v1/buyer.ts:10`), public config methods/placements at 32 and variants at 250 (`:81`), while GEO permits 100 variant image/override entries (`packages/visualizer/src/geometry.ts:159`, `:177`). A generated large demo is not a supported merchant envelope. Reconcile representation and admission without silently truncating or advertising every fixture as purchasable; WIRE guards remain independently authoritative.
10. **Shopify authority:** catalog/variants/contextual base/availability, theme edits, subscription approval, product creation, cart and checkout remain Shopify-owned (SPEC). New UI must not introduce Insignia copies as authoritative state. Current setup/permission/billing observations are not write receipts.
