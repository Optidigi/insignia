# Selected Designer runtime wiring

The host trigger and native purchase-control replacement are owned by the [theme extension integration](../../extensions/insignia-theme/README.md). Its lightweight eligibility read does not load or authorize the Designer. Contextual config readiness requires actual production dimensions, contextual prices and nonempty consistent variant option facts; a false readiness result cannot create an editable Designer. No-country canonical reads remain available for retained readers.

Every customer flow uses the selected Designer in an isolated iframe document with its own Inter/styles. The Shopify theme retains the host trigger and existing Ajax cart adapter, journal, locking and cart-update event. Current and compatible older Lean publications use real frozen production geometry and contextual prices. Existing production choices appear conditionally in the selected quantity/review steps: new designs retain the existing first-allowed-value defaults, while restored designs retain their exact accepted values. Products without these choices keep their existing selected presentation. No customer route falls back to legacy UI, demo catalogues, sample upload receipts or local-preview cart authority.

Missing critical production measurements or financial facts require the selected repair screen and preserve the existing cart until explicit verified replacement/removal. Missing optional product previews after publication show an explicit unavailable preview without inventing a garment or preventing valid artwork selection and quote review. The publication gate still requires complete captured images before a new publication. Canonical read projections support positive small footprints and independent width/height size bounds; merchant authoring constraints remain separate. Deferred artwork retains one stable identity per placement, including the original identity on compatible restoration.

Immutable selected setup and captured garment images come from the published revision. Stable safe UI aliases map back to exact backend placement/method/size identities; real Shopify option tuples supply every available variant cell. Contextual garment prices and the immutable decoration table supply advisory display values. Amounts outside safe numeric display bounds are rejected. Server quote amounts remain exact decimal minor-unit strings.

Review prepares an actual full customized-cart quote before final consent. Every retained sibling is included; unknown amounts remain unavailable. Only the displayed proposal hash may be accepted. Changed cart, publication, expired review or unavailable choices require another review. Lost acceptance acknowledgement retains its exact proposal and idempotency key. Only a verified Shopify Ajax result produces a cart receipt.

Compatible historical selections map their stable placement/method/size/artwork/variant identities onto the current selected publication and require explicit full quote consent. The existing cart and accepted offer stay untouched until verified replacement. Original frozen visuals remain authoritative for order/history; editing does not add an obsolete-visual rebase transition or silently discard unavailable choices.

Each edited group retains its own selected state machine while full-cart review can switch groups. A successful sibling update rebases current cart bindings without discarding other editing state. A publication change while editing exposes repair while the existing Designer remains mounted and suspended. Explicit **Start a new customization** is the consent that resets that draft to current configuration; the original cart group remains until a verified replacement applies.

Unavailable or removed production choices are never filtered out. Repair can review removal of one owned group: the server quotes every remaining sibling, the customer reviews the actual remaining total, and a separate confirmation authorizes the exact proposal and Ajax vector. Explicit removal of all observed customization uses the existing journalled repair mode and preserves ordinary Shopify lines. When the original session is lost, only this observed remove-all recovery is available; a new session is not treated as ownership of old artwork or offers.

The live host persists selected drafts through existing `PUT designs/:id` CAS. Shopify documents that app proxies forward the request method and body, which preserves this existing JSON protocol ([authentication reference](https://shopify.dev/docs/apps/build/online-store/app-proxies/authenticate-app-proxies)). A narrow `POST designs/:id/restore` uses the same JSON capability, current installation, owner, session admission and original expiry checks. It returns one retained draft, captured immutable selected presentation when available, and an explicit compatibility reason. Browser storage contains only a non-authoritative UUID hint; the endpoint validates ownership again. A lost save acknowledgement is reconciled through that same UUID before another update. It does not return current merchant drafts, foreign artwork or bulk historical cart presentations.

Optional artwork movement uses integer image-centre micros in group identity and immutable purchase production instructions. Backend validation binds the complete artwork footprint to the published permitted area, chosen size and variant photo geometry. Existing fixed-position authorization bytes remain unchanged.

Automated qualification covers selected mapping, exact money, reducer/runtime state, authoritative review before commit, retained edits through repair and retry, owned CAS restoration, real Ajax sibling-preserving removal and lost-session recovery. Browser-source live-port tests use the strict Bundler compiler profile; Node host tests retain the existing NodeNext profile. Native Shopify/browser composition and merchant visual acceptance remain separate evidence.

New derived step IDs hash tuples containing delimiter characters or exceeding128characters; derived price IDs hash delimiter-bearing Method tuples or oversized values. Ordinary simple/UUID paths remain readable. Retained immutable step bindings are read explicitly rather than recomputed; price labels migrate only by exact placement/step/Method tuple. Frozen records are unchanged.
