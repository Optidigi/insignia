Avoiding /api/admin and allocating an isolated receiver does not prevent those effects. A new disposable shop and preserved compliance subscriptions do not imply permission for that work.

Proceed only with independently verified destination/processor/config evidence proving excluded production resources remain unaffected, **or** a separately expanded, exact owner/principal authorization for every induced effect with qualified accounting, retention, privacy and cleanup. This proposal currently grants neither. If any destination, automatic authentication path, downstream writer, worker, retry, ownership or erasure premise is unknown/unqualified, STOP_PRE_INSTALL_DESTINATION_EFFECTS_UNQUALIFIED before install/register/uninstall. Do not delete, disable, redirect or modify existing compliance/business subscriptions to pass this gate. Read-only inspection access needed to establish these facts must itself be separately authorized; no VPS access is inferred.

If expanded authority is considered, it must name the exact receiving services/database/queue/storage, expected bounded inbox/job/log/config writes, role/schema startup behavior, retry bounds, rollback limits and privacy-handler qualification. The accepted production uninstall defect and deferred privacy handling remain blockers; owner consent alone is not proof of safe/compliant handling. Count provider-induced deliveries/effects separately from the operator's70-request ceiling and the private callback's45-arrival ceiling; no unbounded production stream is absorbed into either number.

The six-hour window bounds operator/provider mutation attempts and private callback observation only. It does **not** close downstream obligations. Before any install, establish a separately approved downstream accounting/retention/erasure owner and qualified safe processor for the full delayed-delivery horizon, with exact closing evidence, deadline handling, alert/escalation, no dropped receipt and no indefinite pending. If the horizon/processor/effect bounds cannot be established, stop before mutation. Era A can be labelled “before first authenticated session” only when the native flow and independently observed absence of app authentication support that interval. Generate distinct 32-random-byte capabilities in private memory and persist the immutable experiment Shop/app/external-install/era binding and recovery material privately before registering. Store public labels/operation IDs and separately private mapping/hash evidence; no public literal URI or capability fingerprint that enables reconstruction. Return fixed safe classifications; do not forward receipts into production uninstall processing. The collector can deliberately return one failure **after** durable storage in the B delayed-retry branch. It never fails compliance routes; no repeated-failure removal is claimed. No provider request tests the escape guard.

Private native evidence is encrypted/0700, retained at most seven days and shortened on owner/privacy requirement; identifying bodies/URI/HMAC/credentials are erased earlier after reviewed extraction when no longer needed. Public packet contains sanitized native observations, labels/counters/verified hashes and provenance, never fabricated screenshots. Keep only independently justified minimal audit/tombstone facts; no retention exemption is invented. This disposable experiment does not qualify production erasure, compliance deadlines or backup recovery.

## Bounded native sequence and mandatory gap interpretation

1. **Frozen pre-access gate:** obtain separate written authorization for the named resource and ceilings; local receiver/operator tests, two fresh independent reviews and exact-source CI clear; freeze source/build/config/private evidence policy. No credential access before this gate. Do not change production source in response to a native result.
2. **Read-only entry and pre-install effects gate:** exact supported app/version/config/distribution observation and independent app-specific compliance inventory; confirm unchanged Active1158986629121, scopes and existing app identity. All source/deployment shapes that could reconcile subscriptions are inventoried within separately allocated read-only access, or UNKNOWN blocks a complete result. No production host access is inferred. A shop-specific inventory cannot stand in for app-specific records. Resolve the mandatory destination/effects/automatic-session gate above before Era A; otherwise stop before the first installation mutation.
3. **Era A — before first authenticated session:** owner installs then uninstalls without opening/authenticating the app. Owner native observations are labelled attestation, not automatic generation authority. There is no callback subscription registered by this experiment; record any independently available provider/compliance evidence without calling an Admin API for A. No receipt/newer-generation mutation is permitted. This negative interval cannot pass callback-only coverage; absent native receipt is merely a bounded observation, not proof of no event or no obligations.
4. **Era B — acknowledged registration and lost-local-ACK:** owner reinstalls; privately acquire one supported current online grant and exact Shop/current AppInstallation observation. Persist original era binding and capability before one create. Require returned ID/topic/URI and complete inventory. If exact ACK settles, permit one explicit same-URI repeat to classify provider dedup/error/duplicate behavior. If duplicate, inventory both owned IDs then delete only the extra once and read back; otherwise stop on unexpected identity. Create one distinct private URI for the same era as the lost-local-ACK probe: intentionally withhold operator response consumption, keep private transport evidence, then reconcile through full exact-URI inventory **before uninstall**. This proves an operator-observation gap, not the provider's internal commit timing. Any unknown write or revoked access stops with no retry.
5. **B uninstall / delayed delivery:** owner uninstalls only after all B writes exactly settle. Persist native delivery at its original destination; optionally return one failure after durable storage to expose a delayed retry. Never replay a captured native request to Shopify/production; changed metadata/body controls remain local-only. Retain old destination mapping privately through the bounded delay/reinstall observation. Independently distinguish actual native retry, owner attestation and derived local replay.
6. **Era C — reinstall and missing/removal coverage:** owner reinstalls; exact new provider ID must differ, no old mapping rebind. Full inventory must show whether old IDs were removed. Observe any delayed B callback against its original private mapping; a lack of delayed delivery does not pass that fact. Exact installed identity plus complete empty matching inventory proves this controlled missing-subscription case. Owner C uninstall then tests the uncovered interval; a generic/compliance receipt cannot acquire new-generation authority. No missing callback within a window proves event absence. **Automatic failure-removal remains NOT_NATIVE_QUALIFIED:** APP_UNINSTALLED also causes uninstall cleanup, so a missing record after uninstall cannot distinguish those removal causes. Do not manufacture another business topic or product change to force a failure-removal event. Qualified manual deletion does not establish automatic removal timing or missed-uninstall recovery.
7. **Era D — terminal provider-registration overlap:** owner reinstalls; exact new ID and full inventory precede the final create. Coordinate owner uninstall after outbound reservation but before operator acknowledgement. Record local request-start/response-complete/ACK, native owner action and callback arrival; these do not reveal provider transaction ordering. Stop immediately on ambiguity, revoked credentials or unknown subscription settlement. Do not compensate/retry or create a fifth installation. An exact native callback mapped to D provides one observation, not proof of all registration gaps.
8. **Close:** no app is left installed by intention after D's exact owner uninstall; if a prior stop leaves it installed/ambiguous, return exact state and separately request narrowly scoped owner cleanup rather than improvising. Confirm known owned subscription removals only through supported independent evidence. Preserve unrelated/compliance subscriptions and public canonical service. Seal counters/reservations, stop isolated receiver after the bounded retry window, revoke only experiment access, securely erase private raw/secret material by its deadline and retain permitted sanitized facts. No production queue/worker operation is directly authorized. Any separately approved induced downstream effects must remain accounted through their delayed privacy horizon; otherwise the pre-install gate blocks the phase.
