## Implemented seams

- The authenticated Admin product list and editor use server-side Shopify online staff verification, active installation generation, product ownership, and an actual bounded catalog reader. All reads and commands require the current authorization scope. Create, save, copy, and publish recheck it under the PostgreSQL transaction's installation lock. The browser gets a public shell and fetches private data with a single-flight, deadline-bound App Bridge bearer token; no private product/config data is rendered into SSR HTML. The SDK exchange's underlying fetch receives the exchange AbortSignal through an asynchronous request context.
- A shared browser-safe `m5-merchant-draft-v1` carries M2 methods, placements, production options, pricing, and `m5-geometry-v1`. Server commands validate the existing production M2 schema and geometry bridge together. Bounded human labels use category identities, with option-scoped value IDs. A versioned, hash-checked immutable `m5-presentation-v1` companion preserves published choice names without changing M2 economic revision JSON or identity. The typed Admin controls cover normal method/placement/step, view/variant/image, option/value, general and method/placement/step pricing, all-units tiers and presentment override. Advanced JSON is optional.
- Save is an optimistic version compare-and-swap with durable idempotency. The browser keeps the exact request and key across uncertain responses, rereads PostgreSQL state for a canonical recovery decision, and distinguishes a definite permission/validation rejection from an ambiguous outcome. A stale version produces a conflict and reload path. Copy creates a new product-scoped config with fresh internal IDs and remapped labels; it omits source-product image and variant bindings and never aliases the target to the source revision.
- Product detail paginates variants in bounded pages of 100, up to 500. The ninth variant is selectable; a product exceeding the bound is explicitly marked incomplete in the editor. Variant option names/values are projected from Admin, and duplicate identities or repeated cursors fail closed.
- The versioned geometry sidecar stores image dimensions/revision references, per-view normalized placement rectangles, variant overrides, and decoration-step fractions. It rejects nonfinite or out-of-image extents. The browser uses `projectScene` and `applyGeometryCommand` on one typed state store; direct Konva is a projection and drag writes the same state as typed controls. The renderer has no React or react-konva dependency. Browser, server, database, and renderer import boundaries have executable positive and negative probes.
- Publish accepts a durable immutable validated M2 revision and geometry/presentation hashes, then calls the production M4 `prepare`/bounded `advance` path. The service exposes pending, remote-ready activation-pending, conflict, and operator-hold states from durable progress; an older effective revision remains separately identified when a newer operation is pending. It rechecks current eligibility and current shop currency against the immutable revision on interrupted replay. The immutable presentation companion records source draft and installation generations. A completed publish command with no M4 progress remains a queryable current-installation intent bound to its exact command key; the editor can continue it after a newer draft, denied storage or lost response. A stale stored request for an older operation is discarded. Bounded continuation calls drive a pending operation. Terminal receipt replay is read-only; a completed active operation permits a newer edited revision. Default production activation admission remains absent, and this slice never invokes M3 activation.
