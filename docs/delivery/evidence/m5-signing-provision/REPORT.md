It composes the original `createAdminOnlineIdentity.verify/exchangeOnline/readInstallation`, `SigningKeyLifecycle`, durable core, Function ownership reconciler and publication adapter. An actual signed ID token is verified and exchanged into an online staff grant. App/user/provider write permission and Function-read scopes are checked; provider Shop/installation/timezone must agree with the existing managed installation. Authorization generation/epoch comes from the active repository scope, never the input. The original trusted-release reader and artifact validator qualify independent original release/Function timestamps before effects and again before dispatch/activation.

The input contains exactly `directory`, `keyId`, `firstDay`, `lastDay`, `idToken`, `ring`. Ring has `currentKeyId` and `keys` mapping existing wrapping-key IDs to32-byte lowercase hex; persistent custody must already be arranged privately. The operator does not generate/store a wrapping ring or signing seed supplied by the caller. `createPending` generates and seals its own random seed with the existing lifecycle.

The private parent directory must already exist, be owned by the operator UID, mode0700, and have no symlink components. The new run directory is exclusive0700; reservation/events/results are exclusive0600 with file and directory fsync. The nonsecret ID/day plan is hash-bound to the one-attempt reservation before authentication. Every SDK/lifecycle effect is reserved before dispatch and settled with closed facts. No token, wrapping key, private envelope, raw provider error/body or public-config value is journaled/output.

Before any key write, existing public config must exactly match existing lifecycle keys (or be absent when no keys exist). Capacity and key-ID reuse stop. Provider calendar coverage is `firstDay <= D` and `lastDay >= D+2`, rechecked without UTC shortcuts or tolerance. One pending key is created, one original CAS publication is attempted, original adapter exact readback/recovery is used, closing installation/Function/config observations and scope checks precede existing lifecycle activation. Unknown create/activation/publication outcomes stop and forbid retry. A key can remain pending after a stop; no compensating revoke/destroy/epoch change is invented.

Success is `SIGNING_KEY_CONFIG_PROVISIONED`, with `quoteIssuanceAuthorized:false`. It establishes key/public-config provisioning only. Both-Function propagation, active deployment presence, effective ProductConfig and genuine quote/publication readiness continue through their existing independent gates.
