# M4-001 contracts and limits

API versions pinned after checking current stable [Admin GraphQL](https://shopify.dev/docs/api/admin-graphql/2026-07) and [Partner GraphQL](https://shopify.dev/docs/api/partner/2026-07) references on 29 September 2026: both **2026-07**.

## Catalog/context

The application `CatalogContextPort` takes an explicit M3 tenant/shop ID, numeric-string installation generation, merchant Product GID, bounded real Variant GIDs and country. The Shopify adapter resolves up to 100 variants in 25-node requests; it proves `ProductVariant.product.id` equals the requested product, preserves the contextual final `MoneyV2.amount` string and currency, and returns provider request ID, source version, observation and five-minute deadline. Missing/partial/throttled/invalid answers reject the entire vector. The application `resolveFreshCatalogContext` rechecks identity, completeness, exact decimal, source version and freshness at quote-use time. Context prices are scoped to the exact country, shop and generation.

The concrete Admin HTTP transport requires a generation-fenced credential source. It accepts only its fixed read query and API URL, rejects unsafe hosts and near-expired credentials, bounds response size and never returns a token. An application composition root must connect it to M3's credential lifecycle; no buyer-facing quote flow exists yet in this slice. This is a production-shaped adapter contract, not deployed quote issuance.

## Active subscription and policy

The Partner client reads only fixed `activeSubscription(appId,shopId)` on the public app, validates returned app/shop identity and parses a bounded raw JSON response so usage quantities and discount percentages retain exact decimal text. A null result is a normal no-active-subscription state. Every current item is normalized independent of array order: exact case-sensitive handle, provider price kind/`active` metadata/currency/flat or tiered amounts, VOLUME or GRADUATED tiers, usage and discount; future `pendingUpdate` remains separate. Duplicate handles, malformed dates/numbers or contradictory trial/cycle fields reject. HTTP/provider failures are typed and sanitized.

The application binds a provider observation to its own tenant/shop and installation generation before projecting it. It accepts observations only up to a configured **maximum five minutes**, requires exact app/shop/tenant/generation match, a recognized configured plan and usage handle, and a currently valid provider trial or billing cycle. Unknown, stale or absent authority yields no feature grant and no new billable usage. The effective-zero development contract's `price.active:false` flags remain provider price metadata; the *current activeSubscription* and explicit configured policy determine entitlement. Provider amounts never invent commercial policy.

The active trial grants the selected plan's configured features and yields `WAIVE_TRIAL` with `billableUsageAllowed:false`. Future M9 paid-order processing must record that waiver rather than enqueue it for later charging. This slice has no App Events emitter or trial usage ledger and creates no retrocharge path. Scheduled cancellation retains current features only while the active provider contract is current; no local grace is inferred. A pending update never grants future-plan features early. The policy intentionally supports **monthly** hybrid contracts only; an ANNUAL provider response can be normalized for evidence but receives no feature grant. This follows the current architecture's monthly plan lock, not a conclusion that annual Shopify contracts are impossible.

No provider projection table was added. M4-001 has no production quote/publication runtime that needs an offline cached projection. The port returns bounded observations; any future persistence must remain tenant/install scoped, digest-bound, versioned, deadline-bound and refreshable. An expired or absent observation cannot authorize quotes/publication through the supplied application policy. Later runtime composition and reconciliation must not treat the five-minute snapshot as permanently authoritative.

## FX

The [FX research](automatic-fx-research.md) explains why contextual garment prices cannot supply automatic customization FX. `CustomizationFxProvider` requires an exact pair, rate decimal, source/version/provenance, effective/observed times and expiry; `requireUsableCustomizationFx` enforces caller-selected maximum rate age and provider expiry, rejecting missing/stale/wrong-installation observations. No external automatic source is implemented or selected. Cross-currency quote issuance therefore remains blocked until a reviewed provider adapter is supplied; same-currency pricing and explicit exact-currency overrides do not require a fabricated rate.
