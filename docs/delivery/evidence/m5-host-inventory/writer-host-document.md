## Fixed entry and output contract

The on-disk command is `python3 -B scripts/m5-host-inventory/host_inventory.py collect`, receiving one JSON envelope on stdin (maximum64KiB). Every other CLI action/argument is rejected. The operator has no SSH/provider transport, credentials reader, dynamic path/command/executable selector, production SQL, Docker exec/Compose, HTTP health request, worker startup, installation/subscription action, provisioning or host filesystem write. Its subprocess environment is rebuilt from fixed nonsecret locale/PATH/HOME values. Docker uses the fixed local Unix socket and an empty/nonexistent config location; it does not select an inherited context or remote daemon.

**All successful stdout is owner-private capture.** It contains infrastructure metadata and the two explicitly permitted nonsecret policy values. Do not publish it wholesale. Public evidence must be separately projected into counters, source/selector hashes, categories and opaque destination/processor labels. Secret-adjacent configuration is represented by presence/nonempty booleans only; neither value nor value hash is collected. Unknown facts cannot produce a native authority PASS.

The exact envelope keys are `mode`, `allocation`, `qualification`, `reservation`; additional fields fail closed. Live mode is `LIVE`. The allocation must name host65.109.22.104/user serveradmin/port22, read-only scope, trusted fingerprint, current selector hash, ten active observation IDs, expiry, private retention≤7days and accounted incidental audit/session effects. The qualification must bind the actual source SHA256 and selectors to frozen head/tree and independent Spec/Standards review and applicable CI references (`FROZEN_LOCAL_GATE`). The reservation must bind that same allocation/source/selectors/host/fingerprint, private capture, all ten attempted-observation slots and the shared inspection start/deadline (`SSH_READ_RESERVED`).

The collector validates structure and bindings, not owner identity or authenticity of those records. The trusted local orchestrator must independently verify the real allocation, completed reviews/CI and durable accounting before invoking it. Synthetic records exist only inside the local test harness and cannot establish permission. No record generator, credential launcher or pretend signed attestation is included.

For remote stdin source delivery, the caller can use the explicit trusted Python seam `collect_verified_source(envelope, executed_source_bytes)`. It must compare the transmitted/executed frozen bytes to the qualification before executing code, and pass those exact bytes; passing a caller-authored digest is not supported. The on-disk `collect(envelope)` instead hashes its own source file. Neither seam replaces transport trust. The caller must construct a reviewed fixed loader, send code/envelope without shell interpolation, enforce strict host checking/BatchMode/IdentitiesOnly and transport timeouts, and privately reserve/settle each actual SSH attempt. This implementation does not execute or invent that caller.

The previously owner-recorded fingerprint is `SHA256:vttVPAISQypNdyfjFElTJ6ef8Q5S2YlC+XoUn599uq4`. A fresh verification must match the renewed exact owner allocation. A matching historical string is not a newly verified host receipt. The old temporary key was revoked; no old key/run is reused or reopened. Slots1–10 are attempted exactly once in order and individually reserved before host invocation. Slots11–12 are emitted UNKNOWN without accessing any location. Errors stop later reads except a nonzero command exit from the two exact optional router/legacy Docker projections: those emit UNAVAILABLE_COMMAND_FAILED with containerState/failureCause UNKNOWN and globalAbsenceProven=false, then continue the already fixed independent reads. ## Commercial, privacy and accounting limits

The permitted nonsecret schema derives from [provider policy](../../packages/application/src/entitlement/provider-policy.ts) and [production composition](../../apps/web/src/server/admin/production.ts): policyVersion/maxAgeMs and plans with planHandle/usageHandle/policyId/features/includedUsage; base/required/logoLater/options/pricing feature mapping. The collector validates only those fields. It cannot prove provider plan truth, ownership approval, current active subscription/eligibility or exact deployed composition. Missing configuration/provenance becomes one concrete consolidated owner input; it is never filled with inferred development allowances or prices.

Each command stdout and every observation is capped at1MiB; command failures use fixed sanitized categories and raw stderr is discarded. Subprocess deadlines are≤15seconds and bounded by the shared inspection deadline; timed-out children/process groups are killed, with no retry. Full result is bounded by12MiB plus64KiB metadata overhead. Fixed source/archive hashing and metadata reads use the same deadline; each observation accounts attempted selectors even on failure. No host receipt, reservation or artifact write occurs.

The caller owns the **single ≤30-minute** active inspection window across the separate machine Admin collector, three owner-native app-management surfaces and host reads. Errors and incidental requests count; a fresh process is not a new allowance. The collector enforces its allotted start/deadline, but cannot authenticate another collector's ledger or control owner UI network fan-out/audit effects. Shared private ledger completeness, strictly supported existing credentials, native identity/grants, concurrency and audit-effect agreement must be established separately. There is no installation/subscription mutation, production SQL, App Home/Search, provisioning/deployment/version/scope change, fixture or M6/M7 authorization.

Private infrastructure/configuration/provider evidence remains in the owner-approved capture with≤7-day retention and earlier applicable deletion; source-only synthetic local logs contain no credentials/native data. The plan's section10.4 retention/export/erasure/tombstone/restore requirements and section11 lease/retry/idempotency/worker constraints remain binding. Existing privacy deferral, uninstall-generation RED and missing current downstream owners keep `STOP_PRE_INSTALL_DESTINATION_EFFECTS_UNQUALIFIED` in force. Successful metadata collection is never privacy/uninstall/G7 PASS.
