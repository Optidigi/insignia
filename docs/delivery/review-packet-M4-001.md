### Fresh review findings and correction

Both independent sessions used actual `gpt-6-sol`, high reasoning, `read-only` sandbox, restricted network and approval never, with exact fixed refs. Spec/correctness session `01a0eef8-601f-7c12-9402-7f14288b1889` found (P1) Partner snapshot tenant binding could attach a correct provider Shop GID to the wrong M3 tenant because the supplied tenant was not verified, and (P2) the Admin transport required `shopDomain` but M3's usable-token port did not return it. Standards/security session `01a0eef8-5fcb-78f1-946d-c345a14353bb` found (P1) `BILLABLE` disposition from projection time could misclassify an order paid during trial but processed after it, (P2) an attacker-controlled Partner string `#number:3.25` could spoof the raw JSON number marker, and (P2) direct callers of exported Admin HTTP transport could bypass the 25-ID resolver batch cap. Neither review used credentials, live calls or tests.

The correction adds a read-only `getActiveProviderScope` M3 facade backed by active-generation PostgreSQL join, requires it for Partner binding, and joins the same scope to M3's fenced credential lifecycle for Admin reads with a recheck before returning the token. Paid-state policy now yields `REQUIRES_EVENT_TIME` rather than `BILLABLE`; M9 must decide at the order's first full payment fact and cannot use a later current-state projection as charge authority. The Partner parser brands genuine JSON numeric tokens after parsing using a per-response unpredictable marker, so provider strings cannot impersonate them. The direct Admin HTTP transport now validates unique GIDs, country and its own maximum 25-ID vector before credential acquisition. Synthetic tests cover each correction; the PostgreSQL suite verifies identity loss across reinstall/deactivation. The correction head was frozen for fixed-ref rereview.
