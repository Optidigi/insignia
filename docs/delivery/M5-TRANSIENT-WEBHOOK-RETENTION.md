Ordinary tenant callers retain their contract. |

Erased duplicates use the preserved digest/metadata, return `expired`, never restore bytes or refresh collection/deadline. Conflicting bodies remain rejected. Ingress does not enqueue expired receipts and returns 503 with `transient_payload_expired_unresolved`. |
| Queue reservation | Migration adds `unknown/unconfirmed/confirmed/exhausted`, separate from payload erasure, and a cleanup marker. Existing rows become **unknown**; new receipts default unconfirmed. Before any send, a separate committed transaction reserves unconfirmed → unknown. | Bounded accounting | At most 100 uninstall-labelled rows and 100 combined privacy/unknown/unsupported rows per pass, sampled separately. `blockedUninstallIds` and existing categories expose opaque IDs privately; fixed public alerts contain only bounded counts, never subject/shop/body IDs. ## Required decision and remaining blockers

All three mandatory privacy topics (`customers/data_request`, `customers/redact`, `shop/redact`) currently defer; no structured request/subject obligation mapping or qualified fulfillment processor exists. Their raw body may contain the only subject IDs. Maintenance therefore preserves their exact body/deadline and reports `blockedPrivacyIds`, including already overdue work. Unindexed Shopify payloads report `blockedUnknownIds`. **This is an acknowledged overdue privacy/retention violation, not permitted indefinite retention, fulfilled erasure, or a deadline waiver.** Existing handling remains unsafe for deployment.

All other indexed topics, including `orders/paid`, `orders/create` and `refunds/create`, report `blockedUnsupportedIds` with unchanged bodies/deadlines and explicitly overdue, unfulfilled disposition. The worker defers them; no implemented immutable economic capture establishes that their sole raw facts can be discarded. The existing seven-day raw metadata is not authorization for that irreversible loss. Plan §§10.4/11 require the appropriate minimum fact/obligation contract and retention basis; this correction creates no future order/refund processor, economic/privacy store, or indefinite-retention permission. These blockers also prevent deployment.

Uninstall-labelled bodies also report `blockedUninstallIds`; neither a processed state nor a minimal two-field Shop identity proves event purpose/currentness, complete obligation capture or safe discard. The retained advisory reproduces application-accepted synthetic mixed bodies losing facts under the rejected selector; ordinary provider-shaped examples reject and native overlap remains unproven. The corrected regression preserves both pending and processed mixed bodies. All raw-body categories remain overdue/unfulfilled blockers. This removes the newly introduced destructive authority defect; it does not fix the historical generic uninstall authority flaw or grant indefinite retention.

Plan §§10.4/11 already authorize the necessary technical obligation capture, dispatch and erasure implementation under the milestone operating model. The orchestrator owns that implementation; a routine processor choice does not require another external approval. Before deployment it must qualify fulfillment and timely erasure together, including already overdue receipts. A missing lawful retention basis/deadline for residual Shopify-subject, tombstone or audit facts, an unresolved replay/currentness risk trade-off, and access to external backup/log/derivative copies remain substantive owner/resource decisions. Retained routing/domain/digest and all copies need their actual basis, erasure path and ownership qualified. This slice does not invent that basis or copy subject data to a new indefinite store.

The actual production web role is unknown. Current web core and queue use the same configured DATABASE_URL; this source does not provision a different topology. Enqueue-only queue privileges cannot acknowledge application metadata. Local controls prove a narrow metadata-only handoff grant can do so without reading raw payload; they do not qualify all web ingress permissions. The consumer role script retains required handoff/cleanup column grants and explicitly revokes obsolete payload/erasure/lease write grants on reapplication, without collection/deadline/digest/routing or immutable-history rewrite grants. Deployed grants and all alternative processors remain unqualified.

Old unknown rows with missing jobs and reservation-before-transport crashes may never enqueue automatically. They remain unresolved obligations; no genuine uninstall handled claim is made. Populated retention schema cannot roll back and lose exclusion metadata. Historical trusted-release rollback tests now run their exact migration era; production/historical migration bytes and assertions remain intact.

The unchanged unexpired generic uninstall replay characterization remains **RED as a security property**: a replayed signed body with later unsigned metadata can still deactivate a newer generation. Passing its characterization is not an authority fix. M5/G7, native installation/publication safety and full privacy remain blocked.
