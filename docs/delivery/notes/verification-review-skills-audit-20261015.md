## Recommended application of current policy

This matrix is an audit recommendation, not an amendment or a new approval checklist.

| Change impact | Minimum useful verification/review |
| --- | --- |
| Prose, links, status or receipt pointers | Author checks source refs, chronology, links and sensitive data. Reuse existing behavioral evidence. Ordinary required repository CI remains applicable; no artificial RED or new independent full-source pair. Batch related pointer changes into the next natural integration boundary where possible. |
| Local reversible behavior with no trust/economic boundary | One meaningful failing behavior example, affected regression and a bounded independent correctness review. Include interacting callers rather than reviewing an isolated function without context. |
| Money, identity, privacy, concurrency, release or destructive effects | Independent coverage of both correctness and security, with exact source/base and relevant seam tests. Two separate contexts are often useful for a new boundary such as PR159; a single suitably scoped independent reviewer may cover both axes for a narrow operator change. Native proof remains distinct from review. |
| Correction to previously reviewed work | Review the delta and affected contract; retain prior attribution and exact unchanged hashes. Escalate depth if the correction changes authority, economics, concurrency or data loss. A spelling, selector or proven configured-prefix correction should not automatically reopen the full implementation. |
| Major integration or rollout boundary | Cumulative drift/contract review, final-candidate CI and the specific authorized runtime observations. Reuse unchanged module checks. Production rollout still requires the owner. |

An independent review means a reviewer who did not author the change evaluates the actual candidate against requirements and reports findings/limits. It does not mean a fresh model provider, a principal approval, a test PASS or an enforceable capability sandbox. Root self-checks remain valuable but must be labeled self-checks, not independent review. Reusing a returning reviewer for a small correction is honest impact review; it is not a fresh isolated full-source review.

Audit evidence rather than collecting stamps: record a concrete fixed base, changed files/hashes, important interacting assumptions, findings/corrections, executed versus skipped tests and the resulting integration/native limit. Reopen only the affected conclusion when new evidence contradicts it. Preserve failures and archives, but keep their pending wording outside current routing or subordinate to a clear closing receipt. Current scope can remain intact while this process is simplified; reducing product commitments is not supported merely by the volume of tests or documents.
