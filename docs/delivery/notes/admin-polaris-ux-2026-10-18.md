# Merchant admin UI reference and implementation direction — 18 October 2026

The owner requires Polaris **web** components throughout merchant UI, silent skeletons during every route transition, and a more intuitive product configurator. Keep the pinned Polaris1.1 runtime/types. No code/assets or product behavior are copied from references.

## Reference findings

- Shopify recommends related field groups, clear section headings, progressive disclosure and explicit saving for complex forms. Apply this by putting the current product step immediately below a compact save/status toolbar; move detailed publication/support information into Review. Existing draft CAS, recovery and publication authority remain unchanged. [Shopify forms](https://shopify.dev/docs/apps/design/user-experience/forms)
- Shopify’s Settings template groups navigable categories with contextual help. Apply this to store configuration and account/data rows, while keeping optional permission inspection in a disclosure. Useful settings are implemented capabilities; this does not invent preference switches. [Settings template](https://shopify.dev/docs/api/app-home/latest/patterns/templates/settings)
- Polaris web components have no direct skeleton-page replacement. Shopify recommends a stable page shell, pending content regions and coordinated navigation feedback, including failure/retry/cancellation checks. Compose placeholders from real `s-box`/`s-stack` components, retain accessible labels, and remove visible loading copy as the owner requests. Never add fake network latency to ordinary navigation. [Loading migration](https://shopify.dev/docs/apps/build/app-home/migrate-from-polaris-react/skeleton-page), [Loading API](https://shopify.dev/docs/api/app-home/latest/apis/user-interface-and-interactions/loading-api)
- Atlassian recommends skeleton geometry that resembles the eventual content. Carbon describes logical form groups, progress and previous-step review for multi-step forms. Apply these principles within Polaris; do not import either design system. [Atlassian skeleton](https://atlassian.design/components/skeleton/usage), [Carbon forms](https://www.carbondesignsystem.com/building-blocks/core/patterns/forms)
- Stripe separates operational resource navigation from settings. Linear distinguishes workspace settings and permission-relevant controls. These support Products/Orders navigation plus grouped Settings, without fabricated dashboard metrics or unauthorized actions. [Stripe Dashboard](https://docs.stripe.com/dashboard/basics), [Linear workspaces](https://linear.app/docs/workspaces)

## Concrete gaps found and corrected in this pass

The old enforcement checked named islands and exempted shared upload controls. Actual native file inputs/buttons, download links, disclosures and typography remained reachable. Enforce the whole local component import closure of merchant routes, including shared upload/preview components, with negative controls and runtime light-DOM checks. Semantic layout and specialized rendering canvases remain structural content; interactive controls and ordinary typography use Polaris.

Use actual `s-drop-zone` file events, `s-button`, `s-link`, `s-image` and Polaris typography. A disclosure uses a real Polaris button and an accessible controlled region; no unsupported accordion/tabs/skeleton component is invented. Verify exact pinned runtime behavior rather than relying on current documentation alone. [Polaris component index](https://shopify.dev/docs/api/app-home/latest/web-components), [Drop zone contract](https://shopify.dev/docs/api/app-home/latest/web-components/forms/drop-zone)

The new route boundary must cover initial server paint, slow component runtime, authenticated-read success and failure, internal navigation, cancelled clicks and return navigation. It keeps full-document routes and existing security headers. Private derivative imagery must retain credential/referrer omission, lease retirement and late-response fencing; replacing a native image must not silently change those transport contracts.

Research was delegated read-only to `/root/admin_polish_research`; root reconciled the findings against local source and the pinned runtime. Legacy native stores remain human-verification blocked from the prior attempt; no repeated login or copied legacy implementation is used.
