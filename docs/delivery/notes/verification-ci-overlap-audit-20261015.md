## Confirmed gaps and minimal alternatives

1. **D4 selection holes:** `scripts/m4-003/**`, `scripts/m5-017/**` and `scripts/m5-003/**` appear in none of the three PR/push path filters (foundation5–32/35–55; durable5–14/17–24; runtime5–32/35–61). Root25 runs the first replay, root18 the second, and durable68/root15 the query-plan script. Isolated edits can therefore select none of their owning checks; another changed file can mask the gap. Minimum proposal: add the first two paths to both foundation filters and the third to both durable filters. This increases coverage and may increase runs; it is independent of consolidation. No missed product defect is inferred.
2. **D5–7 visibility:** give browser, TS vectors, Rust/Wasm and operator/replay stages explicit names while preserving the complete command list, environment and failure semantics of root25. Either keep `pnpm check` locally and expose equivalent CI stages, or add log groups first. Do not add duplicate executions merely for headings. Step splitting helps diagnose failures and measure duration; it does not itself reduce work or add coverage. Preserve foundation81's actual-Function test and explicit stress controls.
3. **Harmless-document fast path:** consider a deliberately narrow allowlist initially covering only current-state/work-index pointer edits. Run relevant secret/reference/integrity checks and review, with unknown paths falling back to full verification. Do not exempt all `docs/**`: authority/fixtures/manifests/historical integrity inputs may affect executable acceptance. Retain full checks for behavior/trust/money/concurrency changes and milestone/release integration.
4. **Deduplicate deliberately:** first run broad style/API/boundary checks once per candidate, then assess whether one full database job plus focused runtime PostgreSQL/roles/process/image controls is sufficient. Keep the existing comprehensive route as an explicit fallback until measured equivalence passes. Shared artifacts or affected-test selection add coupling and maintenance; saving a24-second build is not automatically worth that complexity. Do not remove actual LOGIN, tenant, financial immutability, crash/restart or deletion-reconciliation tests to hit a size target.

Before changing path filters or required job names, inspect effective repository protections. [GitHub workflow documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onpushpull_requestpull_request_targetpathspaths-ignore) warns that a path-skipped required workflow can remain Pending. [Job conditions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-jobs-with-conditions) behave differently: a skipped job reports Success. Use an explicit fail-closed classifier/aggregate check or preserve required contexts with visible “not selected” reporting; never describe skipped suites as passed. One bounded read-only live check, `GET repos/Optidigi/insignia/branches/main/protection`, returned404 with “Branch not protected”. This establishes only the absence reported by that classic-protection endpoint; effective repository/organization rulesets and their required contexts remain unverified. Do not infer unrestricted merging or implement documentation `paths-ignore` from that result.

Recommendation: fix selection holes and add visibility first; introduce the narrow documentation path next; measure a few representative behavior changes before consolidating overlapping commands. These are research alternatives, not approved rewiring or delivery actions. No test-LOC quota, new infrastructure, scope widening or native effect is proposed.
