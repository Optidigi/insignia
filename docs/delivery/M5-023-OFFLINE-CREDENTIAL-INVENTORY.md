# M5-023 — expiring offline consumer inventory

**OFFLINE_BOOTSTRAP_DEFERRED_NO_M5_BACKGROUND_CREDENTIAL_CONSUMER.** This slice implements permanent managed-install tenant/generation bootstrap. It does not silently claim that an expiring offline credential pair is obtained.

| Consumer | Actual credential/lifecycle | M5 dependency |
| --- | --- | --- |
| [Production admin](../../apps/web/src/server/admin/production.ts), catalog, subscription admission and v3 activation | Per-request verified online staff grant; private actor weak-map; expiry and current-generation checks around provider reads. Activation runs in the staff request and has no background continuation wired here. | Online staff authorization required; no offline dependency. |
| [Worker handlers](../../apps/worker/src/handlers.ts), [runtime](../../apps/worker/src/runtime.ts) | Existing encrypted `core.credentials` single-flight refresh handler for an already stored pair; `enqueueRefresh` is available but first-session/admin Search does not enqueue it. Uninstall deactivation is durable local work. | No first-session/background Admin API work scheduled by this slice. An absent pair remains absent/unusable, never an online-grant substitution. |
| [Quote composition](../../apps/web/src/server/quote-composition.ts), contextual pricing/shop/variant reads | `createQuoteAuthorityPorts` requires an injected `AdminCredentialSource`. Source search finds its definition but no production composition caller. | Later storefront/App Proxy/quote runtime must obtain an expiring offline pair through M3 before enabling persistent Admin reads. No M7 wiring here. |
| Future activation/reconciliation outside a staff request | Not enabled by this web composition. Historical operator/recovery evidence does not confer a background credential. | Must use M3 encrypted expiring offline access, generation/version/claim fences and refresh before independent scheduling is authorized. |

The existing [encrypted repository](../../packages/database/src/repositories/shop-credentials.ts), [envelopes](../../packages/database/src/credentials/envelope.ts) and [refresh lifecycle](../../packages/application/src/shopify/offline-credentials.ts) remain unchanged. Reinstall still revokes the old generation's credentials through reviewed `startInstallation`. Tests include existing M3 refresh/revoke/claim regression coverage. No second store, offline exchange on every authentication, token logging or offline staff authorization is introduced.

M5 admin/G7 can safely establish tenant identity and perform current staff-authorized Search without an offline pair. Persistent background Admin consumers remain disabled/unwired or fail closed without usable M3 credentials. This is the explicit independently staged option in section2 of the supplied M5-023 brief; it is not acceptance of a later public-app background flow without offline access.
