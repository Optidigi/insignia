## Captured-body threat result

The real built HTTP ingress and production worker were exercised with a synthetic signed Shop payload. Generation1 was durably uninstalled; generation2 was created through the reviewed tenant lifecycle. Reusing the captured body and original HMAC with the original delivery ID and changed trigger produced 503 conflict. A new delivery ID with the original trigger remained stale. A changed header pointing at another existing Shop was unverified and did not deactivate that Shop. A new delivery ID plus a trigger later than generation2 activation bound the old signed body to generation2; the production worker then deactivated generation2 and marked that new inbox processed.

This demonstrates a local semantic boundary failure under the stated capture/replay capability. It does not establish that a public attacker can obtain a production body/HMAC pair, modify a genuine Shopify TLS delivery, or exploit a real installation. An attacker with such a captured pair can submit an independent HTTPS request to the public ingress without knowing the signing secret; TLS protects original transport but does not cryptographically authenticate those replayed routing headers. The verifier already documents body-only authentication. No accepted repository predicate, signature document or historical evidence has been changed to conceal the result. The passing characterization test means **reproduction confirmed**, not security PASS.

The smallest correction needs principal approval: separate receipt admission from authority to invalidate a newer generation, and require independent authority before acting on unsigned timing across generations. A body-fingerprint tombstone alone may reject a legitimate later uninstall whose signed Shop payload is identical; no such semantic change is implemented. An exact provider current-installation observation might supply authority but needs a separately reviewed credential/absence/error policy and may be unavailable after uninstall. No provider request was attempted to decide this. Existing bootstrap also consumes delivery timing; a successor must assess that shared boundary without silently rebuilding its accepted contract.
