# Shopify product CSV import research

Checked 2026-11-08 against Shopify Help Center pages. This note supports catalog-only updates in `insignia-rewrite-dev`; no Shopify or Superfunny changes were made during this research.

## Official guidance

- [Using CSV files to import and export products](https://help.shopify.com/en/manual/products/import-export/using-csv) is the canonical field and overwrite reference. Shopify says older CSV templates with different column names remain backward compatible, while recommending the current format. Use one exact template/header family consistently: header names are case-sensitive, and old and new versions of a single field must not both be present. One explicit legacy example is `Barcode`, which is normalized to `Barcodes` on export; having both columns makes an import fail.
- [Importing products with a CSV file](https://help.shopify.com/en/manual/products/import-export/import-products) documents the admin flow and overwrite option. It warns that an import cannot be canceled after it starts and that there is no import history; product data should be backed up first. It also warns that spreadsheet sorting can detach image URLs from their intended rows.
- [Solutions to common product CSV import problems](https://help.shopify.com/en/manual/products/import-export/common-import-issues) covers exact headers, duplicate option tuples, stock-tracker requirements, direct image URLs, and encoding errors.
- [Adding images to product variants](https://help.shopify.com/en/manual/products/product-media/add-images-variants) states that each variant has one assigned preview image; the gallery can still hold additional photos.
- [Adding product media](https://help.shopify.com/en/manual/products/product-media/add-media) notes that a CSV import can succeed while skipping images, without reporting those skips. It also requires direct, publicly accessible file URLs for URL-based media.

## How to update the owned QA drafts

Use only the five existing DEV QA products by their current destination handles. Match the handles from the DEV export/product IDs; do not use source Superfunny handles or derive a destination handle from a title. The owned records are cap `10590373970203`, hoodie `10590396317979`, polo `10590396350747`, trui `10590397694235`, and dames T-shirt `10590398152987`. Keep the protected rich T-shirt fixture `10588458647835` out of the CSV. The unisex T-shirt is the one missing catalog copy.

Select **Overwrite products with matching handles** for those existing QA records. If it is off, Shopify ignores matching handles; if the CSV uses source handles, it can create additional products instead of updating the QA drafts. Shopify's documented overwrite is column-based: blank included non-required cells clear existing values; columns omitted from the file preserve existing values. Include every field intended to replace and omit fields that must remain untouched. Avoid changing option names/values: Shopify warns that changing option values deletes and recreates variant IDs. Shopify's docs describe overwrite matching by product handle but don't promise automatic deduplication of duplicate variant rows, so validate unique option tuples in the CSV and verify final counts after import.

Before import, export/back up only the owned target records and verify their handles against the IDs above. Keep each product's exact current option names and one row per source-confirmed available option tuple. Reuse the existing DEV option axes and exact values; do not create the Cartesian product of color and size lists. The source unisex T-shirt, for example, has only white XS–5XL while the other colors extend through 7XL, so white 6XL/7XL rows must remain absent. Shopify's own variant guidance likewise uses one CSV row for each real variant combination and repeats the product handle for those rows.

The current guide calls the fields `URL handle`, `Option1 name`, `Option1 value`, `Price`, `Inventory tracker`, `Product image URL`, `Image position`, and `Variant image URL`. Older product templates commonly use `Handle`, `Option1 Name`, `Option1 Value`, `Variant Price`, `Variant Inventory Tracker`, `Image Src`, `Image Position`, and `Variant Image`. Shopify documents backward compatibility for older templates, but the import troubleshooting guide says headers are case-sensitive. Prefer the exact current header set from the downloaded Shopify sample; if using an older exported template, retain its exact headers rather than mixing header generations or hand-lowercasing names.

## Draft status, price, and inventory settings

- Include the current `Status` field with value `draft` for each QA product. Shopify defaults status to `active` when the field is omitted. If using a legacy template with `Published`, set it to `false`; product status and sales-channel publication are separate fields. Keep the import dialog's new-product publication option disabled, and verify the resulting products remain Draft.
- The current `Price` field accepts a numeric amount without a currency symbol. Shopify applies that amount in the destination store currency. The DEV store is USD: QA example amounts must not be presented as conversions of the inventory's EUR source prices. Retain the exact EUR source amount separately in the source inventory. Do not roll Insignia method/placement charges into Shopify variant price.
- Leave `Inventory tracker` blank (legacy header: `Variant Inventory Tracker`) to disable inventory tracking. If set to `shopify`, Shopify requires a numeric inventory quantity and related inventory/fulfillment values; the help page says a blank tracker means inventory is not tracked. Therefore an untracked draft is not the same state as a tracked variant with an actual zero balance. Keep the records Draft and untracked as requested; do not set a fulfillment service.

## Media rows and variant-image mapping

For each product, put its product-level fields on its first variant row, then repeat the exact handle on each further variant row and leave product-level descriptive fields blank on continuation rows. Shopify's format has a separate row for each variant. For extra gallery images, add one row per image with the same handle and the image URL; set `Image position` in intended ascending order starting at 1. Shopify allows up to 250 gallery images per product.

Use `Product image URL`/legacy `Image Src` for gallery photos and `Variant image URL`/legacy `Variant Image` for the single color preview assigned to each variant. For a color-specific preview, use the exact same public image URL in a gallery image row and in each applicable variant row; do not infer image orientation from a filename or use a view mockup as the product gallery unless the inventory maps it to that role. Shopify downloads and re-uploads URL images into the destination store. Direct URLs must be publicly reachable HTTPS image files. Avoid preview/share pages and temporary signed URLs. Check source image URLs for actual direct image responses and no credentials or signed query parameters before building the CSV.

After import, inspect every owned product from a fresh page/export: exact title/handle, Draft status, all exact option tuples and prices, untracked inventory, gallery count/order, and variant preview assignments. Do not treat Shopify's success banner as proof that all media imported; Shopify documents that missing CSV images may be silently skipped. Stop before starting the import if the preview indicates unexpected product/variant counts, new products instead of matching QA products, or Active status. After starting, don't retry based only on uncertainty; first inspect the import result and current target records.

The CSV covers Shopify product catalog fields only. It does not configure Insignia views, image assignments, placements, methods, method/placement pricing, geometry, calibration, or customizer behavior; those remain in the Insignia configuration lane. Source pricing/config facts in [legacy-inventory.json](legacy-inventory.json) remain provenance and must not be flattened into the QA catalog example prices.

## Evidence limits

Shopify's public documentation describes matching products by handle and the destructive effects of omitted option data, but it does not specify a variant-row reconciliation algorithm or promise duplicate-variant deduplication. Treat uniqueness as a CSV-generation invariant and verify post-import counts and option tuples. Shopify's troubleshooting page says duplicate option values can fail validation, and its migration guidance states a product with variants needs one row per combination; neither substitutes for post-import verification in this DEV store.
