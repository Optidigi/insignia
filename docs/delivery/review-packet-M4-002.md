## Accepted-quote authority

The server-only `createQuoteAuthorityPorts` connects active M3 installation identity and effective activated publication, M4-001 tenant-bound subscription policy and read-only Admin context/catalog, M2 whole-order pricing, finite currency admission, and an injected whole-quote signer to immutable PostgreSQL acceptance. Canonical M2 Product and Variant IDs are Shopify numeric suffixes; the composition converts to exact GraphQL GIDs for verified provider reads and maps trusted prices back before pricing. No buyer value supplies an effective publication flag, shop currency, or catalog price. Desired country is checked against the finite 249-code ISO 3166-1 alpha-2 snapshot in IANA `iso3166.tab` (source cites ISO/TC 46 N1127, 29 February 2024; source SHA-256 `837c80785080c8433fd9d4ea87e78f161ac7a40389301c5153d4f90198baeb2a`), excluding reserved `XX`, `ZZ` and `XK`. The country and strict numeric/Market GID are locked into the signed quote; the complete Transform and Validation compare them with Shopify's actual localization. Mixed presentment currencies, unsupported exponents, stale context, unknown entitlement, missing effective revision, selling plans, required unconfigured FX and candidate cap violations fail closed.

The fixed quote records the UTC acceptance instant, trusted shop IANA timezone, local civil day ordinal, and D+2 calendar-day validity; its quote ID, complete M2 pricing amounts and allocation in the explicit `m4-quote-economics-v1` persisted projection, normalized physical group projection, effective revision hashes, contextual snapshots, exact FX provenance when needed, policy projection and generation/epoch are persisted atomically with one signed authorization set. The transient M2 result retains its canonical customization identity for pricing; the persisted projection replaces every artwork-linked identity in both groups and lines with `canonicalIdentitySha256` so immutable financial/audit rows do not retain buyer artwork references. A trusted artwork port must attest the exact tenant/install-bound choices as usable through the entire D..D+2 shop-local window, with a fresh UTC observation. The service checks it before constructing the quote and again inside the serialized transaction before signing; only choice digests and the attested local-day bounds are persisted. The default server composition fails closed until a production artwork authority exists. Idempotent retry returns the original accepted quote/set while its generation and epoch remain current; the replay query locks and compares the current installation row, so a caller holding a stale prior epoch cannot replay an old set across a committed revocation. The repository serializes same-key acceptance with locks on the active shop and installation rows, including against a concurrent epoch update, rechecks activated effective revisions, and uses immutable DB rows/triggers. Tenant and entitlement are rechecked after provider reads before signing/persistence. Installation authorization UUIDs are generated by PostgreSQL, unique per generation, safely backfilled, immutable, and paired with checked u32 epochs. See the [synthetic signed quote example](evidence/m4-002/synthetic-accepted-quote.json): a signed negative one-cent unit adjustment and three-cent setup charge on a zero-dollar base produce exactly USD 0.01 total, split deterministically into USD 0.01 and USD 0.00 final units, accepted New York 1 November 2026 through 3 November, with two canonical v2 member carriers and a deterministic synthetic test public key. It is not a live quote. An independent PostgreSQL 18 test uses the same adjustment scenario through the actual application authority and durable facade, verifies the signature and exact persisted quote/carriers, and proves same-key retry without a second signature.

The production-owned TypeScript authorization package preserves the original v2 domain, 92-byte header, 22-byte member, carrier names, and complete-set sign bytes. It uses a signer interface with an injected Ed25519 private-key provider and requires an unrevoked key window covering all of D..D+2. It rejects noncanonical padding, flags, bounds, duplicate/missing indices, mismatched totals and unknown currency/exponent combinations before signing. Candidate admission caps 32 buckets, 200 total line hints, 10,000 customized physical units and 16,000 output bytes; an iterative pre-provider input traversal caps nested JSON depth, node count, and bytes before canonicalization. Cart count/input hints are availability only. The finite [currency matrix and primary ISO provenance](evidence/m4-002/currency-matrix.md) are shared with Rust; `BGN`, `XXX`, `USDC`, `MGA` and `MRU` are excluded. The synthetic OXR Developer adapter pins the exact host/path, lexical positive rates, publication timestamp, freshness, pair, redirect/body/time bounds and explicit errors without fallback. It made no actual OXR request and does not activate automatic FX.
