# Daily encrypted backup and isolated recovery

This runbook defines daily encrypted backup, retention and isolated restore mechanics. [Delivery state](../../docs/delivery/state.md) owns installation/qualification status, recovery targets, permissions, remaining actions and exact cleanup deadlines. The operator never starts application services or restores into the running database/bucket. A local test or DB-only safety snapshot is not complete object/off-host recovery evidence.

`node --test scripts/operations/backup.test.mts` exercises actual OpenSSL authenticated encryption/decryption, byte-for-byte original recovery, retention and isolation admission. `node --test scripts/operations/backup-snapshot.test.mts` covers paginated inventory, missing/unaccounted objects and lifecycle/reference behavior. `BACKUP_PG_TOOLS=/path/to/existing/pg18/bin node --test scripts/operations/backup-integration.test.mts` creates and removes its own private Unix-socket PostgreSQL18 cluster, applies all current migrations, runs real snapshot SQL, dumps/encrypts/restores to a new database and imports actual owner exclusions, then runs the existing rich customer/shop erasure and immutable purchase regression.


Populated historical activation records require the shipped bounded validator-namespace correction. Recovery renders pre-data, correction, data and post-data SQL into private tmpfs, then executes them in one PostgreSQL transaction through `psql`; global restore search-path hardening and CHECK constraints remain enabled. The correction preserves helper bodies and actual historical rows and does not advance the restored migration ledger. Specify `--psql` with the matching PostgreSQL18 client where tools are outside PATH. Success and failure both erase decrypted dump/tar/SQL scratch; failed recovery retains HOLD and exposes no service.

## Prerequisites and exact snapshot contract

Install a reviewed immutable operator/runtime, the Node binary pinned by the qualified artifact and bundled archive dependency notices, util-linux `flock`, OpenSSL supporting CMS AES256-GCM, matching PostgreSQL18 client tools and the existing Node24/privacy import dependencies. Use a dedicated OS account, private mode0700 directories and mode0600 pgpass; source PostgreSQL identity needs the qualified backup read grants only. Use PGHOST/PGPORT/PGUSER/PGDATABASE/PGPASSFILE privately; never supply a connection URI in argv. The recovery identity is a separate isolated schema owner. No new database grants are issued by this operator.

Provision an RSA recipient certificate outside the repo. Backup receives its public certificate only; keep the private recovery key in separately controlled custody. Qualify certificate expiry, rotation and actual decryption before scheduling. CMS AES256-GCM provides authenticated ciphertext; receipts' SHA256 values detect accidental corruption, not source authenticity. Protect receipts and the snapshot manifest as trusted administrative inputs.

The supplied `backup-snapshot.mts` producer performs a bounded read-only source export using the existing private R2 adapter and its pinned aws4fetch signer. It queries current-schema artwork/merchant-preview references and private-payload deadlines, paginates signed ListObjectsV2 requests under exactly the configured bucket/prefix, rejects duplicate/repeating/oversized inventory, missing required keys and any unaccounted key, reads actual bytes, checks available immutable hashes and writes an exclusive private manifest. Inspection/promotion/deletion/rejection, inactive generations or merchant WRITING/RETIRED work must settle before capture. Incomplete uploads retain the original collected+24h cleanup deadline; any remaining reusable quarantine for a USABLE asset cannot outlive upload_until and puts capture on HOLD if cleanup is already due. UPLOADING/PREPARING objects are optional until created; retained USABLE originals/previews are required. Referenced active merchant previews retain their live configuration meaning rather than treating the unreferenced abandon deadline as expiry. Before scheduling:

1. Configure the supplied `backup-run.mts` wrapper with the complete exact allocated Insignia Compose writer list. Its private reviewed config pins project, container name/ID, image ID, configuration fingerprint and health requirement for each web/worker/inspector/verifier/maintenance writer. The example deliberately has invalid placeholders. The existing inspector owner UID1000/serveradmin runs host maintenance with its existing Docker/user-manager authority; the application receives neither socket. The wrapper preflights all identities before stopping anything, obtains an exclusive durable operator lock, journals stop/start intents, stops only originally running named writers, verifies exclusion repeatedly through capture/dump, creates the finite fsynced window, then closes it before resuming only the exact originally running containers. Previously stopped writers remain stopped. Unknown Docker stop outcomes, identity/restart drift, timeout or failed health recovery require operator settlement; no ambiguous stop/start retry occurs. SIGTERM cancels capture, dump and off-host replication clients, prevents success after interruption and attempts safe acknowledged-writer resume. SIGKILL/reboot requires inspecting the durable journal and settling state before another run. Under its permanent journal lock, every new run first scans prior journals: any stop/start intent without an exact atomic terminal acknowledgement bound to that run's preflight/container/original-state identities blocks all new Docker effects, even when systemd has removed /run. No-effect preflight-only interruptions are safe to pass. Preserve unresolved journals; after independently reconciling each exact writer and original health/state, the operator must record an exact terminal acknowledgement before admitting a new run. Never clear a HOLD by deleting the journal or assuming an exited container was originally stopped. Do not pause cleanup across any actual deletion deadline.
2. Supply PGHOST/PGPORT/PGUSER/PGDATABASE/PGPASSFILE for the source backup identity; alternate PGSERVICE/PGSERVICEFILE/PGHOSTADDR/PGOPTIONS/DATABASE_URL, multihost inputs and URI-style database overrides are rejected before any Docker effect, direct dump or exporter credential/provider read so Node pg and libpq cannot select different sources; `ARTWORK_R2_ENDPOINT`, `ARTWORK_R2_BUCKET`, `ARTWORK_R2_PREFIX` and a mode0600 `ARTWORK_STORAGE_PROFILE` containing accessKeyId/secretAccessKey for a separately qualified **read-only** scoped R2 credential. The exporter permits HTTPS account R2 endpoints only, validates key/prefix syntax and never PUTs/DELETEs objects. Configure the dedicated rewrite allocation explicitly; do not point it at another application's bucket. Invoke `node scripts/operations/backup-snapshot.mts EMPTY_PRIVATE_TMPFS_DIRECTORY NEW_MANIFEST PRIVATE_QUIESCENCE_FILE`. The finite mode0600 quiescence file is `{id, startedAt, until}` and must represent actual externally held service exclusion. CLI capture rejects nonempty/nonprivate/non-tmpfs destinations. The supplied service runs the wrapper, which invokes this producer before every dump; no external finite-window producer is required.
3. The producer supplies a manifest with `format: insignia-offline-object-snapshot-v1`, `quiesced: true`, `capturedAt` (UTC, at most one hour old), `databaseExpiresAt` (earliest applicable deletion deadline of private database payloads), `absoluteExpiresAt` (earliest original private collection+6calendar months), explicit `promisedCleanupAt` (UTC or reviewed null), and `objects: [{key, sha256, expiresAt}]`, plus the finite quiescence identity/window. Keys are relative exact object keys; SHA256 is of actual bytes. Expiry is the existing deletion deadline, never a newly invented backup lifetime. Reject a manifest that omits retained objects or deadlines. Empty objects is legitimate only for a truly empty qualified source.

`create --store PRIVATE_STORE --scratch PRIVATE_TMPFS --objects SNAPSHOT_DIR --object-manifest MANIFEST --recipient PUBLIC_CERT` validates paths, hashes and deadlines, obtains a PostgreSQL custom dump, archives actual object bytes, encrypts and writes fsynced ciphertext plus immutable mode0600 intent/completion receipts. Source checksums are checked again after copying. The same quiescence window must cover capture, dump and final completion; expiry/window are rechecked after work. Receipts include start/completion times and database dump SHA256; restore checks archive/receipt UUID names and extracted dump integrity. A global file lock prevents overlapping create/prune. No success receipt is emitted after tool failure. Receipts publish atomically without replacement; malformed independent sidecars cannot block valid expired artifacts from being pruned, but retain an explicit failure for operator inspection. Failed or interrupted intents are distinguishable from completed snapshots. The operator enforces tmpfs for plaintext scratch and source snapshots; configure no swap/core dumps and sufficient bounded capacity; raw DB/object bytes exist there temporarily. Systemd `/run` is expected to satisfy this on a qualified host. Linux stat/statfs verify filesystem type before work. A killed process can leave plaintext scratch files: the operator must remove them before restarting; service restart removes its RuntimeDirectory.

The owner-approved isolated encrypted archive exception permits seven days even when ordinary payload/object expiry occurs sooner. Each **new** snapshot expires at start+7days, capped by `absoluteExpiresAt` derived from original private collection+**six calendar months** in PostgreSQL and any already-promised `promisedCleanupAt`. The reviewed runner must explicitly supply promisedCleanupAt (null only after reviewing that no earlier recorded cutoff applies); direct exporter requires BACKUP_PROMISED_CLEANUP_AT (`none` or exact UTC cutoff). Existing receipts/archives are never extended or rewritten. Inner databaseExpiresAt and each object's existing expiry remain unchanged, and neither source cleanup nor actual promised deadlines are relaxed. A shorter absolute/promise cap physically expires the whole ciphertext archive. Normal original/private live expiry is deferred only inside this encrypted isolated copy, with mandatory actual erasure **and expiry** replay before any restored access.

Run local and remote `prune` at least every minute and before recovery. They delete only independently owned expired artifacts; partial-intent archives retain their original deadline. Qualify timer/deletion delay against actual promises and alert on overdue/unknown cleanup. No archive rotation resets original collection or promised cutoff. Financial/purchased facts are dumped unchanged, never zeroed or repriced.

The deployed development topology uses separate Compose projects. Each container entry may pin its exact `project`; omitting it uses the top-level project. The top-level value groups the backup allocation and never substitutes for an entry's actual project label. Names, IDs, image IDs and complete configuration fingerprints remain mandatory. Do not rename working services to satisfy a backup template.

Include the owner-approved host inspector through `hostInspector`, under its existing UID1000 user manager. The adapter controls only `insignia-artwork-inspection.service`. Freeze its `configSha256` independently from read-only `InspectorService.inspect()` output using the populated startup/storage/socket paths. The identity includes loaded service configuration/security, unit/drop-in/startup/storage/manifest hashes and readiness directory identity; values stay private. The operator independently verifies every pinned artifact file/link, including Node and bootstrap bytes, before effects and restart. It rechecks invocation/PID/start ticks immediately before stopping, drains with the existing infinite service timeout, and refuses a capture while its process, socket or sandbox jobs remain. A bounded client timeout leaves durable HOLD and never authorizes forced termination or restart. Recovery starts only an originally active inspector, requires a new ready invocation, then resumes containers; unknown inspector state holds container recovery too. An originally inactive inspector stays inactive. The supplied services use the existing inspector owner UID1000/serveradmin and explicitly bind its user bus. ProtectHome=read-only permits reading pinned home-based artifacts/private startup profiles while keeping them unwritable in the maintenance namespace. All CLI paths share the installed artifact root /opt/insignia/runtime; populate that prefix with the reviewed version before enabling. Qualify the user-bus environment with read-only service inspection before allocating a drain.

`node --test scripts/operations/backup-run.test.mts` checks split-project identity admission, host inspector drain/readiness/replacement and artifact tampering, failure resume, preservation of previously stopped writers, and process interruption/uncertain-stop HOLD after runtime-directory recreation for both writer types. Read-only service inspection never proves native backup drain/resume. Install the reviewed immutable runtime/tool paths and private populated `backup-run.json` before enabling. The container fingerprint covers Id/Name/Image/Config/HostConfig/Mounts with canonical sorted compact JSON SHA256; generate it from reviewed inspect data without logging environment values. Include every source writer in the exact allowlist. RuntimeDirectory is dedicated tmpfs; receiptDirectory is separately durable mode0700.

Templates are not enabled automatically. Daily `create` needs a fresh qualified snapshot for every run; yesterday's manifest fails. The minute pruning timer must operate independently of daily backup success. Monitor completion freshness (>24h is failure), nonzero tool exit, stale/incomplete intents, disk capacity, missed pruning and actual deletion. A local ciphertext copy is not disaster recovery. ## Isolated restore and mandatory HOLD

Use a fresh dedicated PostgreSQL18 cluster on a private Unix socket, with no web/worker/inspector/provider/storage credentials or network access. Set PGHOST to its absolute socket directory and PGDATABASE to a **new** `insignia_recovery_[a-z0-9_]` database name; unset DATABASE_URL/PGSERVICE/PGSERVICEFILE/PGHOSTADDR. Restore rejects alternate host authority and multihost lists and sanitizes all child libpq environments, including PGOPTIONS. `createdb` refuses an existing target. The name/socket admission is not a network sandbox: independently enforce isolation and verify there are no connected services. The host must retain original database roles/ACL definitions separately; the dump restores database objects/ACLs and does not invent cluster roles or grants.

Run `restore --artifact CIPHERTEXT --receipt RECEIPT --identity PRIVATE_KEY --destination EMPTY_PRIVATE_TMPFS --exclusions LATEST_PRIVATE_EXCLUSIONS`, selecting matching PostgreSQL tools if needed. This rejects expired/corrupt archives, unsafe members and network/normal-runtime target names. It decrypts and validates historical staged object bytes without resetting original deadlines, restores once with exit-on-error/single transaction, then invokes the existing owner-only `scripts/privacy/restore-exclusions.mts import` against that isolated target. It next executes `backup-expiry.mts` under the offline restored schema owner: current buyer/purchase expiry functions, source-bound webhook expiry functions, expired generic transport payload erasure, and inaccessible artwork/merchant-preview deletion staging. The loop drains current inactive-generation cleanup as well as timed expiry; no historical expiry/collection or economic fact is rewritten. The typed operator removes expired/fenced actual staged object files, removes decrypted tar/database scratch and filters excluded object entries from the staging manifest before writing the sanitized result. This is execution, not a marker-only replay claim. A failure leaves HOLD and requires bounded private tmpfs cleanup; no failed plaintext scratch is granted seven-day retention. Supply a **fresh authoritative** exclusions export (coverage must be after backup completion and at most15minutes old at admission) kept separately from backups, with qualified completeness and continuity through source shutdown. Its checksum alone proves neither freshness nor authenticity. A failed step leaves the target and HOLD marker for inspection; do not retry by overwriting it. Start with a different new target after diagnosis.

Success still reports `HOLD_STORAGE_ERASURE_AND_AUTHORITY_REQUALIFICATION`. Objects are staged only, never uploaded or made available. Actual erasure+expiry replay has run, but real storage cleanup/authority/public readiness still requires separate qualification. Reconcile remaining staged objects against restored erasure fences AND current expiry/retention before any private-bucket import; remove erased/expired objects and execute existing cleanup to terminal state without changing purchase/economic history. Requalify roles/secrets/rotation, installation/provider state, release authority, schema/runtime image identity, originals/previews and actual private storage cleanup. Never restore into the active bucket or replay external mutations. The latest pending/blocked privacy requests preserve their meaning. Do not expose service until independent recovery acceptance; no command here removes HOLD.

Closure evidence and remaining native actions belong to the [current checklist](../../docs/delivery/state.md). Restore acceptance must observe actual object reconciliation/reimport, preserved purchase facts, off-host loss recovery, measured RPO/RTO, interruption/deletion behavior and key custody; no procedure here clears HOLD or grants production access.

## Off-host encrypted archive replication

`backup-replica.mts` uses the existing pinned aws4fetch signer, resolved from the real storage package path. It streams **only completed encrypted `.cms` archives**, with original source receipt SHA256, byte length and expiry, up to the explicit1GiB bound. It never sends raw database dumps, originals, signing/decryption keys or source bucket credentials. `node --test scripts/operations/backup-replica.test.mts` covers the injected HTTP transport boundary: actual ciphertext byte/hash roundtrip; deadline-before-body ordering; remote completion/readback; lost upload response/no redispatch; foreign/conflicting objects; expired/corrupt restore refusal; and owned expiry pruning. These are local transport fixtures, not actual provider qualification.

Provision a separate explicitly authorized private backup bucket or disjoint prefix and credential profile. No bucket/resource grant is inferred by this source or the example. Source and target namespaces must be declared separately and must not overlap. Grant the replica operator only target list/read/create/delete authority; source object credentials remain separate. Require an exclusively controlled immutable target prefix: no other actor may overwrite its objects. The script never assumes conditional DeleteObject support. Conditional create-once PUT is documented by [Cloudflare R2 extensions](https://developers.cloudflare.com/r2/api/s3/extensions/); the signer is used directly with one fetch, without AWS retry dispatch.

Install a mode0600 populated `backup-replica.json` from the invalid-placeholder example, mode0600 credentials, and mode0700 durable replica journalDirectory. `replicate CONFIG` accepts only private completed local receipts and same-UUID matching archive files. It writes a local immutable reservation before dispatch, then a remote `UUID/intent.json` with the **original expiry** before the archive. Every PUT uses `If-None-Match: *`; conflicting objects are never overwritten. It verifies remote archive actual streamed SHA256/size and exact intent/completion receipt, then atomically publishes a local `UUID.complete.json` with source hash/size/expiry/completion time, actual configured remote identity and verified replication completion time. A request-sent response alone cannot create this marker.

A lost or failed write leaves its original local/remote intent and HOLD. A second invocation never resends an unsettled mutation, even after a negative GET; a complete matching remote receipt+intent+actual ciphertext readback may settle an already committed copy using **read-only** evidence. Preserve unresolved reservations for operator settlement. Do not generate a new UUID simply to retry an unknown copy. The wrapper invokes configured replication after resuming the known original writers. `replicaRequired: true` without replicaConfig fails before any writer stop. Without configured replication it reports `LOCAL_BACKUP_ONLY_OFFHOST_UNCONFIGURED`; no off-host completion is claimed. When replication is required, configure the heartbeat collector to require the exact matching verified replica completion marker before it treats a local backup as fresh.

`prune CONFIG` paginates only the allocated backup prefix, preserves unknown/orphan/conflicting identities on HOLD, and prunes independently valid expired archives without extending source deadlines. A remote conditional deletion intent precedes deletes. Delete errors/unknown responses leave the deletion marker on HOLD rather than retrying an uncertain mutation. Expired intent-only copies with no committed archive remain held because absence cannot prove a prior PUT will never commit. Exact remote intent and atomic archive ownership metadata (UUID/source SHA/original expiry) qualify deletion; payload corruption cannot extend a known-owned archive's retention. Unknown/conflicting ownership metadata remains HOLD. Ciphertext is deleted before metadata. Minute pruning atomically writes private `replicaJournalDirectory/retention.json`: exact remoteIdentity plus observedAt with overdueCount null before work (including failed credentials/provider work), and0 only after fully qualified success. Required-replica heartbeat must treat missing/stale/null retention evidence as unknown; DB/local deletion success cannot mask a held remote copy, and the collector must match the configured exact remoteIdentity to prevent evidence from a different namespace refreshing health. Enable the separate minute replica pruning timer with alerting for missed/overdue/held cleanup; native deadline compliance is still an observed operational requirement, not proved by a timer template.

`download CONFIG UUID NEW_PRIVATE_DIRECTORY` validates live completed remote identity and actual ciphertext SHA/size, writes a new mode0600 encrypted archive/source receipt plus HOLD marker, and never decrypts or imports objects. Supply the retrieved `.cms` and original source `.json` to the existing isolated restore with a **different empty private tmpfs destination**, private recovery key and fresh authoritative exclusions. Private source data remains unavailable until erasure/expiry/provider/runtime requalification. Qualify loss-recovery timing, scoped remote credentials, conditional-write behavior, retention/deletion interruption and separate key custody under the current checklist before claiming disaster recovery.
