# Immutable inspector artifact — owner-approved host-service exception

This package provides the existing production worker inspection entrypoint/dependencies and the Node executable pinned by packaging source. It changes no inspection algorithm, grants, storage bucket/prefix, socket protocol or sandbox mechanism. CI creates a versioned tar preserving modes/internal symlinks, source head/tree, exact file inventory, manifest digest and generated service digest. Uploading a raw directory would lose executable/private modes; use the tar.

`node scripts/ci/package-artwork-inspector.mts EXISTING_PORTABLE_WORKER NEW_DESTINATION` performs offline code packaging. `bin/node start.mts --manifest-sha256 EXPECTED --verify-only` qualifies relocation/integrity without loading private settings, DB, storage or artwork inspection. The expected digest comes from reviewed CI receipt/artifact provenance, never from a caller-supplied environment value. The generated unit binds that literal digest and immutable release directory to the reviewed source tree. The unit template is itself included in the code inventory; independently verify the rendered unit against its receipt before installation. Host libraries, user manager, sandbox policy and real jobs require qualification on each changed deployment boundary; current deployment observations are recorded in [delivery state](../../docs/delivery/state.md).

## Host-service exception and private custody

Keep one Insignia-specific `serveradmin` user service outside Docker because the current runner deliberately delegates each hostile artwork job to existing host `systemd-run --user` cgroups and approved `/usr/bin/bwrap` network/mount/PID isolation. An ordinary least-privilege worker container cannot supply that contract. This exception does not mount host DBus/Docker sockets into a container, add capabilities, change global policy, or affect another application. Web/order worker/public routing remain versioned Docker/Compose/Traefik. The effective narrow host-service exception is recorded in the [operating model](../../docs/delivery/operating-model.md). Packaging or a previous handover never qualifies all recovery/monitoring or rollout boundaries.

Qualified install identity: `%h/insignia-artwork-releases/<reviewed source tree>/` containing the verified artifact; generated unit remains `insignia-artwork-inspection.service` in the same user manager, UID1000. Private startup configuration resides at `%h/.config/insignia/artwork-inspection.env`, outside the artifact, owned by serveradmin mode0600. Preserve the existing effective private configuration/storage profile; packaging performs no native move.

Keep existing inspection-only DB login, scoped R2 profile, allocated endpoint/bucket/prefix and readiness directory inode, socket protocol and private modes. Verify old-process exit and socket absence before replacement; a new socket may reuse an inode. No Shopify/Partner/wrapping/queue credentials. Unit unsets those variables and dynamic loader/Node/proxy injection; storage profile must be an external regular0600 owned file. Existing account lingering and exact scoped AppArmor profiles stay unchanged. Service cgroup keeps512MiB/no swap/one CPU/64 tasks; each hostile job retains256MiB/16 tasks/10second runtime, all namespace isolation and no unisolated fallback. No auto-restart or blind socket removal; stop waits for existing bounded effects to settle.

The bootstrap is `start.mts`. Read current deployed identity from state and independently verify the artifact manifest; source changes require affected-boundary qualification before deployment.

## Qualification for a changed artifact or deployment

Local tests prove fixture relocation, manifest tamper rejection, secret/external-symlink exclusion and unit boundaries. Runtime CI additionally packages the actual portable worker and imports its real sharp/saxes decoder without a checkout; this is not a hostile-file sandbox or native deployment pass. Source head from CI can be its synthetic merge build; verify its tree/parents against normal integration before deployment.

After independent review and final artifact CI qualification under the recorded owner exception: privately verify CI tar/digests, extract as serveradmin with preserved modes/`--no-same-owner` into a new release path, verify all bytes, and compare the exact unit/config/socket/user/security delta before any service change. First qualify the existing synthetic no-network/secret-isolation/resource-limit probe using the new artifact; then one drained service handover, readiness, representative SVG/PNG/JPEG jobs, graceful stop/restart and cleanup. Preserve old artifact and uncertain effects; never restart/retry an unresolved storage operation. No install/deploy command, policy change or authority grant is included here.

Keep the active immutable release under `%h/insignia-artwork-releases/<reviewed source tree>/` and its private startup/storage files under `%h/.config/insignia/`. Resolve the actual current tree from [state](../../docs/delivery/state.md); do not substitute a historical release tree. Preserve active custody during temporary-copy cleanup. The current owner/operator checklist owns outstanding recovery, monitoring, rotation and collection/deletion obligations; this procedure does not extend any deadline or repeat a completed handover.
