# Independent release verifier image

This package replaces the verifier's mutable checkout/absolute SDK code paths with one digest-bound image. It preserves the existing independent receiver, four pinned management reads, selected Admin reads, append-only role, request fencing, durable journals and no-ambiguous-retry rules. Packaging alone does not qualify native deployment or make provider observations current. The [18 October native combined-runtime receipt](../../docs/delivery/evidence/lean-v1/native-combined-release-2026-10-18.json) separately qualifies the immutable image, exclusive old-receiver shutdown, existing official session, selected reads, append and actual web/worker agreement. It supersedes the old frozen186 transition instructions; old observations retain their actual expiry.

Runtime CI builds the existing portable worker dependencies, fetches the public Shopify CLI 4.8.2 archive by its exact SHA256, validates/extracts it without installing or running package scripts, and packages the unchanged pinned SDK client. A complete relative code manifest includes Node 24.21.0, SDK, source, profiles and production dependencies. Local relocation and a network-disabled image probe verify the actual packaged imports; no session or startup secrets enter the image. `client.mjs` is a byte-exact historical pinned code input; its SHA256 is checked during packaging rather than reformatted. CI records the source commit/tree, manifest digest, image ID, exported archive hash and exact workflow run/attempt through its artifact provenance. The artifact retention is three days; deployment custody must retain its approved immutable identity independently.

`compose.yaml` is a deployment template, not an apply command. Pin `INSIGNIA_VERIFIER_IMAGE` and `INSIGNIA_VERIFIER_MANIFEST_SHA256` from independently reviewed CI/deployment provenance. The bootstrap checks that digest before importing the receiver or reading credentials. The image's private identity file is checked against the independently supplied digest; it is not authority on its own. Consumer web/worker image and CI bindings remain separately verified provenance, never web-supplied environment assertions.

Provision these paths privately before any separately authorized handover, owned by UID1000 and without symlink parents:

- Startup file: mode0600; exactly `databaseUrl`, `clientSecret`, `appendPassword`. The database URL permits only `insignia_runtime` at the existing `insignia-rewrite-m5-019-database:5432/insignia_rewrite` on its private network. The independent append password remains separate from the ordinary role and is used only by the existing append mechanism.
- Journal directory: mode0700, exclusively the verifier's existing durable custody. Reconcile every reservation/settlement before migration; never discard an unresolved append or start a second receiver.
- SDK auth directory: mode0700, dedicated writable HOME for the official pinned SDK's existing no-prompt session/refresh behavior. Supply only the already-authorized session configuration through a private operator route. A missing/expired session stops collection; the image does not log in, copy browser data or obtain broader access.
- Metadata socket directory: mode0700, shared only with the intended consumers. It exposes the existing closed request protocol, not credentials or signing authority.

The container runs as UID1000, read-only with no capabilities, public ports, Docker socket, SSH key or host browser mount. Only journal, dedicated SDK auth and metadata socket mounts are writable; startup credentials are read-only. The canonical database network is external and the verifier has separate egress for its existing selected provider operations. No other application service is changed by this template.
