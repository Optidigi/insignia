# Independent release verifier image

This package provides one digest-bound independent verifier image. It preserves the receiver, pinned management/selected Admin reads, append-only role, request fencing, durable journals and no-ambiguous-retry rules. [Delivery state](../../docs/delivery/state.md) owns deployed identities, qualification limits and remaining operator actions. Packaging does not make provider observations current.

Runtime CI builds the existing portable worker dependencies, fetches the public Shopify CLI archive pinned by the packaging source and exact SHA256, validates/extracts it without installing or running package scripts, and generates the reviewed session adapter from strict typed source. A complete relative code manifest includes the pinned Node binary, SDK, source, profiles and production dependencies. Local relocation and a network-disabled image probe verify the actual packaged imports; no session or startup secrets enter the image. `client.mts` is maintained source; the pinned Node binary strips its types into the SDK-relative `client.mjs` runtime artifact. The reviewed generated-byte SHA256 is fixed in the release paths module and checked by both packaging and the runtime. Official SDK bytes/version remain unchanged. Offline qualification exercises the real SDK constructor with synthetic auth results and all network paths denied; it does not claim native authentication. CI records the source commit/tree, manifest digest, image ID, exported archive hash and exact workflow run/attempt through its artifact provenance. The artifact retention is three days; deployment custody must retain its approved immutable identity independently.

`compose.yaml` is a deployment template, not an apply command. Pin `INSIGNIA_VERIFIER_IMAGE` and `INSIGNIA_VERIFIER_MANIFEST_SHA256` from independently reviewed CI/deployment provenance. The bootstrap checks that digest before importing the receiver or reading credentials. The image's private identity file is checked against the independently supplied digest; it is not authority on its own. Consumer web/worker image and CI bindings remain separately verified provenance, never web-supplied environment assertions.

Provision these paths privately before any separately authorized handover, owned by UID1000 and without symlink parents:

- Startup file: mode0600; exactly `databaseUrl`, `clientSecret`, `appendPassword`. The database URL permits only `insignia_runtime` at the existing `insignia-rewrite-m5-019-database:5432/insignia_rewrite` on its private network. The independent append password remains separate from the ordinary role and is used only by the existing append mechanism.
- Journal directory: mode0700, exclusively the verifier's existing durable custody. Reconcile every reservation/settlement before migration; never discard an unresolved append or start a second receiver.
- SDK auth directory: mode0700, dedicated writable HOME for the official pinned SDK's existing no-prompt session/refresh behavior. Supply only the already-authorized session configuration through a private operator route. A missing/expired session stops collection; the image does not log in, copy browser data or obtain broader access.
- Metadata socket directory: mode0700, shared only with the intended consumers. It exposes the existing closed request protocol, not credentials or signing authority.

The container runs as UID1000, read-only with no capabilities, public ports, Docker socket, SSH key or host browser mount. Only journal, dedicated SDK auth and metadata socket mounts are writable; startup credentials are read-only. The canonical database network is external and the verifier has separate egress for its existing selected provider operations. No other application service is changed by this template.

For changed artifacts or deployment, requalify affected artifact import, exclusive receiver shutdown, private credential/session provisioning, role/auth/selected-read/append, consumer admission/expiry/restart and reconciliation before rollback. Never start a historical retired receiver or replay a settled operator. Preserve unresolved journals and verify exclusive ownership before replacement.

Permanent startup/auth/state and management Compose custody is under `%h/.local/share/insignia/runtime/`; resolve populated private paths from current custody, not a historical transition packet. Preserve operational state/auth, journals, image, independent credentials and the shared metadata socket directory without extending actual credential/data expiry. Code identity may remain stable while installation, permission, subscription and Function observations expire normally. Obtain fresh correlated collection/consumer agreement under current admission rules; never restamp old observations. The current checklist owns retention, restart/recovery qualification and other remaining work.
